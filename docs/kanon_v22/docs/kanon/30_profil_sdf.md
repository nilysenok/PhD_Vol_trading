## 30. Профиль SDF · правила С0–С12 и торговые добавки

Профиль накладывается на КАНОН v2.2 целиком: кластеры К1–К21 действуют как есть, здесь — только то, что зависит от стека (Rust-воркспейс, Python-скринер на сервере) и от предмета (ленты бирж, симулятор, деньги). Валидатор — `cargo xtask` (на языке проекта, К14 без отступлений).

**Зачем.** Этот проект ломается в своих местах: цифра из потолка выдаётся за деньги, параметры подбираются и считаются на одних часах, страница склеивается из двух окон данных, секрет попадает в чат, фоновый процесс на сервере теряется без pid, скрипт на 600 строк никто не читает, владельцу пишут в bps, когда он просил проценты. Каждое из этих мест закрыто правилом с проверкой или строкой ревью.

### Правила профиля

| № | Цвет | Правило | Почему |
|---|---|---|---|
| С0 | красное | в шапке `spec.md` есть `Каталог модулей:`, `Потолок:`, `Уровень доступа агента:`; есть секция «Порядок блоков» со стрелками | валидатор не знает, где искать блоки и кто от кого зависит |
| С1 | красное | файл `.rs` ≤ 200 строк; функция ≤ 40 строк, длиннее — строкой выше `// xtask: длинная — почему` | файл читается агентом целиком (К13) |
| С2 | красное | `scripts/*.py`, `scripts/*.sh`, `skriner/*.py` ≤ 200 строк; `python3 -m py_compile` и `bash -n` чистые; `.py` с самопроверкой в `__main__` без аргументов — запуск, ненулевой код — ошибка | скрипт на 600 строк никто не прочтёт и не проверит |
| С3 | красное | похоже на секрет в файле под git: токен Telegram `\d{8,10}:[A-Za-z0-9_-]{35}`, приватный ключ `0x[0-9a-f]{64}`, `cookie=`, `uc_token`; `.env` в индексе | засвеченный секрет перевыпускается, история git не чистится |
| С4 | красное | `*.parquet`, `data/` (кроме `data/.keep`), `target/`, `dashboard_*.html` в индексе git | данные не покидают сервер; мусор и конфликты у параллельных агентов |
| С5 | красное | `pkill`, `killall`, `rm -rf`, `nohup` вне `scripts/server.sh` и `scripts/_lib.sh` | процессы снимаются по pid из файла; удаление — с подтверждением владельца |
| С6 | красное | `http://`, `https://`, `api.hyperliquid.xyz`, `wss://` в `#[cfg(test)]`, `tests/`, `*_tests.rs` без пометки `// xtask: сеть — почему` | тест с сетью — медленный и мигающий; фикстуры ответов с датой (К13) |
| С7 | красное | крейт зависит (`[dependencies]` с `path`) от блока правее в «Порядке блоков»; `skriner` импортирует что-то кроме стандартной библиотеки и `requests` | порядок блоков — контракт; обратная зависимость ломает сборку по частям |
| С8 | жёлтое | нет `rust-toolchain.toml`; `Cargo.lock` не под git | сборки на Маке и сервере расходятся |
| С9 | красное | ключ в `profiles/*.toml` или в `profile/src/*.rs` (`#[serde(rename)]`, поле структуры профиля) отсутствует в `docs/sdf_parametry_edinyi_spisok.md` | дубли и самодельные имена ручек; владелец и симулятор говорят на разных языках |
| С10 | красное | страница `docs/otchety/*.html` или `*.md` с двумя окнами данных в шапке; сборщик страниц принял входы с разными `eval`/окном | одна страница — одно окно (урок 06.10: 24-часовые куски в странице 17 ч) |
| С11 | жёлтое | `❓` с датой ≥ 21.10 без `умолчание:` и `срок:`; файл `docs/zadaniya/*.md` без раздела «Выдача» | вопрос без умолчания блокирует; задание без выдачи не проверить |
| С12 | жёлтое | `bps` в `docs/otchety/*.md` с датой ≥ 21.10 и в строках сообщений `notify` / `skriner` | владелец читает проценты (печать 08.10) |

Новое правило вводится жёлтым на неделю, потом красным (К14). Правило без теста в `cargo xtask self-test` не считается введённым. С1 и часть С3–С4 уже есть в `xtask` v2.1 — переносятся под новыми номерами, тесты остаются.

**Пометки в коде** — единственный способ отступить от С1, С6: строка `// xtask: <правило> — <почему>` выше или на той же строке. Пометка без «почему» — ревью «НЕ СЛИВАТЬ».

### Правила, которые проверяет человек (ревью)

- **Первая цифра — потолок.** Оценка по серединам стакана, «исполняют всегда», задержка 0 — не деньги. В отчёте слово «потолок» стоит рядом с такой цифрой, честная цифра — отдельной строкой.
- **Честная половина.** Параметры выбраны на одной половине данных, счёт — на другой; выбор и счёт на одних часах — подгонка, вердикт «НЕ СЛИВАТЬ» для кода критерия.
- **Одна пара — не статистика.** Цифра на ≤ 20 сделках или ≤ 10 событиях называется «мало событий» и не идёт в ворота.
- **Задержка — замеренная.** Из Амстердама до Токио 215–240 мс в одну сторону; всё, что живёт только при 0 мс, помечается «нужен Токио» и в ворота не идёт.
- **Деньги считает код с тестом «попробуй сломать».** Проверяющий для кода денег и критерия обязателен; тест падает до правки и зелёный после; вредные входы (пустая лента, дыра в данных, нулевой объём) — в тесте.
- **Событийная схема мерится не часами.** $/нед, доля событий в плюсе, худшее событие, число событий в неделю; «70 % часов в плюсе» к ней не применяется.
- **Данные не покидают сервер.** Отчёт тянет на Мак только агрегаты (CSV на тысячи строк, не Parquet на гигабайты); `scp` сырых данных — «НЕ СЛИВАТЬ».
- **Заявок нет до GO.** Любой код, который ставит заявку (`order`, `place`, `cancel` в клиенте биржи), живёт только в `trader` и только после ворот 4 направления; ключ — API-кошелёк без права вывода, в `.env` сервера, руками владельца.
- **Выход до открытия США** — у любой стоящей заявки по акциям-перпам обязателен; проверяющий ищет ветку снятия заявок перед 13:30 UTC (с 01.11 — 14:30).

### Торговые добавки к К9 и К10

- **Направление — гипотеза с порогом до первой строки кода.** Порог — в единицах, которыми меряется схема: $/ч или % капитала в неделю, событий в неделю, доля продолжений. Срок — дата. «Ещё недельку» без новой гипотезы — закон 14.
- **Ворота направления** — этапы 2–5 шаблона: скринер в бумаге → вердикт на честной половине → робот в бумаге → микроразмер. «Сервис запущен» — не ворота.
- **Разведка на существующих данных — бесплатна, запись — по «да» владельца.** Новая запись, новый радар, новая служба на сервере — только после печати `Ъ` в `_dir.md`.
- **Закрытое направление — строкой в `arhiv.md` с причиной и отчётом**, модули переходят в статус «заморожен»; код не удаляется.
- **Часы владельца — ограничение.** Задание агенту — по шаблону `docs/zadaniya/_shablon.md` с бюджетом; отчёт расхода — шестой строкой итога.

### Формат

- Блоки: латиница, строчные, дефис: `sdf-core`, `recorder-hyperliquid`, `skriner`.
- Идентификаторы Rust и Python — английские; комментарии, канон, сообщения владельцу — русские; имена тестов — транслит инварианта (`ochered_pessimistichnaya_ne_ispolnyaet_ranshe`).
- Отчёты: `docs/otchety/ГГГГ-ММ-ДД_тема.md` или `.html` по шаблону `docs/sdf_shablon_otveta.md`; в шапке — окно данных (UTC) и коммит.
- Задания: `docs/zadaniya/ГГГГ-ММ-ДД_тема.md` по `docs/zadaniya/_shablon.md`; раздел «Выдача» обязателен.
- Форматы `data/`: `data/<служба>/<файл>.{json,csv,parquet}` с полем `"v"`; pid — `data/<имя>.pid`, журнал — `data/<имя>.log`.

**Валидатор.** Таблица С0–С12 выше; остальное — К1–К21 в `cargo xtask`.

**Ошибки.** Потолок 131 $/ч по серединам принят за цель, две недели ушли на догонялку. Перебор 16 200 наборов на тех же 17 часах, на которых и считали, — плюс исчез на честной половине. Страница 17 ч собрана с кусками 24-часового окна. Скрипт на 600 строк с `pkill -f` снял чужой процесс. Пароль root в чате — дважды. Владельцу написали «+123 bps» вместо «+1,2 %».
