# Дирижёр — как продолжить работу (SDF)

Записка для новой сессии дирижёра. Правила — в `CLAUDE.md`, роли — в `.claude/agents/*.md`, состояние — в `handoff.md` (собирается сам). Здесь — порядок работы, уроки проекта, перенесённые как правила, и то, что зависит от сервера и денег.

## 1. Начало
1. Проект — `~/Developer/arbitrazh` (ветка `main`); сервер — `sdf` (`/opt/arbitrazh`), все действия там — `scripts/server.sh`. Если сессия открыта из другой папки, роли недоступны: запускай обычного агента и первой строкой вели прочитать `.claude/agents/<роль>.md` и `CLAUDE.md`.
2. Прочитай `handoff.md`, `OTKRYTO.md`, этот файл. Живое состояние: `gh pr list --state open`, `scripts/kopii.sh spisok`, `scripts/server.sh bg-status`, `uptime` и `df -h` на Маке и сервере.
3. Очереди задач — секции ЗАДАЧИ в `_ctx.md` блоков; первые — из СЕЙЧАС в `_dir.md`. Выжимка блока — `cargo xtask brief <блок>`.
4. Перед первым запуском агентов в день: `cargo xtask self-test` (секунды).

## 2. Цикл работы
- Задача → `kodir` в постоянной копии `~/Developer/.sdf-kopii/kod-N` (в задании — имя копии; кодер делает `git fetch origin && git checkout -B <ветка> origin/main`), финиш через `scripts/finish.sh`.
- PR → `proveryayushchiy` в `prov-1`: вердикт комментарием в PR. В задании — что сделано по словам кодера, что проверить особо (какой тест обязан упасть при временной поломке), считает ли код деньги или критерий (тогда «попробуй сломать»).
- Вердикт «СЛИВАТЬ» → в группу слияний. «НЕ СЛИВАТЬ» → `SendMessage` тому же кодеру с пунктами вердикта, если его контекст меньше 200 тыс. токенов; иначе — свежему кодеру с вердиктом и именами файлов.
- Группа слияний по непересекающимся блокам → `scripts/sliyanie.sh N1 N2 …` в копии `check`: одна `check.sh --konets` на группу, производные, push.
- Раздел «## Канон» слитых PR → `pisar` одним PR на группу.
- Параллельно — не больше строки «Потолок» в `spec.md` (2 кодера + 1 проверяющий). Исследователь, писарь, архитектор не считаются. На сервере — одна сборка за раз под `nice -n 19 -j 2`.

## 3. Слияние — только так
```
scripts/sliyanie.sh N1 N2 …          # в ~/Developer/.sdf-kopii/check на main
# внутри: baseRefName == main · последний вердикт «СЛИВАТЬ» · git merge-tree чистый · gh pr merge ·
#         ff-only main · check.sh --konets (пересобирает ROOT.md, handoff.md, dashboard.*) · коммит производных · push
```
- Руками (GitHub лежит): `git merge --no-ff -m "Merge pull request #N from <владелец>/<ветка>"` в копии `check`, затем `scripts/check.sh --konets && git push origin main` — одной цепочкой через `&&`.
- Два `check.sh` одновременно в разных копиях — нельзя: `cargo` делит замок `target/` и память; второй ждёт.
- Перед `gh pr merge` у стопки веток — база следующего PR на `main` до слияния предыдущего.

## 4. Уроки проекта, перенесённые как правила
- **Потолок принят за деньги.** Оценки A/B/C скана (131 $/ч по серединам) две недели считались целью. Здесь: любая цифра без очереди, комиссий и замеренной задержки помечается «потолок»; в ворота идёт только честная половина.
- **Подгонка.** Перебор 16 200 наборов на 17 часах, на которых и считали. Здесь: выбор на одной половине, счёт на другой — в задании обязательно, проверяющий кода критерия ищет это первым.
- **Склейка окон.** Страница 17 ч с кусками 24-часового окна (06.10). Здесь: одно окно на страницу — правило С10, сборщик отказывается.
- **Regex-замены.** 29.09 испорчены 17 строк `_ctx.md` и скрипт. Здесь: `sed -i`, `perl -i`, `cat >`, heredoc, `python3 -c` закрыты запретом в `.claude/settings.json`.
- **`pkill -f` и потерянные процессы.** Здесь: фон на сервере только `scripts/server.sh bg <имя>`, pid в файле, снятие `bg-stop <имя>`; `pkill`, `killall` — запрет (С5).
- **Пароль root в чате — дважды.** Здесь: вход только по ключу; секреты в `.env` на сервере руками владельца; `.env` агенту не читается (запрет в `settings.json`).
- **Два подвисших ssh и 600-строчный вывод в чат.** Здесь: ssh только через `scripts/server.sh` с тайм-аутом; вывод — в файл на сервере, в чат `grep`-куски.
- **Пять проверяющих на один шаг, 30 коммитов.** Здесь: проверяющий — один проход на PR; обязателен только для денег и критерия; PR без кода (`.md`, `.toml`, `.csv`) — уровень «канон», haiku.
- **Контекст 600–800 тыс. токенов у агента.** Здесь: бюджет в строке задачи, два бюджета — не возобновлять; `/clear` после закрытого шага.
- **Канон — пачкой.** Кодер `_ctx.md` не правит, строки — в «## Канон» описания PR; писарь вносит после группы. Конфликт в каноне — версия `main` целиком плюс свои строки.
- **Общий файл у предела.** `sdf-core/src/files.rs`, `outputs.rs`, `analyzer/_ctx.md` держать с запасом ≥ 30 строк; дошёл до 170 — разгрузка отдельным PR первым.
- **Жалоба «не работает»** — сначала условия: сервер или Мак, ветка, окно данных, что запускали; потом задача.
- **Описание PR и вердикт — в свой файл** в папке сессии, не в общий.
- **Локальное слияние — одной цепочкой до push.**

## 5. Что зависит от сервера и денег
- **Тяжёлое — только на сервере.** Перебор, свечи за недели, симулятор на длинной ленте — `scripts/server.sh bg` под `nice`; на Маке — `cargo check`, тесты, короткие прогоны на фикстурах. Данные на Мак не тянутся.
- **Скринер — служба `systemd`** (`scripts/systemd/`): перезапуск — `scripts/server.sh restart sdf-xyz-premarket`, стоп — файл `data/xyz_premarket/STOP`; второй слушатель Telegram на тот же токен не поднимать (409).
- **Заявок нет до GO.** Код заявок — только в `trader`, только после ворот 4 `_dir.md`; ключ — API-кошелёк без вывода, кладёт владелец. Агент этот код не запускает (запрет `cargo run -p trader` в `settings.json`).
- **Выгрузки каналов** (Hyperdash) — владелец кладёт в `data/hyperdash/` на сервере через `scp`; в git — только разобранные агрегаты CSV до 1 МБ.
- **Часы США** — `America/New_York` в коде, не константа UTC; переход 01.11 ломает все «13:30 UTC».

## 7. Правила координации и эффективности
- **Группы слияний** по непересекающимся блокам — одним шагом, одна проверка на группу.
- **Кодер без простоя.** После PR берёт следующий номер очереди поверх своей ветки. Таймбокс 50 тыс. токенов или 40 минут.
- **Серия** до 3 номеров одной темы в одних файлах — один PR до 40 минут.
- **PR без кода** проверяется только валидатором и писарем, модель haiku.
- **Модель по задаче:** простая → haiku, обычная → sonnet, трудная (план, логика симулятора) → основная; подъём после одной неудачной попытки младшей.
- **Отчёт расхода дня** `docs/otchety/ГГГГ-ММ-ДД_rashod.md`: строка на запуск агента — роль, модель, бюджет, токены, минуты, исход.
- **Бюджет в строке задачи** `~20м · ≤ 50т`: один бюджет — остановка и «как разрезать»; два — не возобновлять.
- **Закрытое направление не блокирует живое.** Правка замороженного модуля — только печатью; вопросы к нему — в `arhiv.md`.
