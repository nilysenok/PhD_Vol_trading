# spec.md — законы пространства SDF
Профили: код + эксплуатация
Уровень доступа агента: 3 (локальные команды и тесты; сервер `sdf` по ключу; Telegram-бот; API бирж только на чтение. Ключи, заявки и деньги бирж — уровень 4, только владелец)
Роли: владелец Никита · партнёр Антон · агент · советник · проверяющий · источник Иван
Потолок: 3 сборочных агента (2 кодера + 1 проверяющий); Мак 12 ядер, 32 ГБ; сервер `sdf` 4 ядра, 7 ГБ — там одна сборка за раз, `nice -n 19 -j 2`
Каталог модулей: . skriner

## Что это
Анализатор и скринер неэффективностей Hyperliquid. Записываем ленты и стаканы, считаем в симуляторе худший сценарий исполнения, ищем параметры и события, которые дают деньги; владелец утверждает профиль. Робот (`trader`) — только после ворот направления. Направление сейчас одно — акции-перпы HIP-3 (`xyz:`): движуха вне сессии США и ликвидации крупных позиций (`_dir.md`). MEXC ← Binance и догонялка Hyperliquid ← Binance закрыты печатями (`arhiv.md`, 02.10 и 06.10).

## Словарь домена
- **ведущая / ведомая** — Binance USDⓈ-M ведёт, ведомая биржа отстаёт; **d** — расхождение в %, + означает ведущая выше
- **оракул** — внешняя цена актива у Hyperliquid (для `xyz:` — премаркет, основная и постмаркет сессии США, ночью Blue Ocean; в выходные внутренняя EMA 30 мин); **mark** — цена ликвидации, медиана трёх цен, одна — из стакана
- **уровень** — цена ликвидации позиции; **выброс** — ход цены за уровень при ликвидации, в %; **возврат** — доля выброса, отыгранная за 5 / 15 / 30 мин
- **сессия США** — 13:30–20:00 UTC в летнее время, с 01.11 на час позже; **ночь** и **выходные** — всё остальное
- **событие** — одна ликвидация или одна сработка сигнала; **исполненное событие** — наша лимитка исполнилась бы по свечам или ленте
- **честная половина** — параметры подобраны на одной половине данных, счёт — на другой; цифра без неё — потолок, не деньги
- **ворота** — факт, по которому направление идёт дальше; «сборка зелёная» — не ворота
- **скринер** — служба на сервере: сигналы в Telegram, журнал `signals.csv`, дашборд; заявок не ставит

## Правила домена
1. Процессы общаются только через Parquet, JSON и CSV в `data/`; сокетов между ними нет. Данные `data/` не покидают сервер; счёт — там под `nice`; Мак — только код.
2. Секреты — только в `.env` (`chmod 600`, не в git даже в закрытом репозитории). Засвеченный в чат секрет — перевыпустить.
3. Ключи, заявки и деньги бирж — вне агентной системы. Робот запускает владелец; ключ робота — API-кошелёк без права вывода.
4. В белую: смотреть публичные кошельки и стоять лимиткой — да; двигать цену ради чужой ликвидации, KYC MEXC, «пробив», серые сервисы — нет.
5. Деньги считаем в $/ч и в % капитала в неделю при заявке под капитал; событийная схема — ещё $/нед, доля событий в плюсе, худшее событие. Владельцу — проценты, не bps; «в сутки» не показываем.
6. Первая цифра — потолок: оценки по серединам стакана, без очереди и комиссий, — не деньги. Симулятор считает худший сценарий: очередь пессимистичная, задержка +100 мс к замеренной.
7. Критерий остановки — до эксперимента, в `_dir.md` направления (гипотеза с порогом и сроком). «Почти прошли» — NO-GO.
8. Имена торговых ручек — только из `docs/sdf_torgovaya_mehanika.md`; остальные секции профиля — `docs/sdf_profil_robota.md`; единый список ключей — `docs/sdf_parametry_edinyi_spisok.md`. Дубли имён запрещены.
9. Никогда не тейкер на входе: цена, пересекающая стакан, сдвигается на шаг от лучшей.
10. Фон на сервере — только `scripts/server.sh bg <имя> …`, pid в `data/<имя>.pid`; снимать — только по pid из файла. Массовое удаление — только с подтверждением владельца в Telegram.
11. Одна страница отчёта — одно окно данных: шапка несёт окно и коммит, сборщик страниц отказывается смешивать окна.
12. `docs/*.md` — справка без статуса; задачи, вопросы, печати, ждуны — только в `_ctx.md` блоков и `_dir.md`.

## ПЕЧАТИ
Ъ — секреты (токен бота, cookie, пароли) — только в `.env`, никогда в чат, документы и git; пароль root засвечен дважды — вход на сервер только по ключу (владелец 29.09)
Ъ — данные скана и сессий не покидают сервер; счёт — на сервере под nice; Мак — только код (владелец 05.10)
Ъ — ключи и заявки бирж — вне агентной системы; робота запускает владелец (владелец 29.09)
Ъ — файлы правим только инструментами правки, не regex-заменами: 29.09 так испорчены 17 строк `_ctx.md`; процессы снимаем по pid из файла (владелец 29.09)
Ъ — граница «в белую»: смотреть кошельки и стоять лимиткой — да; двигать цену ради чужой ликвидации — нет; MEXC KYC, «пробив», серые сервисы — нет (владелец 06.10)
Ъ — результат по парам — только по шаблону `docs/sdf_shablon_otveta.md` (владелец 05.10)
Ъ — опорная цена премаркета для `xyz:` — оракул Hyperliquid, внешние ленты только для сверки (оракул и есть внешняя цена 24/5; владелец 20.10)
Ъ — владельцу все величины в процентах, не в bps (владелец 08.10)

## Типовые оптимистичные допущения (К9)
исполнение «всегда», когда цена коснулась уровня; задержка 0 вместо замеренной 215–240 мс до Токио (540 мс круг); комиссия забыта; выброс считается по одному событию; подбор и счёт на одних часах; потолок A/B/C по серединам принят за деньги; одна пара как статистика

## Порядок блоков (К2, К21)
`sdf-core` → `profile` → `recorder-binance` → `recorder-mexc` → `recorder-hyperliquid` → `record` → `analyzer` → `universe` → `notify` → `web` → `skriner` → `trader`
Блок зависит только от блоков левее. `skriner` (Python, сервер) читает только `data/` и `.env`; Rust-крейты от него не зависят. `recorder-mexc` и `trader` заморожены: задач нет, менять только печатью.

## Горячий путь (К21)
`analyzer` — симулятор и перебор: один набор параметров на 17 ч ленты ≈ 2 с; большие сетки — за один проход или в очередь на сервере. Турниров библиотек нет.

## Форматы данных (К12)
папка данных: `data/` (не в git) · расширения: `.parquet`, `.json`, `.jsonl`, `.csv` · блок-владелец форматов: `sdf-core` (`sdf_core::files`, `outputs`, `meta`, `pairs`); `skriner` владеет `data/xyz_premarket/{closes.json,signals.csv,state.json,settings.json,stats.json}` с полем версии `"v"`. Таймстемп — время биржи, время приёма — отдельной колонкой. Выгрузки каналов (Hyperdash) — `data/hyperdash/`, не в git.

## Внешние системы (К21)
- `[hl]` Hyperliquid Info API и WS: 1200 веса/мин на IP, ≤ 10 соединений, 1000 подписок; `candleSnapshot`, `metaAndAssetCtxs(dex)`, `clearinghouseState`, `l2Book`; рвёт соединение раз в ≈ 3 ч — фикстуры ответов в тестах, факты с датой в `docs/`
- `[xyz]` trade.xyz: часы сессий акций США, оракул, ограничение ±0,5 % за шаг — `docs/zadaniya/2026-10-20_xyz_premarket.md`, сверено 20.10
- `[binance]` USDⓈ-M WS: только сигнал, не торгуем
- `[tg]` Telegram-бот: один слушатель на токен; команды только от владельца; торговых команд нет
- `[nasdaq]` api.nasdaq.com последняя сделка — только сверка оракула
- `[sdf]` сервер Timeweb Амстердам: `docs/sdf_server.md`; до Токио 215–240 мс кругового

## Библиотеки (К13)
Rust: одна на задачу, без OpenSSL и системных зависимостей — `Cargo.toml` воркспейса; новая — печатью в `sdf-core/_ctx.md`. Python (`skriner`): только стандартная библиотека и `requests`; новая — печатью в `skriner/_ctx.md`.

## Сборка и проверка (К14)
`cargo fmt --all --check` → `cargo check --workspace --all-targets` → `cargo clippy --workspace --all-targets -- -D warnings` → `cargo test --workspace` → проверка скриптов (`py_compile`, `bash -n`, ≤ 200 строк) → `cargo xtask check`; `--konets` ещё: `cargo xtask self-test`, на `main` — сборка производных и их свежесть (`--main`)

## Окружение (К19)
Мак владельца (12 ядер, 32 ГБ) — код, узкая проверка; сервер `sdf` (Ubuntu, 4 ядра, 7 ГБ, `/opt/arbitrazh`) — данные, скринер (`systemd`), длинный счёт под `nice`; рабочие копии — `~/Developer/.sdf-kopii/` (`kod-1`, `kod-2`, `prov-1`, `pisar`, `check`); часовой пояс канона — UTC, в скобках МСК; `rust-toolchain.toml` закрепляет стабильный Rust, `Cargo.lock` в git
