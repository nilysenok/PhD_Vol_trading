# Контракт `evaluate` движка перебора (Ж-034 к Ж-031#Э1-а), формат строки v1.1

Источник: WIP кодера `fastbt/sweep.py`, `sweep_sk.py`, `sweep_stat.py`, `sweep_modes.py`, `sweep_synth.py` (ветка `sweep-engine`, 27.10 19:00). Если код расходится с контрактом, прав контракт; правки кода делает кодер.

## 1. Сигнатура
```python
evaluate(obj: Obj, params: Params, period: PeriodName, commission: float) -> Row
Obj        = dict  # §2
Params     = dict[str, int | float | str | bool | None]   # §3, полная точка: база ⊕ отклонения
PeriodName = Literal["tune2018", "ctrl2019", "train", "validation"]   # §4
commission = float  # % на сторону: 0.035 | 0.04 (§5)
Row        = dict[str, float | int | str]   # §6, ключи и единицы фиксированы
```
В коде `Sweep.evaluate(params, comm_pct)` — та же функция с obj и period из `Spec`; допустимо, если строка совпадает с §6.

## 2. obj — объект оценки
| kind | поля | статус |
|---|---|---|
| `Sk` | `sid ∈ {S1…S6}`, `tickers` (по умолчанию 17 из `data.TICKERS`) | `SkEvaluator` |
| `A_sborka` | `sostav`: {sid → точка Params}, параметры сборки (веса, лимиты; сетка Э1-г) | адаптер Э1-г |
| `C`, `E`, `B`, `D` | `semya`, `sigma` (ряд σ̂: const/naive/harj/hyb × h), основа A или A′ | адаптеры Э2–Э3 |

Адаптер — объект с полями `sig_names`, `series_digest()`, `code_id()`, `signals(sig_params)`, `pnl(sigs, params, comm, end) -> DataFrame[excess, exposure, turnover, sides]`. Других путей к данным у evaluate нет.

## 3. params — три класса
1. **Сигнал** (`sig`) — ключи сетки семьи `sigprov.SIG_GRIDS[sid]` (ma_window, z_entry, …). Входят в ключ кэша (§7) и вызывают `signals`.
2. **Пост-сигнал** (`post`) — маски поверх кэшированных сигналов: зашитые фильтры (ужесточение), `q_sily`, `vyhod_dev`. В ключ кэша не входят и применяются после кэша.
3. **PnL** (`pnl`) — RM (стоп, тейк, трейл, безубыток, время, `rm_tip`/`rm_edinitsa`, √RV-выходы), слой исполнения, фильтр оборота, параметры сборки.

Класс параметра задаёт yaml сетки (`bloki.*`, Э1-б). Любое значение из закоммиченной сетки должно приниматься. Сейчас `SkEvaluator._rm_index` пускает только узлы `grids.rm_grid(sid)` — это нарушение контракта, его нужно снять. Неизвестный ключ — `KeyError`; молча его не игнорировать.

## 4. period
| имя | годы | роль | в цели (`objective`) | честная половина |
|---|---|---|---|---|
| `tune2018` | 2018 | настройка | да | нет |
| `ctrl2019` | 2019 | контроль внутри train | нет | нет (контроль) |
| `train` | 2018–2019 | отчёт | нет | нет |
| `validation` | 2020–2021 | один взгляд на этап | **никогда** | да |

- В коде имена `setup`/`control` — псевдонимы `tune2018`/`ctrl2019`.
- Границы — календарные годы по дате бара; прогрев читает историю до периода, PnL — только дни периода; даты ≥ 2022 — `PermissionError`. Ряд дневной до 18:50 (Н6); сигнал по close t, доход t → t+1 (задержка 0 баров).
- `validation` доступна только в режиме `validation`, с флагом открытия на диске. Повторный взгляд — только с `reopen_note`; при нём `n_mult = 2` и N удваивается.
- Цель: среднее годовых Шарпов периода − 0,5·σ(ddof=1). На `tune2018` это Шарп 2018 (σ = 0 при одном годе).

## 5. commission
В процентах на сторону. Значения: 0,04 (отбор, ledger) и 0,035 (пересчёт). Комиссия списывается при входе и при выходе. Позиция, открытая на последнем баре периода, платит выход. Строка несёт `comm_pct`. Пересчёт при 0,035 в N не входит.

## 6. Row — колонки (формат v1.1)
| колонка | единица / определение |
|---|---|
| `v` | `"1.1"` |
| `obj`, параметры точки | как во входе, по одной колонке на параметр |
| `period`, `okno_s`, `okno_po` | имя периода; первая и последняя дата PnL (ISO) |
| `zaderzhka` | `"close_t→close_t+1, 0 бар"` |
| `chestnaya` | `net` / `kontrol` / `validation` |
| `comm_pct` | % на сторону |
| `sharpe` | годовой, избыточной над ключевой ставкой ЦБ, mean/sd(ddof=1)·√252 |
| `msr` | mSR Фавра–Галеано (`metriki_e.msr`), годовой; nan при mVaR ≤ 0 |
| `sortino` | mean·252 / (sd отрицательных, ddof=1·√252) |
| `mdd` | доля капитала от пика, ≥ 0 |
| `oborot_y` | Σ\|Δ позиции портфеля\| за год, в долях капитала |
| `dni_v_rynke` | доля дней с экспозицией > 0, 0…1 |
| `sdelok_y` | сторон в год на пару (тикер, семья); круговая сделка — 2 стороны |
| `sharpe_<год>` | Шарп по каждому году периода |
| `objective` | цель §4 |
| `plateau`, `n_sosedey` | средний Шарп соседей ±1 шаг сетки по каждому параметру; число соседей |
| `N`, `n_mult` | накопленные пробы ledger × n_mult |
| `dsr` | DSR(N): SR* по N и V = var(дневных SR проб, ddof=1); при N = 1 DSR = PSR |
| `pbo` | PBO по CSCV, 8 блоков, по набору точек режима. В строке одиночного evaluate — nan, заполняет драйвер |
| `series_digest`, `code_id` | как в ключе кэша §7 |

## 7. Ключ кэша (Д5)
`sha1(json([obj, sorted(sig_params), series_digest, code_id]))`; `series_digest` — sha1 склейки дайджестов рядов тикеров, `code_id` — `cache.code_hash()`. Ключ меняется при смене ряда (например, вечерней сессии на 18:50) и при смене кода сигналов. Кэшируются только сигналы. PnL на диск не кэшируется: его мемо живёт на один прогон, ключ мемо — `(params, comm, годы)`.

## 8. Драйвер
`driver(evaluate, setka: yaml sweep-setka v1, mode) -> list[Row]`, где mode ∈ {oat, factorial, morris, optuna, validation}.
- Драйвер строит точки из `bloki` и `uslovie` сетки, вызывает evaluate и ведёт ledger N. Каждый вызов вне validation, включая соседей плато и обрезанные (pruned) пробы Optuna, — это +1 к N.
- В конце драйвер заполняет `pbo` и пишет `tablica.csv`, `ledger.json` (с `"v"`) и `dop.json`.
- Optuna: TPE, `n_jobs ≤ 8`, seed из сетки.
