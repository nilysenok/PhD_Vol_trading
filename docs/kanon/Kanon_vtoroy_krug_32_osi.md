## Часть 3. Слабые места конкретно в агентах, командах и скиллах — сводка

1. **Агенты без определений** → нет исполняемых ограничений, нет памяти, нет лимитов ходов. Решение: пять файлов ролей (ось 22).
2. **Проверка той же моделью и той же сессией** → артефакты обвязки не ловятся. Решение: проверяющий на другой модели, финальный аудит в чистой сессии (ось 13, 22).
3. **Кэш субагентов 5 минут** → переплата. Решение: `subagentPromptCacheTtl: 1h` (ось 24).
4. **Лид делает сам** → контекст, единая точка отказа, самооценка. Решение: хук на пути записи лида, правило ожидания (ось 32).
5. **Команды агентов** — сейчас не нужны: задачи последовательны и зависимы, токены ×N. Единственное место, где они окупятся: панель ревью из трёх линз перед открытием теста (данные / статистика / код) и поиск причины «числа не те» конкурирующими гипотезами, если это повторится. Включать точечно, с `TaskCompleted`-хуком, который не даёт закрыть задачу без EVIDENCE.
6. **Скиллов нет** → процедуры переписываются, побочные эффекты доступны модели. Решение: шесть скиллов (ось 23), `/otkrytie` только вручную.
7. **Память не используется** → повторные поправки, обучение агентов с нуля. Решение: auto memory + agent memory + постмортем-шаблон (ось 25).
8. **Нет эвалов** → канон проверяется только следующим инцидентом. Решение: регресс-набор из инцидентов + эвалы скиллов (ось 31).
9. **Восстановление после сбоя ручное** → 40 минут и риск потерь. Решение: коммиты каждые 20 минут, `/vosstanovlenie` (ось 26).
10. **Числа в текст попадают руками** → главный риск несовпадений на защите. Решение: единый JSON чисел и сборка документов из него (ось 28).
