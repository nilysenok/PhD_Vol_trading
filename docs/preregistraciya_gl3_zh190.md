- О1. dev 2017–2021; годовое переобучение 1 января 2016…2021 по строкам с концом цели h < cut, окно расширяется от самой ранней доступной строки. 2016 считается только как история для слоёв, которые смотрят в прошлые прогнозы; в метрики не входит.

- О3. Метрики — как в 6б (`scripts/analysis/gl3_r6b_common.py`): QLIKE = r − ln r − 1; среднее пяти годовых средних по пулу 17 тикеров; годы; стресс март–июнь 2020 и верхний терциль RVI (как `_stress` раунда 6); RV/σ̂² в обеих стресс-строках; число тикеров (из 17) строго лучше эталона (QLIKE тикера — среднее пяти годовых) и одностороннее биномиальное p. Число тикеров — против каждого из трёх эталонов.
- О4. Эталоны: (1) честно переобученный финал FIN_PIT (`data/regen/gl3_r6b_h5/pit/experts/FIN_PIT.parquet`, из п. 2б Ж-188: замороженные параметры warmup 2016, ES по О2, годовой refit); (2) HAR-J(б) — сохранённый эталон (`har_corr`, PIT-чист по аудиту 2а); (3) HAR-J(б) потикерный HAR_i — строится в итерации 1 (Э3 ниже). Сохранённый финал D12_h5 показывается справочно.
- О5. LOYO: если у строки есть сетка, прогноз года Y — точка с наименьшим средним QLIKE по остальным четырём dev-годам; точки сетки показываются строками с eligible = False.
- О6. «Лучшая схема» итерации, которая идёт дальше, — строка с наименьшим средним QLIKE LOYO.
- О7. Обратное преобразование лог-прогноза бустинга: exp(s²/2), s² — дисперсия лог-ошибки (ddof 0) на внутренней валидации текущего обучения, один скаляр на панель (по тикеру — только там, где это задано схемой).
- О8. Признаки v3 — список признаков финала h=5 (`docs/tables/gl3_r5_r6/frozen_warmup_configuration.json`, `feature_names["5"]`, построен на `features_pit_v3`), без выходов моделей (`har_feature`), как в Г8.
- О9. В этапе 1 — только LightGBM (категории и `init_model` — его средства). Отступление от «как сейчас»: финал — среднее уровней XGB и LGB; здесь только LGB.
- О10. Каждый fit — в ledger (h, cutoff, max_target_end < cutoff < 2022-01-01); на каждый новый модуль — тест на синтетике и мутация, которую тест ловит. Модели не сохраняются, прогнозы — float32.

## Итерация 1 (h=5) — что меняем: схема обучения бустинга; эталон HAR_i

Записано 05.11.2026 до счёта.

- Б-а — панель 17 тикеров, параметры LGB финала (`fin5params.lgbm`, функция потерь финала — Хьюбер, текущий порог), цель ln RV(t+5), ES по О2.
- Б-б — отдельная модель на тикер: max_depth 4, num_leaves 15, min_data_in_leaf 50, lambda_l2 5, learning_rate 0,03, feature_fraction 0,8, bagging_fraction 0,8, до 1000 деревьев, остановка через 50; признаки — 40 лучших по gain панельной модели Б-а той же отсечки (прошлое окно); s² по тикеру.
- Б-в — Б-а + тикер и сектор категориальными признаками LightGBM (`categorical_feature`); сектор — статический ключ из данных проекта.
- Б-г — модель Б-а той же отсечки → продолжение по тикеру (`init_model`), learning_rate 0,01, до 200 деревьев, остановка через 20 по внутренней валидации тикера, не меньше 50 деревьев; s² по тикеру.
- Э3 (HAR_i) — потикерный OLS HAR-J(б) в логах на регрессорах эталона, с той же схемой эмбарго; β*_i = λ·β_i + (1−λ)·β_pool, s²*_i = λ·s²_i + (1−λ)·s²_pool, λ ∈ {0; 0,25; 0,5; 0,75; 1}, выбор λ — LOYO (О5). λ = 0 обязан совпасть с HAR-J(б) эталона (≤ 1e−8 отн.).
- Итог итерации — таблица: эталоны (FIN_PIT, HAR-J(б), HAR_i по λ и LOYO, справочно сохранённый финал), Б-а…Б-г; лучшая схема по О6.

## Этап 1 одним пакетом (Ж-191) — что меняем: схема × нормировка × функция потерь, затем гиперпараметры по группам и бэггинг

Записано 05.11.2026 до счёта; заменяет порядок «итерация в день». Схемы Б-а…Б-г и Э3 — как выше.

- П1. Итерации 1–2 — одна сетка 4 × 2 × 5 = **40 конфигураций**: схема {Б-а, Б-б, Б-в, Б-г} × нормировка {нет; доли RV_252} × потеря {MSE в логах; Хьюбер с порогом финала ×1, ×2, ×4; QLIKE в логах}. Один модуль обучения, конфигурация — словарь `{scheme, norm, loss}`.
- П2. Нормировка «доли RV_252»: цель ln(RV(t+5) / RV_252), RV_252 — среднее RV тикера за 252 даты до d включительно (≥ 252 наблюдений, иначе строка не входит в обучение и прогнозируется без нормировки); признаки дисперсионного уровня делятся на RV_252, признаки в единицах корня — на √RV_252, прочие (внешние уровни, календарь, доли) не меняются. Классификация признаков — как нормировка Г4 раунда 6 (`gl3_r6h5_data.py`, `harx(..., normalized=True)` и `static_x(..., normalize)`), список записывается до счёта. Прогноз переводится обратно умножением на RV_252 дня d.
- П3. QLIKE в логах — своя целевая функция LightGBM: f = ln σ̂², y = ln RV, grad = 1 − e^(y−f), hess = e^(y−f); без поправки exp(s²/2). Для MSE и Хьюбера поправка по О7 (по тикеру у Б-б и Б-г).
- П4. Порог Хьюбера финала берётся из `fin5params.lgbm` (параметр `alpha` у LightGBM `huber`); если там нет явного значения — значение LightGBM по умолчанию, записывается в таблицу.
- П5. Итерация 3 — для двух лучших конфигураций П1 (О6): кластеры тикеров по уровню RV и ликвидности (медиана ln RV и медиана ln оборота за 252 даты до отсечки, стандартизация, k-means, seed 42, n_init 20, k = 3); на каждую группу и отсечку — Optuna TPE, n_trials = 20, seed 42, цель — QLIKE на внутренней валидации по О2; пространство поиска — как `SPACE["lgb"]` раунда 6 (`gl3_r6h5_engine.py`). Строки: «конфигурация + optuna по группам» × 2.
- П6. Итерация 4 — на лучшей строке П1 ∪ П5: бэггинг 10 seed (42–51), прогноз — среднее лог-прогнозов, затем поправка по О7 (у QLIKE — без неё).
- П7. Б* — строка с наименьшим средним QLIKE LOYO среди П1, П5, П6. Сравнение с эталонами — О3/О4.
- П8. Тесты — один набор на модуль: PIT (конец цели < cut во всех fit), purge/embargo, мутация «сдвиг вперёд» (признак или цель дня d+1 ловится); плюс известный ответ для градиента QLIKE. Один PR на этап.
- П9. Процессы — не более 10 всего (hw.ncpu = 12): этап 1 — 8, эталоны/HAR_i — 2.

## Этапы 2–3 (все h одним прогоном) — что меняем: основа HAR_i + Б* на остатке, комбинации, архитектура

Записано 05.11.2026 до счёта этапов 2–3; Б*_h — по У-8a.

Этап 2 (основа — HAR_i LOYO по λ, с s²_i; in-window лог-прогнозы — `data/regen/gl3_zh190/etalony/HARi_inwin_h{h}.parquet`):
- Г-1: цель — остаток ln RV − ln HAR_i (in-window, без поправки) той же отсечки; f — схема и потеря Б*_h, параметры Б*_h; ln σ̂² = ln HAR_i + c·f, c ∈ {0,5; 0,75; 1}, LOYO; поправка смещения по тикеру: exp(s²_i/2), s²_i — дисперсия итоговой лог-ошибки тикера на внутренней валидации (О2), сжатие 0,5 к общей. Если потеря Б*_h — QLIKE (h=5), Г-1 отличается от Г-2 только поправкой смещения — так и считается, записывается в отчёт.
- Г-2: та же схема Б*_h с QLIKE-целью в логах, смещение ln HAR_i — `init_score`, без поправки; c ∈ {0,5; 0,75; 1}, LOYO.
- Г-3: ln σ̂² = w_i·ln Б*_h + (1 − w_i)·ln HAR_i (оба с поправками); w_i,d = Q^HAR_i / (Q^HAR_i + Q^Б_i) по последним 252 закрытым окнам тикера (конец цели ≤ d), w_t — то же по пулу, w = 0,5·w_i + 0,5·w_t, обрезка [0; 1]; ежедневно. История до 2017 — прогнозы 2016.
- Г*_h — наименьший средний QLIKE LOYO среди Г-1, Г-2, Г-3.

Этап 3 (поверх Г*_h):
- А-1: по тикеру неотрицательный ридж (alpha = 1) в логах над {ln HAR_i, ln Б*-панель, ln Б*-тикер, ln Г*} + свободный член; Б*-панель — лучшая строка этапа 1 схемы panel или cat этого h, Б*-тикер — лучшая строка схемы ticker или cont (по mean_QLIKE пяти лет); веса тикера — годовая отсечка по OOS-прогнозам прошлых лет с концом цели < cut (2016 — первая история), сжатие 0,5 к общим весам пула; обратное преобразование — exp(s²/2) по тем же прошлым остаткам тикера.
- А-2: смесь в логах: вес стресса σ(a + b₁·z_lnRVI + b₂·z_lnRV_w) на d (z — отклонение от прошлой медианы по закрытым датам); спокойный эксперт — Г*, стрессовый — два варианта: HAR_i и Г-1 с c = 1 (LOYO между ними); a, b — годовая отсечка по QLIKE на прошлых закрытых окнах.
- А-3: поверх лучшей из {Г*, А-1, А-2} — k_i,t = EWMA(RV/σ̂²) по закрытым окнам (прогнозы не позже d−h), полураспад {20; 60; 120}, k = w·k_i + (1−w)·k_t, w ∈ {0,5; 0,75}, k ∈ [0,7; 1,5]; LOYO.
- H*_h — наименьший средний QLIKE LOYO среди Г*, А-1, А-2, А-3.

Итог h (Ж-190 п. 4): H* сравнивается с FIN_PIT и HAR_i LOYO — по среднему QLIKE лучше обоих, ≥ 3 из 5 лет лучше каждого, обе стресс-строки не хуже каждого, ≥ 10 из 17 тикеров лучше каждого. Выполнено — проект протокола открытия без открытия.
