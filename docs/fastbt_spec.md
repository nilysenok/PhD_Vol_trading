## 2. Цена исполнения входа и выхода

**Вход и выход исполняются по close сигнального бара.** Цены уровней стопа и тейка в доходность не попадают.

- **Вход.** На баре t при `sig[t]=±1` позиция открывается по `ep=close[t]` (`SW:734`, `SW:744`; тренд `SW:870`; vpred `SW:1220`; pivot `S5R:457`; vwap `S6R:371`). Затем `pos[t]=cp` (`SW:751`), и бар t зарабатывает `log(close[t+1]/close[t])`.
- **Выход.** На баре t выхода `cp=0` и `pos[t]=0`, поэтому последняя полученная доходность — `pos[t-1]*log(close[t]/close[t-1])`. Значит, выход идёт по close[t] независимо от причины. В журнале сделок цена выхода тоже `close[t]` (`SW:720`).
- **Проверка** (`exp_exec.py`, SBER S1, sl=1, tp=2 ATR): у 133 сделок `Σ pos·log_ret` на [вход; выход) совпадает с `dir·log(close_x/close_e)` до 1e-12. Из 81 выхода по SL у 46 close за уровнем стопа, то есть убыток больше расстояния до стопа.

## 4. Стоп и тейк в одном баре

Приоритет у стопа: `if low<=sl … elif high>=tp` (`SW:668-686`, `SW:936-961`, `S5R:407-420`, `S6R:338-347`). Внутри бара порядок событий не моделируется. Цена выхода всё равно `close[t]`, поэтому приоритет влияет только на причину выхода в журнале и на запуск cooldown (п. 14). Cooldown запускается только после стопа.

## 5. Гэп через уровень

Отдельной логики гэпов нет. Проверяются только `low/high` бара против уровня, исполнение по `close[t]` (п. 2), ни по уровню, ни по open. Open в движках не используется вообще (`open_arr` идёт только в `compute_base` для подсчёта красных и зелёных свечей, `SW:350-353`).

## 6. Временной стоп

- Единица — бары, то есть торговые дни. Отсчёт: на баре входа `held=0` (`SW:738`). В начале каждого следующего бара в позиции `held+=1` (`SW:653`). Выход по `held>=max_hold` (`SW:710`) происходит на баре `t_вх+max_hold` по close, после проверок SL/TP, ADX и сигнала.
- В A для контртренда и диапазона `max_hold` берётся из сетки RM (п. 12). В A для тренда **временного стопа нет**: в `bt_trend_v3` нет параметра max_hold. Варианты сетки с комментарием «OFF max_hold variants» (`V4:341-349`) на деле означают трейл с `trail_atr_mult=99` и N=30…200, то есть фактически только начальный стоп и сигнальный выход (18.6).
- В B — динамический `max_hold_t` (п. 15).
- `time_decay` (только диапазон, в сетках v4 `False`, в S5/S6 ATR-вариантах `[False, True]`): после `held>max_hold//2` тейк сужается до `ep±0,5·исходного расстояния` (`SW:928-934`).

## 7. Безубыток

- **A, контртренд и диапазон (ATR).** Условие по close: `(close[t]−ep)·dir > be_trigger·ATR_вх`. Тогда `sl=ep` (`SW:659-665`, `SW:921-925`). Проверка идёт до проверки стопа на том же баре, то есть `low[t]` сравнивается с `ep` после того, как close[t] уже известен (18.9). `be_trigger ∈ {None, 1.0}`, None превращается в −1, то есть безубыток выключен (`SW:1673`).
- **A, тренд.** `be` включается при `(close−ep)·dir > be_thresh·ATR_вх`. После этого трейл ограничен ценой входа: `tsl=max(tsl,ep)` (`SW:805-809`). None превращается в 1e12 (`SW:1684`).
- **S5 и S6 с уровнями pivot/vwap.** `be_frac=0,5` при `breakeven=True`: срабатывает при `(close−ep)·dir > 0,5·tp_dist` (`V41:372`, `S5R:400-404`, `V41:585`).
- **B.** Контртренд и диапазон: `(close−ep)·dir > k_be·σ[t]·ep` — σ текущего бара, а не бара входа (`SW:1171-1177`). Тренд: `> k_be·σ_вх·ep` (`SW:1282`).
- Безубыток срабатывает один раз (`be_active`). Выход по безубытку помечается exit_reason 4 и считается стоповым выходом (запускает cooldown).

## 8. Комиссия

**Формула всюду одна:** `net_r[t] = pos[t]·log_ret[t] − |pos[t]−pos[t−1]|·c`, разность берётся с `prepend=0` от начала маски (`V4:359-372`, `V4:416-428`, `V4:1004-1006`). Комиссия списывается на баре изменения позиции: вход и выход по c каждый, разворот ±1→∓1 стоит 2c. База — номинал позиции (вес 1), вычитается прямо из лог-доходности.

## 9. Ставка на свободный капитал

- **В v4 и v4_1 ставки нет.** Шарп при отборе считается без вычета ставки и без начисления на свободный капитал (`V4:359-372`).
- **В МСП** (`ST5:179-235`; то же `FMB:31-75`):
  - `rf_daily = key_rate(дата).ffill().bfill()/365` (`ST5:213`);
  - `cal_days[i]` = календарные дни от предыдущей даты портфеля, первый день считается за 1 (`ST5:216-219`);
  - `fdr = max(0, 1−exposure)·rf_daily·cal_days` (`ST5:227`), где `exposure` = среднее по тикерам от `|среднее по стратегиям pos|` (`ST5:196`, `ST5:208`);
  - `total = portfolio_return + fdr − margin_cost` (`ST5:232`), `excess = total − rf_daily·cal_days` (`ST5:233`).
  - Безрисковая ставка за выходные и закрытие биржи (25.02–24.03.2022) начисляется одним баром.
- **Источник ставки.** Путь `/Users/nilysenok/Desktop/PhD/.../cbr_key_rate.parquet` (`ST5:42`, `FMB:17`) на Маке отсутствует. Без файла код молча берёт плоские 16% (`ST5:71-73`).

## 10. Размер позиции, маржа, плечо

- Позиция (тикер, стратегия, подход) принимает значения {−1, 0, +1}, это 100% номинала (`V4:631`, `V4:1521-1523`). Шорт симметричен, стоимость заимствования не учитывается. В A/B/C/D плеча нет. D — бинарный затвор, масштаба нет, хотя `max_lev` есть в сетке (п. 15).
- МСП: вес 1/6 на стратегию внутри тикера, затем EW по доступным тикерам (`ST5:206-210`). Экспозиция всегда ≤1, фактический максимум 0,22–0,28.
- `margin_cost = max(0, exposure−1)·(key+0,02)/365` (`ST5:230`) не умножается на `cal_days` и **ни разу не срабатывает**.

## 11. Сигналы S1–S6 (daily, версии, давшие позиции)

Общее для всех:
- `sig[:WARMUP]=0`, `WARMUP=200` баров.
- Фильтр объёма `vf_pass`: запрет, если `volume < 0,5·SMA20(volume)` (`SW:361`).
- ATR14 — простое скользящее среднее TR (`SW:233-241`), а не по Уайлдеру. ADX14 — по Уайлдеру (`SW:243-284`).
- Все индикаторы на баре t используют данные до close[t] включительно.

**S1 MeanRev** (`SW:489-507`, сетка `SW:79`).
- `z=(close−SMA_w)/STD_w` (ddof=1).
- Long при `z<−z_entry`, short при `z>z_entry`, плюс фильтры: `vol_regime=ATR14/SMA50(ATR14)<1,2`; ≥3 красных свечи из 5 для long (зелёных для short); `volume<SMA5(volume)`; `vf_pass`.
- Выход по сигналу: `|z|<z_exit`.
- Сетка: w {15, 20, 25} × z_entry {1,5; 2; 2,5} × z_exit {0,3; 0,5; 0,7} = 27.

**S2 Bollinger** (`SW:509-534`).
- Long при `close<=SMA−k·STD`, short при `close>=SMA+k·STD`, те же фильтры, что у S1.
- Выход — пересечение close через SMA.
- Сетка: w {15, 20, 25} × k {1,5; 2; 2,5} = 9.

**S3 Donchian** (`SW:536-557`).
- Long при `close>max(high, w)[t−1]`, short при `close<min(low, w)[t−1]`; фильтры `ADX>20`, `volume>SMA20(volume)`, `vf_pass`.
- Daily-тренд-фильтр не применяется: `daily_trend=None` для daily (`V4:1075-1078`).
- Выход long — `close<min(low, w)[t−1]`, short зеркально.
- Сетка: w {10, 15, 20, 25} = 4.

**S4 Supertrend** (`SW:559-577`, расчёт индикатора `SW:286-313`).
- Long — пересечение close вверх через ST, short — вниз; фильтры `ADX>20`, `vf_pass`.
- Выход — обратное пересечение.
- Сетка: период {10, 14, 20} × множитель {2; 2,5; 3; 3,5} = 12.

**S5 Pivot (V41)** (`V41:180-362`, сигналы `S5R:245-297`).
- Уровни: недельные или месячные pivot по H/L/C **предыдущей** ISO-недели или месяца (`S5R:87-172`), classic или fibonacci (`S5R:68-84`).
- Long при `close<S1`, short при `close>R1`.
- Наборы фильтров: fs2 — ADX<30 и |наклон SMA20 за 10 баров|<0,02; fs3 — плюс vol_regime<0,95; fs4 — ADX<25, ширина BB < её 30-го перцентиля за 252 бара, |наклон|<0,01, vol_regime<0,9. Во всех наборах плюс `vf_pass`.
- Выход — пересечение close через P.
- Сетка сигналов: период {weekly, monthly} × тип {classic, fibonacci} × fs {2, 3, 4} = 12 (`S5R:484-488`).
- RM: pivot 216 (`S5R:496-503`) + ATR 288 (`S5R:514-521`) = 504.
- SL pivot: `|S1−S2|·{1; 0,5}·(1+buffer)`; TP: `|P−S1|` (до P), `|R1−S1|` (до следующего уровня) или его половина (`S5R:304-362`). Для short используются R1/R2.

**S6 VWAP (V41)** (`V41:400-575`, сигналы `S6R:217-276`).
- `VWAP_w = Σ(tp·vol)/Σvol` по окну w, `dev = STD(close−VWAP, w)` (`S6R:201-214`).
- Long при `close<VWAP−m·dev`, short при `close>VWAP+m·dev`.
- Наборы фильтров fs1–fs4: fs1 — ADX<35, остальные как в S5.
- `dir_bias=ON`: long только при MA50>MA200 на дневных данных, short только при MA50<MA200 (`V41:161-171`, `S6R:264-269`).
- Выход: `|close−VWAP|<0,5·dev`.
- Сетка: w {5, 10, 20, 60} × m {0,5; 1; 1,5; 2} × fs {1, 2, 3, 4} × bias {OFF, ON} = 128 (`S6R:419-424`).
- RM: ATR 216 + VWAP 48 = 264 (`S6R:435-450`).

**Сила сигнала для слоя исполнения** (`V4:128-204`): S1 — `min(|z|/3, 1)`; S2 — `min(пробой/(0,5·STD), 1)`; S3 — `min(ADX/35, 1)`; S4 — `min(|close−ST|/(1,5·ATR), 1)`; S5 — `min(dist/|R1−S1|, 1)` (`V41:244-248`); S6 — `min(|close−VWAP|/(2·dev), 1)` (`V41:461-469`).

## 13. Отбор топ-10 и голосование

- **Метрика.** `calc_sharpe_v4` = `mean(net_r)/std(net_r, ddof=1)·√252` по всем барам маски, включая бары без позиции, комиссия 0,40%, без ставки (`V4:359-372`). Пустая маска даёт −999, std<1e-12 даёт 0.
- **Окна.** A — маска обучения; B, C, D — маска валидации (п. 16).
- **Ничьи.** `sorted(..., reverse=True)` устойчив, поэтому при равном Шарпе выигрывает порядок перебора. Порядок перебора — `expand_grid`: декартово произведение по **отсортированным именам ключей**, последний ключ меняется быстрее всех (`SW:191-197`). В B, C, D выбор идёт по строгому `>`, выигрывает первая конфигурация в порядке циклов (`V4:723`, `V4:788`, `V4:943`).
- **Ограничения C** (`V4:788-796`). Конфигурация принимается, только если экспозиция ≥5% и сделок в год ≥10 на маске валидации. Если таких нет, второй проход с порогами 3% и 6 сделок. В V41 пороги 2%/3, затем 1%/1, затем запасной вариант «C = A» (`V41:929-943`). Это равносильно argmax по допустимым конфигурациям.
- **Голосование** (A: `V4:627-631`; B: `V4:717-721`; V41: `V41:353-356`):
  ```python
  mag = mean(|pos_k|);  dir = sign(Σ pos_k);  ens = (mag > 0.5) · dir
  ```
  Условие «больше половины» относится к **ненулевым** голосам в любую сторону, а направление даёт знак суммы. Пример (`exp_exec.py`): 4 long, 2 short, 4 flat дают +1; 3 long, 3 short, 4 flat дают 0. В диссертации (§2.3.3): «более половины сигнализируют в одном направлении». Это расходится с кодом (18.5).
- **Что голосует.** Каждая из top-10 — отдельный прогон движка с собственными сигналом, RM и параметрами слоя исполнения (`V4:615-625`) на `[WARMUP, test_end)`. Отдельной ребалансировки нет: позиция ансамбля пересчитывается на каждом баре.
- **Слой исполнения** (`V4:211-275`) применяется к каждой из 10 позиций до голосования:
  1. `binary=|pos|>0,5`, при этом бары с силой ниже `min_strength` обнуляются, **в том числе посреди открытой сделки**;
  2. `consec_entry`: бинарная позиция 1 появляется только с k-го подряд бара серии;
  3. `min_hold` продлевает единицы на k баров;
  4. `cooldown`: после перехода 1→0 следующие k баров принудительно 0;
  5. направление берётся заново по знаку сырой позиции на каждом баре (`V4:274-275`).

  Следствие шага 5: `min_hold` не продлевает позицию за пределы сырой сделки, он только восстанавливает бары, обнулённые фильтром силы. Проверка (`exp_exec.py`, SBER S1): при min_strength=0 позиции с min_hold=5 и с min_hold=0 совпадают и равны сырой. При 0,5 фильтр обнуляет 270 баров внутри сделок, min_hold=5 возвращает 164 из них.

## 14. Порядок в баре и разворот

Порядок в баре t (`SW:648-751`; остальные движки так же):
1. `cooldown_rem−=1`.
2. Если позиция открыта: `held+=1` → безубыток по close → SL → TP → [диапазон: ADX14>30 (`SW:962-966`)] → сигнальный выход `exit[t]` → `held>=max_hold`. Тренд: пересчёт трейла → SL → сигнальный выход (`SW:787-848`).
3. При закрытии после стопа или безубытка `cooldown_rem=cd` (`SW:724`).
4. Если позиции нет (в том числе её только что закрыли) и `cooldown_rem==0`, то вход по `sig[t]` по close[t] (`SW:729`).
5. `pos[t]=cp`.

Следствия:
- Повторный вход на том же баре разрешён. Выход и вход в ту же сторону оставляют `pos` неизменной, поэтому комиссии нет (пример `exp_exec.py`: сделка закрыта на баре 211 и тут же открыта заново).
- Разворот: выход по любой причине плюс противоположный `sig[t]` на том же баре дают переход ±1→∓1, комиссия 2c.
- Противоположный сигнал при открытой позиции **игнорируется**, если нет выхода.
- После стопа cooldown блокирует бары t…t+cd−1, ближайший вход — t+cd.
- В B cooldown всегда равен 5 барам после стопа: это значение по умолчанию в `dispatch_bt_vpred_v3`, в сетке B его нет (`SW:1714`, `V41:667`).

## 15. B, C, D: формулы и что происходит с открытой позицией

**B (σ_pred вместо ATR)**:
- Контртренд и диапазон (`SW:1144-1246`, `SW:1351-1458`):
  - `sl=close·(1∓k_sl·σ[t_вх])`, `tp=close·(1±k_sl·ratio·σ[t_вх])`; σ=NaN заменяется на 0,02 (`SW:1218-1222`).
  - `max_hold_t = int(clip(base·(σ_med/σ_вх)^γ, 3, 3·base))`, если γ задан, иначе base (`SW:1226-1230`); base = 20 для контртренда, 10 для диапазона (`SW:1717`, `SW:1734`).
  - `σ_med` — медиана σ>1e-6 **по всему ряду**, включая будущее (`V4:703-704`, 18.8).
  - Диапазон, кроме того, выходит по ADX>30.
- Тренд (`SW:1250-1347`):
  - начальный `sl=ep·(1∓k_sl·σ_вх)`;
  - трейл `tsl = rh_10[t] − k_trail·σ[t]·close[t]` (N=10 жёстко, `SW:1725`);
  - безубыток по σ_вх;
  - `max_hold_t` с base 30 (`SW:1724`). Временной стоп есть, хотя в A у тренда его нет.
- Сигналы — top-10 сигнальных наборов A этого года (`V4:684-695`).
- Параметры слоя исполнения для всех 10 берутся от **top-1** A (`V4:678-682`, `V4:636`).
- Выбирается одна конфигурация B: argmax Шарпа ансамбля на маске валидации (`V4:700-725`).

**C (маска режимов)** (`SW:1953-1994`):
- Ранг: `pctrank = rolling(L, min_periods=max(50, L//5)).rank(pct=True)` по σ_h, только прошлое и текущее значение.
- Тренд: `pctrank>thr`. Контртренд: `pctrank<1−thr`. Диапазон: `lo≤pctrank≤hi`.
- Гистерезис (только тренд и контртренд, `SW:1931-1950`): вход при `>thr` (`<1−thr`), выход при `<thr−0,10` (`>1−thr+0,10`).
- `rise`/`fall`: `σ[t]−σ[t−5] >0 / <0`.
- `term_filter`: `σ_h22/σ_h1 >1` для тренда, `<1` для контртренда.
- Бары без σ (до 2017 года) получают маску False.
- **С открытой позицией.** Маска применяется к уже готовой позиции ансамбля A поэлементно: `final_pos[~mask]=0` (`V4:884-886`). Позиция на маскированном баре **закрывается** по close этого бара. Когда маска снова открывается, а A всё ещё в сделке, позиция **открывается заново посреди сделки A**, тоже по close. Обе операции платят комиссию. По сохранённым позициям C (daily, 2022–2025): 1384 закрытия и 1323 повторных входа внутри непрерывной сделки A.

**D (затвор)** (`SW:2162-2188`, `V4:923-975`):
- σ проходит сглаживание (`ewm(span)`, если задано), затем `max(σ, floor)`, `min(σ, cap)`, затем NaN или значения <1e-6 заменяются на 1e-6.
- `scale = (target/σ)^γ` либо `(1/σ)/rolling_mean(1/σ, L, min 20)`; затем `scale=min(scale, max_lev)`.
- `gate = scale ≥ порог`, `final = pos_A·gate`.
- Размер позиции не масштабируется.
- С открытой позицией то же, что в C: закрытие и повторное открытие посреди сделки A (204 и 222 случая в сохранённых данных).
- Единицы не согласованы: σ дневная (около 0,017), а target, floor и cap заданы в годовом масштабе (18.7).

## 16. Walk-forward: окна и маски

- `_year_bounds(dates, Y)` возвращает `(searchsorted(1 янв Y), searchsorted(1 янв Y+1))` (`SW:1753-1758`).
- **A** (`V4:493-503`):
  - тестовые годы 2020–2025 (+2026), в МСП идут только 2022–2025 (`ST5:50`, файлы `wf_positions` содержат 2022–2025);
  - маска обучения `[WARMUP, _year_bounds(Y)[1])`, то есть от 27.03.2015 **до 1 января Y+1** (утечка);
  - отбор гоняет движок до `train_end`;
  - тестовый прогон идёт до `test_end=_year_bounds(Y+1)[1]` (1 января Y+2, для 2025 до n);
  - в файл записываются бары `[_year_bounds(Y)[0], _year_bounds(Y+1)[0])` (`V4:1173-1181`);
  - окно расширяющееся, параметры свои на каждый Y;
  - состояние сделок на 1 января Y порождено параметрами года Y, применёнными к истории, а не переносится из года Y−1. На стыке лет позиция может скачком поменяться, и в МСП это засчитывается как оборот (`ST5:192`).
- **B, C, D** (`V4:660-669`, `V4:839-848`, `V4:906-915`; V41 так же):
  - тестовые годы 2022–2025;
  - валидация `[_year_bounds(2020)[1], _year_bounds(Y)[1])` = **[1 янв 2021; 1 янв Y+1)**, то есть включает тестовый год (утечка), а 2020 год не входит;
  - горизонт σ (h1/h5/h22) выбирается на той же маске вместе с прочими параметрами (как элемент сетки B и как цикл в C и D);
  - C и D берут позицию ансамбля A этого же года (`V4:850`, `V4:917`). Её параметры подобраны с маской до конца Y.
- **Вариант [0]** (корректный по смыслу). A: `train_end=_year_bounds(Y)[0]`, обучение до 31.12.Y−1. B/C/D: `val_end=_year_bounds(Y)[0]`. Начало `val_start` — решение владельца: `_year_bounds(2020)[0]` даёт 2020…Y−1, `[1]` даёт 2021…Y−1. В fastbt маски нужно сделать параметром, чтобы режим [1] воспроизводил печать.
- **Отдельная утечка C для S1/S2** (18.4). V41 берёт позиции A из parquet, а там ненулевые значения есть **только в тестовом году Y** (`V41:1446-1478`). Поэтому Шарп «валидации» [2021; Y+1) считается фактически только по году Y.

## 17. Метрики

- **Отбор и пороги в v4.** Шарп см. п. 13. MDD = `min(cumsum(net) − cummax(cumsum(net)))` в лог-доходностях (`V4:416-428`). Экспозиция — % баров с pos≠0 (`V4:431-437`). Сделки — число входов из 0 (`SW:1593-1609`).
- **Метрики v4 по годам** (`V4:375-413`): Шарп чистый при 0,40%, без ставки; годовая доходность `mean·252`; волатильность `std·√252`; MDD по cumsum.
- **МСП, печать.** `FB:20-22`: `Шарп = mean(excess)/std(excess, ddof=1)·√252` по дням 2022-01-03…2025-12-30 из `MSP_*_inst.csv`. Проверка: 1,3153 / 1,4654 / 2,5099 / 2,5357 совпадают с печатями.
- **В самом `stage5_msp.py`** знаменатель другой: `std(total)` (`ST5:267-268`). Получилось бы 1,289 / 1,432 / 2,386 / 2,419.
- **Сортино** (`ST5:284-286`): `mean(excess)·√252 / std(total[total<0], ddof=1)`. Отрицательные дни берутся по total, а не по excess, и std считается по их значениям, а не как полуотклонение относительно нуля.
- **MDD МСП:** `max(cummax(cumsum(total)) − cumsum(total))·100` (`ST5:289-292`).
- **Агрегация МСП ALL6 × EW** (`ST5:421-442`):
  1. для каждой пары (дата, тикер) берутся средние позиции и валовой доходности по **имеющимся** стратегиям. Если строк C нет (п. 0, 18.3), среднее считается по 5 стратегиям;
  2. затем на каждом тикере вычитается комиссия от `|Δ средней позиции|`;
  3. затем EW по тикерам, присутствующим на дату.

  Весов и ребалансировки нет: веса фиксированные, пересчитываются каждый день.
- Бутстрап: `FB:25-35`, 10 000 повторов, seed 42.

## 18. Сомнения (ничего не исправлено, только описание)

1. **Утечка теста в маске.** `_year_bounds(...)[1]` в A (`V4:494`), B/C/D (`V4:661-662`, `V4:840-841`, `V4:907-908`), а также в V41 (`V41:207`, `V41:426`, `V41:617-618`, `V41:918-919`). Начало валидации 2021, а не 2020.
2. **Канонический код — c22a4b3, а не HEAD.** HEAD `strategies_walkforward.py` даёт другие сетки и генераторы и падает на `_pctile_cache`. S5/S6 и C для S1/S2 взяты из V41, а не из V4 (п. 0). README и текст считают источником `stage3_walkforward`.
3. **В сохранённых позициях нет C** для S3 MTLR 2022, а также S4 MTLR 2022–2023, PHOR 2024, TATN 2023: 1228 строк. Закоммиченный V4 в этих случаях отдаёт «C = A» (`V4:862-866`), а прогон, давший файл, видимо, шёл без этого запасного варианта. МСП C усредняет такие пары по 5 стратегиям. Для один-в-один fastbt должен при отсутствии допустимой конфигурации C **пропускать единицу** (режим-флаг).
4. **Утечка C для S1/S2 daily.** V41 загружает позиции A только тестового года (`V41:1460-1476`), поэтому валидация C для этих стратегий — это сам тестовый год.
5. **Голосование.** Порог `mean|pos|>0,5` и `sign(Σ)` (п. 13) — не «больше половины в одном направлении», как в §2.3.3.
6. **Тренд A без временного стопа.** «OFF max_hold» на деле трейл ×99 (`V4:341-349`). `chandelier` совпадает с `fixed_atr` (`SW:791-794`). В parabolic не используется `sar_max`. В B у тренда временной стоп есть (base 30).
7. **D, единицы.** σ дневная, target 0,05–0,30, floor 0,10 и cap 0,60 годовые. В стандартном варианте `scale=(tv/σ)^γ` почти всегда ≥ max_lev, и затвор открыт. При floor=0,10 scale становится константой. Отсекает в основном вариант обратной волатильности. По сохранённым позициям D закрывает сделку A посреди только 204 раза, а C — 1384 раза.
8. **B: `σ_med` по всему ряду**, включая тест и будущее (`V4:703-704`, `V4:730-731`). Это слабое заглядывание вперёд в динамическом max_hold.
9. **Внутрибарная неоднозначность.**
   - Безубыток включается по close[t], и на том же баре low[t] сравнивается с ep (`SW:659-670`).
   - Трейл тренда использует `rh_N`, включающий high[t], и на том же баре сравнивается с low[t] (`SW:791`, `SW:814`).
   - Исполнение всегда по close, поэтому стопы и тейки — только триггеры. Убыток по стопу не ограничен уровнем (46 из 81 стоп-выхода в примере, п. 2).
10. **Комиссия.** Отбор идёт при 0,40% на сторону (`V4:115`), в тексте и МСП 0,05–0,06%. В `MSP_A_inst` и `MSP_D_inst` комиссии нет, в `MSP_B` есть (аудит). Комиссия МСП считается на усреднённой по 6 стратегиям позиции, поэтому встречные сделки стратегий взаимно гасятся. В метриках v4 по годам `prepend=0` на начало каждого года: если позиция открыта 1 января, комиссия входа берётся снова.
11. **Ставка.** Исходный файл недоступен (`ST5:42`). Без него код молча подставляет 16%. Ряд, давший печать, держит 21% весь 2025 год и пропускает решения 14.02.2022 и 16.09.2024 (п. 9). `margin_cost` без `cal_days`.
12. **Две формулы Шарпа МСП**: печать (`FB:20-22`, знаменатель std(excess)) и `ST5:268` (знаменатель std(total)). Сортино по total<0 (`ST5:284-286`).
13. **Слой исполнения.** `min_hold` практически не работает (п. 13). Фильтр силы обнуляет бары внутри сделки, и это даёт лишние выходы и входы с комиссией. Частичный выход (cp=0,5) после дискретизации `>0,5` стал бы нулём; в сетках v4 он выключен.
14. **Неразличимые точки сетки.** В C для диапазона гистерезис игнорируется (`SW:1970-1972`), так что точки дублируются. В фазе 2 соседи ±2 по индексу частично совпадают с уже посчитанными точками грубой сетки.
15. **B и печать.** Печать B (1,47) собрана из `wf_positions_B.parquet` с неизвестным генератором. B из v4/v4_1 (`daily_positions_pre2026`, approach B) с ним не совпадает (аудит). Спецификация B выше описывает v4/v4_1.
16. **v4 для часового таймфрейма** использует дневные окна сигналов (`V4:481` `SIGNAL_GRIDS[sid]`) и `WARMUP=200` на часовых барах. В печать МСП это не входит.
17. **Данные.**
    - IRAO 20.01.2015 (+4,68 лог) не скорректирован. В доходности не попадает (до WARMUP), но через ADX влияет на апрель–июль 2015 года в окне обучения A.
    - Ценовых корректировок нет вообще.
    - Close — последняя 10-минутная свеча, а не официальное закрытие.
    - Общего календаря нет.
18. **Дата σ_pred.** Прогноз в строке t сильнее связан с RV дня t−1, чем дня t (0,63 против 0,41), а цель — RV дня t+1. Вероятен лишний лаг. Заглядывания вперёд нет.
