### 1. ГЛАВНАЯ ЗАДАЧА

Разработать принципиально новую гибридную архитектуру прогнозирования реализованной дисперсии SBER на следующий торговый день.

**Единственный тикер — SBER. Использовать всю доступную историю 10-минутных данных за 2014–2026 годы.**

HAR-J остаётся эконометрическим фундаментом прогноза.

XGBoost и LightGBM используются как готовые прогнозные эксперты и, при необходимости, как ограниченные корректирующие модули.

Главная инновация — объединить:

1. Анализ последовательности 10-минутных свечей.
2. Обучаемый Intraday Encoder.
3. Специализированные корректирующие эксперты.
4. Gating Network для определения оптимальных весов.
5. Прямую оптимизацию итогового прогноза по QLIKE.

Не ограничиваться простым усреднением моделей.

Не повторять динамические веса и режимные смеси V4 без действительно нового источника информации.

### 3. АРХИТЕКТУРА

Для каждого завершённого торгового дня t сформировать последовательность:

`X_t = [x_t,1, x_t,2, ..., x_t,n]`

где каждый элемент содержит доступные характеристики соответствующей 10-минутной свечи.

Использовать при наличии:

- логарифмическую доходность;
- High–Low range;
- Open–Close return;
- объём;
- нормированный объём;
- квадрат доходности;
- отрицательную и положительную семивариации;
- положение цены относительно дневной VWAP;
- внутридневное накопление RV;
- относительное положение свечи внутри торговой сессии.

Не добавлять признаки, если для них нет надёжных исторических данных.

Никаких будущих M10-свечей.

### 4. INTRADAY ENCODER

Разработать компактный модуль извлечения информации из последовательности 10-минутных свечей.

Проверить архитектуры:

**E1. Temporal Convolutional Network (TCN)**

Небольшая причинная свёрточная сеть с ограниченным числом параметров.

**E2. Compact 1D CNN**

Извлекает локальные паттерны волатильности, объёма и изменения цены.

**E3. Path Signature Encoder**

Использует упорядоченную внутридневную траекторию и её смешанные взаимодействия.

**E4. Fixed Statistical Encoder**

Контрольная модель с заранее определёнными внутридневными признаками.

Приоритет — TCN и компактная CNN, но их необходимо сравнить с более простым encoder, чтобы отделить пользу глубокой архитектуры от обычных M10-признаков.

Не использовать Transformer без предварительного доказательства необходимости.

### 5. МНОГОМАСШТАБНАЯ ПАМЯТЬ

Одна торговая сессия может содержать недостаточно информации.

Поэтому исследовать последовательности последних:

- 1 торгового дня;
- 5 торговых дней;
- 22 торговых дней.

Это **исторические окна признаков**, а не новые горизонты прогнозирования.

Прогноз остаётся строго h=1.

Предлагаемая конструкция:

`z_t = Encoder(M10_history_t)`

где z_t — компактный вектор скрытых характеристик.

Начать с 1 и 5 дней. Окно 22 дня добавлять только при подтверждённой необходимости.

Ограничивать размер скрытого пространства.

Не обучать десятки тысяч свободных параметров при ограниченной дневной истории.

### 6. СПЕЦИАЛИЗИРОВАННЫЕ ЭКСПЕРТЫ

Создать несколько корректирующих модулей.

**Expert 0 — HAR-J**

Нулевая поправка: итоговый прогноз совпадает с HAR-J.

**Expert 1 — Normal Volatility**

Коррекция HAR-J в спокойных рыночных состояниях.

**Expert 2 — Shock / Jump**

Коррекция при нестабильной внутридневной динамике.

**Expert 3 — Recovery / Mean Reversion**

Коррекция после завершившихся всплесков RV.

Специализацию экспертов обучать на данных, не считать её заданной заранее.

Начать с двух ненулевых экспертов.

Третий добавить только при доказанной дополнительной информации.

### 7. GATING NETWORK — ОБУЧЕНИЕ ОПТИМАЛЬНЫХ ПРОПОРЦИЙ

Создать компактную обучаемую сеть распределения доверия между экспертами.

Вход:

`Z_gate = [z_M10, HARJ, XGB, LGBM, forecast_disagreement, past_errors, regime_features]`

Сеть выдаёт:

`pi_t = softmax(G(Z_gate))`

Сумма весов равна единице.

Каждый вес неотрицателен.

Гибрид должен определять пропорции самостоятельно, без заранее заданных правил вида 70/20/10.

Рассмотреть две разные архитектуры.

**Architecture A — Forecast MoE**

`F = pi_H*H + pi_X*X + pi_L*L`

Это контрольная конструкция: динамическая смесь самостоятельных прогнозов.

**Architecture B — Residual MoE**

`F = H * exp(sum_k pi_k*g_k(z_M10))`

Это основная исследовательская архитектура.

Эксперты корректируют HAR-J с учётом M10-информации.

Дополнительно проверить вариант:

`F = H * exp(w*log(M/H) + sum_k pi_k*g_k(z_M10))`

где M — выбранный исторически доступный прогноз самостоятельного бустинга.

Не использовать обе архитектуры одновременно без отдельной абляции.

### 8. ОБУЧЕНИЕ ПО QLIKE

Основная функция:

`QLIKE = log(F) + RV_actual/F`

Обучать метамодель непосредственно на итоговой QLIKE при положительных прогнозах.

Добавить:

- L2-регуляризацию;
- ограничение размера поправки;
- мягкое сглаживание весов;
- предотвращение схлопывания экспертов;
- early stopping на внутренней временной валидации;
- shrinkage к HAR-J или простой смеси.

Не обучать на будущих фактах соответствующего прогнозируемого дня.

Если обучаются сразу Encoder и Gating Network, использовать строгий walk-forward и вложенную временную проверку.

### 9. ДВУХЭТАПНОЕ ОБУЧЕНИЕ

Сравнить два механизма.

**Stage A — Frozen Encoder**

Сначала получить компактные M10-представления, затем обучать небольшую коррекцию HAR-J.

При выборе способа получения encoder-признаков не допускать использования данных из будущих тестовых окон.

**Stage B — Joint Training**

Совместно обучать Encoder, корректирующих экспертов и Gating Network по QLIKE.

Проверить, даёт ли совместное обучение дополнительную ценность.

Не считать его автоматически лучше: сложная архитектура может переобучиться.

### 10. ПРОБЛЕМА РАЗМЕРА ВЫБОРКИ

В распоряжении имеется большое количество M10-свечей, но существенно меньше независимых целевых дневных наблюдений.

Не считать каждую M10-свечу отдельным независимым наблюдением для дневного QLIKE.

Использовать:

- компактную сеть;
- ограниченное число экспертов;
- сильную регуляризацию;
- детерминированные seeds;
- последовательный временной протокол;
- внутренние временные окна;
- регистрацию каждого эксперимента.

Отдельно оценить, сколько уникальных дневных примеров реально используется для обучения.

### 11. ОСОБАЯ ПРОВЕРКА — ПОСЛЕ 2021 ГОДА

Проблема предыдущих гибридов: они улучшали прогнозы на ранней истории, но теряли преимущество относительно самостоятельного XGBoost позднее.

Проверить, способна ли новая M10-архитектура обнаруживать такие изменения.

Показать:

- распределение весов до и после 2021 года;
- изменение ошибки HAR-J;
- вклад Intraday Encoder;
- эффективность каждого эксперта;
- долю дней, когда гибрид лучше XGBoost;
- влияние кризисных дней;
- устойчивость без наиболее влиятельных наблюдений.

Не использовать фактическую позднюю историю для выбора гиперпараметров более ранних прогнозов.
