## Цель

Скрипт открытия должен уметь выполнить ровно один повтор после зафиксированного сбоя. Первый замок `data/fwd/models/OPENED_HARJ_FWD.json` (статус «сбой», sha256 1869be4539c2…) и `docs/otchety/harj_fwd/FREEZE.json` (v1, sha256 4c9085d6…) не удаляются, не перемещаются и не перезаписываются.

1. **FREEZE v2** — новый файл `docs/otchety/harj_fwd/FREEZE_v2.json`, пишется отдельным писателем.
   - Ключ `v` = 2.
   - Ссылки на предыдущие:
     - `prev_freeze`: путь и sha256 v1;
     - `prev_lock`: путь, sha256, статус, причина;
     - `prev_commit` = коммит v1 (37c3180c…);
     - `fix_commit` — коммит с правкой.
   - `owner_yes` = Ж-249, с дословной цитатой: «Разрешаю один повтор запуска проверки на новом периоде после устранения технической ошибки.»
   - `outputs.lock` = `data/fwd/models/OPENED_HARJ_FWD_r2.json`.
   - Пересчитываются только технические поля: `code_sha256` (замыкание импортов на новом коммите), `git`, `packages`, `written_at`.
   - Научные поля копируются из v1 побайтно по значению: `calendar`, `dates`, `candidates`, `controls`, `family`, `params`, `initial_state`, `not_admitted`, `rehearsal`, `power`, `inputs_archive_sha256`, `inputs_new_sha256`, `derived_archive_sha256`. Входы перехэшируются и обязаны совпасть с v1; несовпадение — отказ писателя.
   - `diff_v1`: список ключей, отличающихся от v1, с пометкой «технический». Любое отличие научного ключа — отказ.
   - Писатель отказывает, если `FREEZE_v2.json` уже существует.
2. **Скрипт открытия** (`scripts/fwd/otkrytie_harj_fwd.py` и проверки) получает явный режим повтора, например `--povtor` вместе с `--otkryt`. Режим повтора:
   - читает `FREEZE_v2.json` и проверяет его так же строго, как v1: sha кода с замыканием, входы, пакеты, гейты без `pending`/`ABANDON`/пустого EVIDENCE;
   - требует «да» Ж-249 в журнале, по образцу проверки Ж-248;
   - требует, чтобы первый замок существовал, был в статусе «сбой» и его sha256 совпадал с `prev_lock` в v2;
   - отказывает, если замок r2 уже существует (O_EXCL, как сейчас);
   - ставит замок r2 до чтения новых данных;
   - пишет выходы `FWD_*` и прогнозы новых дат только в несуществующие файлы; существующий файл — отказ до замка;
   - по любому исключению фиксирует в r2 статус «сбой» с трассой, как сейчас.
   Режим без `--povtor` ведёт себя как прежде: при существующем первом замке отказывает.
3. **Песочница** (`--pesochnica`) проходит путь повтора целиком на поддельном периоде из архива. В tmp создаются поддельные первый замок «сбой» и FREEZE v1/v2; реальные файлы не открываются. Результат: все узлы на 38 парах побитно равны архиву, 7 строк семейства.
