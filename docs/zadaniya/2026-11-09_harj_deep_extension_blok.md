# 4. АРХИТЕКТУРА A — QLIKE-NATIVE HYBRID BOOSTING

## 4.1. Главная идея

Вместо самостоятельного прогнозирования RV обучать специализированный бустинг непосредственно корректировать HAR-J.

Модель:

`F = H * exp(g_XGB(Z))`

где:

- H — исторически доступный HAR-J;
- g_XGB — специализированный корректор;
- F — итоговый прогноз гибрида.

Аналогично для LightGBM.

## 4.2. Правильная функция потерь

Использовать:

`L = log(F) + Y/F`

Пусть:

`F = H * exp(g)`

Тогда:

`dL/dg = 1 - Y/F`

`d²L/dg² = Y/F`

Реализовать пользовательскую QLIKE-функцию для градиентного бустинга.

Проверить градиент и гессиан численно.

Обеспечить:

- положительность итогового прогноза;
- численную устойчивость;
- корректную инициализацию g=0;
- ограничение экстремальных поправок;
- сильную регуляризацию;
- отсутствие будущей информации.

## 4.3. Проверить две разные постановки

**A1 — Direct QLIKE Offset Boosting**

Бустинг непосредственно оптимизирует QLIKE итогового прогноза HAR-J × exp(g).

**A2 — Conditional Multiplicative Calibration**

Модель оценивает условный корректирующий множитель:

`c(Z) = E[Y/H | Z]`

Итог:

`F = H*c(Z)`

Проверить, являются ли эти способы практически эквивалентными и есть ли содержательное отличие от V6 A0g/A2.

Если архитектура уже исследована, не повторять её как новую конфигурацию.

# 5. АРХИТЕКТУРА B — STABLE + ADAPTIVE RESIDUAL

## 5.1. Главная гипотеза

Ошибка HAR-J содержит две качественно разные составляющие:

- устойчивую, существующую длительное время;
- временно изменяющуюся при смене рыночных условий.

Одна общая ML-поправка может смешивать эти закономерности и ухудшать прогноз.

## 5.2. Предлагаемая модель

`F = H * exp(g_stable(Z) + a_t*g_adaptive(Z))`

где:

- g_stable — устойчивый компонент;
- g_adaptive — специализированная адаптивная поправка;
- a_t — коэффициент её применения.

Сначала оценить устойчивую поправку на предыдущей истории.

Затем отдельно обучать адаптивный компонент для объяснения оставшейся условной ошибки.

Не обучать две одинаковые модели на одних и тех же признаках без ограничений.

## 5.3. Инновационная часть

Адаптивный компонент должен реагировать на обнаруженное изменение статистической структуры ошибок.

Проверить:

- краткосрочное изменение QLIKE-score;
- изменение распределения прошлых RV;
- изменение корреляции между признаками и ошибкой;
- ослабление ранее работавших признаков;
- появление систематического смещения.

Механизм адаптации выбирает скорость обновления на основании причинно наблюдаемых сигналов.

Не использовать календарную метку «после 2022 года» как готовое правило.

Детектор смены режима должен обнаруживать изменения самостоятельно по прошлой информации.

Обязательно сравнить с уже проверенными state-space и online-механизмами V4/V5.

Если математического отличия нет, исключить конфигурацию.

# 6. АРХИТЕКТУРА C — UNCERTAINTY-GATED CORRECTION

## 6.1. Главная проблема

Иногда коррекция HAR-J полезна, иногда ухудшает прогноз.

Нужно оценивать не только величину предлагаемой ML-поправки, но и неопределённость её эффективности.

## 6.2. Математическая конструкция

`F = H * exp(alpha_t*g_ML(Z_t))`

где:

`0 <= alpha_t <= 1`

Коэффициент alpha зависит от ранее оценённой неопределённости корректирующей модели.

Если дополнительная информация надёжна, коррекция применяется сильнее.

Если информация неустойчива, коррекция приближается к нулю.

## 6.3. Как оценивать неопределённость

Рассмотреть:

- расхождение прогнозов нескольких исторически обученных корректоров;
- нестабильность OOF-коррекции;
- изменение ошибок по прошлым временным окнам;
- локальную плотность наблюдений в пространстве признаков;
- неустойчивость M10 Encoder.

Начать с простых оценок.

Не создавать большую вторую нейросеть для прогнозирования доверия.

Не выдавать эпистемическую неопределённость за точную вероятность улучшения.

## 6.4. Контроль

Сравнить:

- фиксированную коррекцию;
- коррекцию с ограничением величины;
- условную коррекцию по неопределённости.

Показать, добавляет ли именно неопределённость информацию сверх обычного режимного Gating V4/V7.

# 7. АРХИТЕКТУРА D — TAIL-AWARE HYBRID

## 7.1. Главная гипотеза

Ошибки гибрида могут концентрироваться в экстремальных днях.

Если обычная коррекция улучшает спокойные периоды, но сильно недооценивает редкие всплески RV, средняя QLIKE может ухудшаться.

Проверить это количественно до обучения.

## 7.2. Двухкомпонентная конструкция

`F = H * [(1-p_t)*c_normal(Z_t) + p_t*c_stress(Z_t)]`

где:

- p_t — вероятность стрессового состояния следующего дня;
- c_normal — коррекция нормального состояния;
- c_stress — коррекция стрессового состояния.

Все компоненты должны быть положительными.

При c_normal=c_stress=1 результат точно совпадает с HAR-J.

Вероятность p_t формировать только по доступной прошлой информации.

## 7.3. Обучение

Использовать:

- M10-концентрацию RV;
- историю крупных движений;
- отрицательную семивариацию;
- историю экстремальных дневных RV;
- динамику объёма;
- исторические ошибки HAR-J.

Не использовать фактическое стрессовое состояние следующего дня как признак.

Обязательно проверить калибровку p_t и итоговую QLIKE.

Не повторять старую jump-aware модель под новым названием.

Главное отличие должно заключаться в совместном согласованном прогнозировании условных компонентов и итогового среднего.

# 8. АРХИТЕКТУРА E — FORECAST-SUPERVISED M10

## 8.1. Проблема прежнего Encoder

Простая TCN/CNN может плохо использовать информацию отдельных свечей, поскольку обучается через ограниченное число дневных целевых наблюдений.

Предлагается заменить свободное кодирование на структурированную обучаемую агрегацию.

## 8.2. Neural/Bespoke Realized Measures

`B_t = sum_k w_t,k*r²_t,k`

Веса зависят от исторически доступных характеристик M10.

Использовать положительные нормированные веса.

Проверить:

- равные веса;
- ограниченные обучаемые веса;
- веса по характеристикам свечей.

B_t используется исключительно как дополнительный исторический признак гибрида.

**Не изменять целевую RV и зафиксированную HAR-J.**

Главная задача — доказать, что новые веса свечей предсказывают ошибки старого гибрида и самостоятельного XGBoost.

Не запускать повторно то, что уже включено в V7+.

# 9. АРХИТЕКТУРА F — ORTHOGONAL JOINT HYBRID

## 9.1. Цель

Научиться совместно использовать бустинг и M10 Encoder без дублирования одной и той же информации.

Модель:

`F = H * exp(g_boost(Z) + g_M10(X))`

Сначала бустинг обучается корректировать HAR-J.

Затем Encoder обучается объяснять оставшуюся ошибку, которую бустинг не смог предсказать.

## 9.2. Последовательное обучение

Stage 1:

Обучить специализированный Hybrid-XGBoost или Hybrid-LightGBM по QLIKE с HAR-J offset.

Stage 2:

Получить причинно корректные OOF-прогнозы первой ступени.

Stage 3:

Обучить M10 Encoder исправлять остаточную условную ошибку.

Stage 4:

Проверить итоговую QLIKE гибрида.

## 9.3. Чередующееся обучение

Если последовательная конструкция показывает новую информацию, исследовать ограниченное чередование:

1. Зафиксировать Encoder, обучить бустинговую коррекцию.
2. Зафиксировать бустинг, обучить Encoder.
3. Повторить заранее заданное небольшое число раз.
4. Проверить устойчивость и дополнительную ценность.

Это не означает автоматического дифференцирования через разбиения деревьев.

Избегать сложной нестабильной совместной оптимизации.

## 9.4. Главные абляции

Сравнить:

- HAR-J + Hybrid-Boosting;
- HAR-J + M10 Encoder;
- HAR-J + Boosting + Encoder;
- последовательное обучение;
- чередующееся обучение.

Доказать, что два компонента дают взаимодополняющую информацию.
