# 2. ОТДЕЛИТЬ ТРИ ТИПА ГИБРИДОВ

## Тип A — Forecast Combination

Гибрид объединяет готовые прогнозы.

Проверить:

**A1. HAR-J + XGBoost.**

**A2. HAR-J + LightGBM.**

**A3. XGBoost + LightGBM.**

**A4. HAR-J + XGBoost + LightGBM.**

Для каждого исследовать:

- простое равновесное среднее;
- фиксированные веса, выбранные во внутренней временной валидации;
- веса по прошлому QLIKE;
- веса по прошлому RMSE;
- умеренно меняющиеся веса по прошлым 126/252/504 дням;
- ограниченные веса с регуляризацией к равновесному варианту.

Вес должен быть определён до наступления прогнозируемого дня.

Не использовать будущее значение RV.

Не выбирать веса по итоговому оценочному периоду.

Если XGBoost и LightGBM практически полностью дублируют друг друга, зафиксировать это как экономически значимый отрицательный результат.

## Тип B — Residual Hybrid

Это отдельное направление, принципиально отличающееся от усреднения.

HAR-J формирует базовый прогноз.

Бустинг прогнозирует корректировку на основе информации, которую HAR-J не объясняет.

Проверить:

**B1. HAR-J + residual XGBoost.**

**B2. HAR-J + residual LightGBM.**

Основной кандидат — положительная мультипликативная коррекция:

`RV_hybrid = RV_HAR × exp(g(X))`

Исследовать также аддитивную коррекцию с заранее установленным правилом положительности прогноза.

Приоритет отдавать QLIKE-согласованному обучению.

Для мультипликативной архитектуры проверить объектив:

`loss = log(RV_hybrid) + RV_actual / RV_hybrid`

и возможность включения `log(RV_HAR)` как offset в корректную функцию обучения.

Тщательно проверить аналитические производные, численную устойчивость, положительность и обработку малых значений RV.

**Критически важно:** residual-бустинг должен обучаться на причинно корректных исторических OOF-прогнозах HAR-J.

Нельзя обучать поправку на ошибках HAR, полученных при подгонке HAR на тех же самых наблюдениях, и затем считать это независимым прогнозным эффектом.

Проверить, предсказывает ли бустинг именно дополнительную компоненту, а не просто заново воспроизводит HAR.

## Тип C — Adaptive Hybrid

Исследовать динамическое использование прогнозов.

**C1.** Вес HAR и ML в зависимости от прошлого QLIKE.

**C2.** Вес в зависимости от заранее наблюдаемого уровня RV.

**C3.** Вес в зависимости от изменения волатильности.

**C4.** Вес в зависимости от подтверждённых исторических рыночных режимов.

**C5.** Размер residual-коррекции в зависимости от уверенности в ней.

**C6.** Упрощённое переключение HAR/ML при причинно определённом структурном изменении.

Использовать только заранее доступные данные.

Не строить сложную модель переключения, если простое среднее уже работает не хуже.

Каждый новый параметр адаптации повышает риск переобучения и требует отдельного обоснования.

# 3. ПРОВЕРИТЬ ДОПОЛНИТЕЛЬНУЮ ИНФОРМАЦИЮ

Для каждой пары моделей определить:

- корреляцию прогнозов;
- корреляцию ошибок;
- корреляцию разностей QLIKE-loss;
- расхождения при высокой RV;
- расхождения при низкой RV;
- расхождения в стрессовых режимах;
- частоту ситуаций, когда одна модель права, а другая ошибается;
- зависимость этих ситуаций от доступных прошлых признаков.

Проверить, в каких случаях бустинг действительно исправляет HAR.

Отдельно исследовать связь остаточных ошибок HAR с F1–F6.

**Нужно доказать, что второй компонент приносит новую информацию, а не просто увеличивает сложность.**

# 4. ПРОВЕРИТЬ ОБУЧАЮЩУЮ АРХИТЕКТУРУ

Для каждой даты t:

1. Сформировать признаки из информации, доступной на t.
2. Использовать HAR-прогноз, полученный без будущих наблюдений.
3. Использовать прогноз ML, обученный на разрешённом прошлом.
4. Рассчитать веса или residual-коррекцию по данным, уже известным на t.
5. Сформировать итоговый прогноз RV на t+1.
6. Только после наблюдения фактической RV добавить эту ошибку в доступную историю.

Необходима корректная временная вложенность:

**Внешнее окно → исторические OOF-прогнозы → обучение гибрида → прогноз следующего периода.**

Все метапараметры, калибровку, регуляризацию и правила переключения выбирать только внутри прошлой истории.

Не смешивать fitted values базовых моделей с настоящими out-of-fold прогнозами.

Учитывать календарную доступность RV и всех рыночных признаков.

# 5. НЕ ПОВТОРЯТЬ ПРОВЕРЕННЫЕ ОТРИЦАТЕЛЬНЫЕ ГИПОТЕЗЫ

Поэтому основные гибриды строить на действующих сильных базовых моделях.

Не возвращаться к повторному подбору обучающих окон без нового объяснения.

# 10. КАК ВЫБРАТЬ ЛУЧШИЙ ГИБРИД

Не выбирать только по минимальному общему QLIKE.

Использовать следующие критерии:

**A. Точность:** снижение QLIKE относительно лучшей самостоятельной модели.

**B. Временная устойчивость:** отсутствие сильной деградации в отдельных периодах.

**C. Дополнительная информация:** подтверждённый вклад второго компонента.

**D. Статистическая убедительность:** корректные сравнения с учётом всей истории поиска.

**E. Простота:** меньше новых параметров при сопоставимой точности.

**F. Воспроизводимость:** точная реконструкция прогнозов и обучения.

Представить три лучших архитектурных варианта, только если они действительно конкурентоспособны.

Если residual-модели уступают обычному ансамблю, зафиксировать этот результат и оставить более простую конструкцию.

# 12. ФИНАЛЬНОЕ РАСПОРЯЖЕНИЕ

**УТВЕРЖДАЮ ГЛУБОКОЕ ИССЛЕДОВАНИЕ ГИБРИДОВ HAR-J, XGBOOST И LIGHTGBM.**

Не смешивать самостоятельные модели и их гибриды.

Не менять исходные данные и утверждённые результаты.

Не дублировать активную волну E.

Не переобучать GRU, LSTM и GARCH.

Не переходить к другим тикерам до завершения SBER h=1.

Главные приоритеты:

1. Проверить простой ансамбль HAR + XGBoost.
2. Проверить HAR + LightGBM.
3. Проверить вклад объединения XGBoost и LightGBM при корреляции ошибок 0,998.
4. Исследовать residual XGBoost и residual LightGBM.
5. Проверить ограниченную динамическую адаптацию.
6. Сравнить все конструкции на одном временном контракте.
7. Выявить, какая архитектура даёт самостоятельную дополнительную информацию.

**Главный исследовательский результат — определить, можно ли сочетанием устойчивой структуры HAR-J и нелинейного прогнозирования XGBoost/LightGBM достичь более точной и стабильной оценки будущей реализованной волатильности, чем каждой моделью по отдельности.**
