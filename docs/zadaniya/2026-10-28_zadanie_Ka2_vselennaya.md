# Задание kodir — К-а2: вселенная U_d (рычаг (а), Ж-069 п. 3)

## Входы
- **План:** записка `docs/otchety/2026-10-28_rychagi_10_00.md` — раздел (а), строка К-а2.
- **Толкование:** `docs/resheniya/tolkovaniya.md` [Ж-069 п. 3, 28.10 10:22] — порядок выгрузки и правило U_d.
- **Состав IMOEX:** `docs/issledovaniya/2026-10-28_sostav_imoex.csv` (#396). Одна строка на дату, поля `date_eff`, `known_from`, `n`, `tickers` (через пробел), `known_from_status`.
- **Оборот:** `data/regen/V40/daily_value/{T}.csv`, формат `date,value`, 2014–2021, 77 тикеров. Выгружено 28.10 10:24, журнал — `data/regen/V40/sha_journal.csv`.
- **Образец ранга по обороту прошлого года:** `fastbt/likvidnost_e.py` (мутация № 19).

## Цель
1. **`fastbt/vselennaya.py`:**
   - `sostav(d) -> frozenset` — состав IMOEX, действующий на d по `date_eff` (последний `date_eff ≤ d`).
   - `U(d, k=40) -> frozenset` — топ-k тикеров из `sostav(d)` по сумме VALUE за **прошлый календарный год**. Ранг фиксирован на год, ex-ante.
   - `digest()` — хэш файла состава и файлов оборота.
   - Чтение ≥ 2022 — отказ.
   - Тикер без оборота в прошлом году в U не входит; это пишется в отчёт.
2. **Скрипт `scripts/vselennaya_spisok.py`.** Печатает и пишет в `docs/tables/diag/vselennaya_U_2015_2021.csv`:
   - для каждого года 2015–2021 и каждой даты смены состава — |U_d| и список;
   - итог: тикеры, хоть раз попавшие в U_d за 2015–2021, и сколько из них не входят в нынешние 17.

   Это список для шага 3 выгрузки (1-мин и 10-мин). **Выгрузку не запускать.**

## Тест (синтетика)
Мутации, которые обязаны ловиться:
- ранг по обороту **текущего** года (мутация № 19);
- состав по `known_from` вместо `date_eff` — должно быть консервативно по `date_eff`, тест на дату между ними;
- состав 2021 применён к 2016 (из записки);
- тикер вне `sostav(d)` попадает в U.
