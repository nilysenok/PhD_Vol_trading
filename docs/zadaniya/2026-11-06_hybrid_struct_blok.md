# 4. ЭТАП B — HAR AS FEATURES

Создать новый класс моделей, в которых HAR-J не является просто отдельным прогнозом.

Его компоненты используются как структурированные признаки бустинга.

- недельную компоненту RV;

- относительные вклады компонентов;
- отношения короткой RV к длинной;

## B2. HAR-LightGBM

Провести независимое аналогичное исследование LightGBM.

Не копировать механически параметры XGBoost.

## B3. Контроль

Сравнить:

- обычный XGBoost;

Определить, какие именно составляющие HAR полезны.

Не считать большой feature importance доказательством улучшения.

# 5. ЭТАП C — RESIDUAL BOOSTING С КОРРЕКТНОЙ ФУНКЦИЕЙ ПОТЕРЬ

Исследовать гибрид, в котором HAR формирует основной прогноз, а ML корректирует его.

Основная конструкция:

`RV_hybrid = RV_HAR × exp(g(X_t))`

Для неё использовать QLIKE-согласованное обучение.

Обозначить:

`f = RV_HAR × exp(g)`

`L = log(f) + RV_actual/f`

При оптимизации по g аналитические производные:

`gradient = 1 - RV_actual/f`

`hessian = RV_actual/f`

Проверить производные численно и выполнить тесты положительности прогнозов.

Обязателен корректный временной OOF-протокол для HAR.

Не использовать ошибки HAR, рассчитанные по обучающей подгонке, вместо исторических ошибок прогноза.

## C1. Residual XGBoost

HAR-J + нелинейная корректировка XGBoost.

## C2. Residual LightGBM

HAR-J + нелинейная корректировка LightGBM.

## C3. Shrinkage

`RV_hybrid = RV_HAR × exp(lambda × g(X_t))`

Исследовать умеренное ограничение коррекции.

## C4. Контроль без коррекции

При `lambda = 0` модель должна воспроизводить HAR.

Обязательно проверить, превосходит ли такая коррекция использование HAR как обычного признака самостоятельного бустинга.

Не повторять без изменений ранее отклонённые residual-эксперименты. Новая реализация допускается только при документированном архитектурном отличии.

# 6. ЭТАП D — COMPONENT HYBRID

Это отдельное приоритетное направление.

Вместо прогнозирования одной общей поправки к HAR исследовать структуру его отдельных компонентов.

HAR-J учитывает разные горизонты прошлой волатильности и скачки.

Проверить возможность нелинейного уточнения:

- краткосрочной компоненты;
- недельной компоненты;
- долгосрочной компоненты;
- влияния скачков;
- асимметричной реакции на отрицательные доходности.

Не создавать сразу отдельный бустинг для каждой составляющей.

Сначала выполнить простую абляцию.

Если компонент не добавляет информации, исключить его.

Для экономически обоснованных компонентов можно исследовать нелинейные функции:

`g_daily(RV_daily, X_t)`

`g_weekly(RV_weekly, X_t)`

`g_monthly(RV_monthly, X_t)`

`g_jump(Jump_t, X_t)`

После этого сформировать положительный итоговый прогноз в согласованной с QLIKE модели.

Нужно сохранить интерпретируемость структуры и не допускать произвольных отрицательных прогнозов RV.

**Цель — найти конкретную компоненту волатильности, на которой нелинейная модель превосходит линейную спецификацию HAR.**

# 7. ЭТАП E — CONDITIONAL ERROR CORRECTION

Проверить гипотезу, что поправка бустинга полезна не всегда.

Вместо непрерывной корректировки:

`RV_hybrid = RV_HAR × exp(a_t × g(X_t))`

где `a_t` — коэффициент активности коррекции, определяемый исключительно по прошлым данным.

Исследовать простые причинно корректные показатели:

- прошлую RV;
- отношение дневной RV к месячной;
- прошлые ошибки HAR;
- рыночную RV;
- недавние скачки;
- прошлое расхождение HAR и ML.

Проверить три конструкции:

**E1.** Постоянная величина коррекции.

**E2.** Плавная коррекция по одному интерпретируемому показателю.

**E3.** Коррекция по двум показателям, только если E2 даёт устойчивое улучшение.

Не строить сложный переключатель без доказанной необходимости.

Обязательный контроль — самостоятельный XGBoost или LightGBM, а не только HAR.

**Диагностика ошибок → HAR как признаки → QLIKE residual learning → корректировка компонентов HAR → условная коррекция → ограниченный Mixture of Experts → статистическая проверка.**
