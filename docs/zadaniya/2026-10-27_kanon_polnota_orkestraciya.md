## Блок 1

Владелец, 27.10: доработай канон проекта — добавь раздел «Полнота работы». Раздел обязателен для главной сессии и всех агентов, включается в каждое задание агенту целиком. Текст:

**Полнота работы**

A. Гейты до работы.
1. До начала любой нетривиальной задачи агент пишет файл гейтов `GATES.md` в своём рабочем каталоге: список наблюдаемых результатов G1…Gn, у каждого — `CHECK:` (команда, которая проверяет результат), `EXPECT:` (ожидаемый вывод или значение), `EVIDENCE:` (фактический вывод; до запуска — `pending`). Один гейт — один результат. Ручной гейт (без команды) допустим, только если проверку нельзя выразить командой; это пишется явно.
2. Гейты покрывают каждое независимое требование задания. Требование без гейта — повод вернуть задание на уточнение, а не пропустить его.
3. Тривиальные правки и фактические ответы гейтов не требуют.

B. Исполнение.
4. Задание выполняется целиком. Нет заглушек, «TODO», «остальное аналогично», «упрощённой версии». Если часть невозможна — гейт помечается `ABANDON: <id> <причина>`, и это выносится в отчёт первой строкой; удалять или переписывать гейт задним числом нельзя.
5. Файлы читаются полностью; код, который меняется, читается вместе с местами вызова.
6. Любое отступление от задания (сетка, выборка, число повторов, метод, пропущенный шаг) — отдельной строкой «отступление» с причиной, до выводов. Молчаливое упрощение — нарушение.
7. Запреты не обходятся «для скорости»: запрещённые файлы не читаются, замки не снимаются, запрещённые команды не выполняются. Мешает — доложить.
8. Ошибка или странный результат — разбор до причины, не подавление симптома (try/except, фильтр строк, подмена значения).
9. Четыре прохода по результату: (1) сделать полностью; (2) перечитать как эксперт и заменить каждое слабое место; (3) искать дефекты корректности, интеграции, производительности и доказательств — исправить; (4) повторять, пока проход ничего не находит.

C. Доказательства и отчёт.
10. Гейт закрыт, только если команда CHECK выполнена, код возврата 0 и вывод совпал с EXPECT; вывод записан в EVIDENCE. Галочка без вывода = не закрыт. Самооценка «проверил, работает» доказательством не является.
11. Все числа в отчёте перемеряются в момент написания отчёта и берутся из файлов или выполненных команд с указанием источника. Оценки «примерно» допустимы только там, где измерить нельзя, и помечаются отдельно.
12. Отчёт «готово» запрещён, пока есть незакрытые, отложенные или ABANDON-гейты, или вопрос, ждущий решения владельца. Тогда отчёт называется «передача» и начинается с перечня незакрытого.
13. Отчёт пишется для того, кто не видел работы: сделано / не сделано / проверено (какими командами) / отступления / требует решения. Без пересказа задания и общих слов. Реестр гейтов «закрыто N из M» обязателен.
14. Главная сессия перед слиянием сама перезапускает CHECK-команды листа (перепроверка родителем), а не верит отчёту; при расхождении результат возвращается агенту, а не доделывается главной сессией молча.

D. Контекст и разбиение.
15. Большая задача разбивается на листы с собственными гейтами и явным владением файлами; у ветки — интеграционные гейты (совместимость листов, сквозной прогон, регрессии). Разбиение — до распараллеливания.
16. Вопрос владельцу — только если без ответа работа невозможна или необратима; иначе разумное умолчание, записанное явно.
17. При признаках исчерпания контекста (повторное чтение тех же файлов, потеря деталей задания) агент пишет файл передачи и просит замену, а не доделывает «как получится». Занижать оставшийся контекст и сворачивать работу раньше времени — тоже нарушение.

Впиши раздел в канон, подними версию, укажи, какие существующие пункты он дополняет или заменяет, добавь шаблон `GATES.md` в репозиторий и покажи дифф. КОНЕЦ БЛОКА

## Блок 2

Владелец, 27.10: доработай канон — добавь раздел «Оркестрация и дисциплина правок». Текст:

Оркестрация

Контекст агенту передаётся файлами: задание — отдельный файл задания с путями к входам; состояние этапа — файл state/<этап>.md; агент не получает историю диалога и не читает план целиком, только свой раздел. Выход этапа — файл, следующий этап получает путь.
Один агент — одна задача, один результат, одно владение файлами (список путей в задании). Писать вне своего списка запрещено. Параллельно — не более 3–5 агентов; при большом числе элементов — пакеты по 5–10 на агента, не агент на элемент.
Роли разделены: автор реализации не меняет тесты; проверяющий не меняет код (только читает, запускает, пишет отчёт и подложенные ошибки в отдельной копии); главная сессия сливает только после собственного перезапуска проверок.
Ответ агента главной сессии — не длиннее 500 слов: сделано / не сделано / проверено / отступления / решения. Всё остальное — в файл отчёта с путём.
Повторы ограничены: этап с валидатором перезапускается не более 3 раз, затем останавливается с отчётом об ошибке.
Расследование отделено от починки: пока причина не названа и не воспроизведена тестом, правки и коммиты запрещены; гипотезы перечисляются все, проверяются по очереди, отбрасываются явно.
Агент, исчерпавший контекст, заменяется новым через файл передачи; главная сессия не доделывает его работу сама.

Дисциплина правок
8. Сначала план, потом код: для нетривиальной задачи — план с критериями успеха (гейтами) до первой правки.
9. Хирургические правки: меняется только то, что требует задание; несвязанный код, комментарии, форматирование не трогаются; «улучшения по пути» запрещены — они отдельное задание.
10. Простота: предпочитать короткое решение длинному; не добавлять абстракций, флагов, режимов и параметров «на будущее»; мёртвый код удалять, а не оставлять под флагом.
11. Никаких режимов, воспроизводящих исправленные ошибки: старые результаты — в архив с хэшами, эталоны пересчитываются на исправленном коде.
12. Каждое изменение данных, ключей кэша, параметров по умолчанию — отдельный PR с тестом, который падает без правки, и строкой «что изменилось в числах».

Структура канона
13. Главный файл канона — короткий (до 150 строк): роли, запреты, порядок работ, указатели. Подробные правила — отдельными файлами в .claude/rules/ по темам (полнота, оркестрация, данные, тесты, отчёты); задание агенту ссылается на нужные файлы, а не на весь канон.
14. Журнал решений владельца — отдельный файл только для записи (append), с номером и временем каждого блока; главная сессия подтверждает приём блока его номером. Блок без подтверждения считается не дошедшим.

Впиши разделы, разнеси по файлам .claude/rules/, подними версию, покажи дифф и список того, что из старого канона заменено. КОНЕЦ БЛОКА
