## 1. Протокол

Шаг k = 1…10, год оценки vy = 2015 + k. Разработочный набор — шаги 2–6, то есть vy 2017–2021 [Р, «Протокол»]. Данные — `data/regen/features_pit_v3.parquet`, 17 тикеров. Цели: h=1 — RV(t+1), h=5 и h=22 — среднее RV за [t+1, t+h] [Р].

Честный протокол: всё, что используется на шаге t, берётся только из шага t−1 [Р; Ж, № 1].
- **Эмбарго по концу цели.** Строка i с целью [i+1, i+h] входит в обучение, только если i + h меньше номера первой строки vy [Р].
- **LSTM и GRU** (`scripts/analysis/ref_nn_sv.py`).
  - Гиперпараметры, число эпох (лучшая эпоха лучшего испытания) и траектория lr берутся из исследования шага t−1.
  - Модель переобучается на всех строках до vy_t ровно на это число эпох, без взгляда на vy_t.
  - Подбор не урезан: optuna TPE (seed 42), 30 испытаний на (модель, тикер, шаг, h), MedianPruner(5, 10), критерий — val-QLIKE.
  - Пространство: hidden {32, 64, 128}, layers {1, 2}, dropout {0,1; 0,2; 0,3}, lr {3e-4; 1e-3}, seq {22; 44}.
  - batch 32, до 100 эпох, ранняя остановка внутри исследования по val-MSE (patience 10). Модель — по тикеру.
  - Переобучение — seed 42/43/44, прогноз — среднее ln-прогнозов трёх seed.
  - Шаг 1 нужен только для s² шага 2, он считается с фиксированными параметрами диссертации [Р].
- **Поправка Б0.1** у LSTM и GRU — один вариант, объявленный заранее: F = exp(s²/2), s² — дисперсия OOS-остатков года оценки шага t−1 [Р; Ж, № 1].
- **GARCH(1,1) и GJR-GARCH(1,1)** (`scripts/analysis/ref_garch_cal.py`).
  - Доходности close×100, Constant, normal; параметры оцениваются по годам < vy [Р].
  - Калибровка масштаба по тикеру — OLS по логарифмам с единичным наклоном на годе оценки шага t−1. Прогноз шага t — σ²·a·exp(s²/2) [Р].
- **Эталон** — HAR-J с поправкой sm, прогнозы `data/regen/D16_10_harj_h{h}_val.parquet` [Р].
- **Метрики** считаются на общих строках всех моделей: 21 471 строка на модель и h [Р]. Среднее берётся по пяти годам.
  - Финал взят из [Ф]. Эталон HAR-J в [Ф] и в [М] совпадает до 4-го знака на каждом h; это проверяет `scripts/analysis/prilozhenie_spravochnye.py`.

## 4. Снятие прежнего справочного GRU (25.10)

Прежний справочный GRU (`scripts/analysis/gru_sv.py --oos-params`, отчёт [G25]) снят: его протокол нечестный [Р; Ж, № 1].
- **Главное нарушение.** Гиперпараметры брались с шага t−1, но число эпох выбиралось ранней остановкой по самому году оценки, то есть по тому году, на котором потом считалась метрика [G25, «Протокол»; Р].
- **Ещё три отличия от честного протокола** [Ж, № 1]:
  - не было эмбарго: декабрьские цели h=22 заходили в январь года оценки;
  - вариант Б0.1 выбирался из пяти по метрике шагов 2–6;
  - шаг 1 брался из внутривыборочного подбора.
- **Прежние числа** (OOS QLIKE, среднее 2017–2021, h = 1 / 5 / 22): 0,3049 / 0,2273 / 0,2367 [G25, таблица «Цель (4)»]. С округлением до трёх знаков это 0,305 / 0,227 / 0,237 [Р; FD, раздел 5]. На h=22 у прежнего GRU стояла поправка smrob, а не sm [G25].
- **Честные числа** GRU: 0,3345 / 0,3309 / 0,4331 [М].
- **Почему разница так велика.** Без поправки честный GRU хуже прежнего на 12% / 25% / 67% [Р].
  - Лучшая эпоха исследования — шум. Медиана best_ep на шагах 2–6: h=1 — 9 (GRU) и 6 (LSTM); h=5 — 4 и 2,5; h=22 — 2,5 и 2 [Р].
  - Эпоха, лучшая на годе t−1, на годе t даёт недо- или переобученную сеть. Ранняя остановка по году оценки — сильный и нечестный отбор [Р].
  - Отдельной абляции не было [Р].
- **Проверка кода.** Переобучение шага s с параметрами и эпохами исследования того же шага s и seed 42 воспроизводит val-QLIKE лучшего испытания до 6 знаков, на трёх случаях [Р].
- В цели (4) финала прежний GRU заменён честными GRU и LSTM; прежние числа приведены там в скобках как нечестные [FD, раздел 5].

## 5. Детектор утечек

Адаптеры `lstm`, `gru`, `ref_garch` — в `tests/leak/models_ref.py`, самопроверка с внедрённой утечкой — в `tests/leak_selfcheck_ref.py` [Р, «Детектор утечек»].

**GARCH и GJR: 42 из 42 стадий** [Р; Ж, № 2].
- **Утечка в `arch.fix()` найдена и исправлена.** Первый прогон дал 6 из 42: стадия «будущее не влияет» падала на всех датах, расхождение от 1e-16 до 1e-10 [Ж, № 2].
  - Причина: `arch_model(...).fix(params)` считает границы дисперсии (`variance_bounds`) по всей выборке, включая даты после t. Ранние σ² сдвигались на ~1e-11 от данных после t [Р; Ж, № 2].
  - Исправление: своя причинная рекурсия GARCH/GJR с backcast, как в arch. С 2016 года она совпадает с `arch.fix` до 2e-8 относительно, медиана — 7e-16 [Р; Ж, № 2].
  - После исправления 42 из 42. «Будущее не влияет» — побайтно на трёх датах. Перемешанная цель: QLIKE модели 3,3–13,2 против константы 0,68–3,05 [Р].
  - Некалиброванный прогноз совпадает с `garch_sv.py` до 4-го знака QLIKE (GJR h=1: 0,4514) [Ж, № 2].
- Самопроверка (калибровка шага t по году шага t+1) ловится: 4 стадии упали [Р].

**LSTM и GRU: 41 из 42 стадий** [Р; Ж, № 3–4]. Детектор шёл на уменьшенном бюджете: SBER, LKOH, IRAO; 3 испытания; 4 эпохи [Р].
- «Будущее не влияет» — побайтно на всех 36 стадиях [Р].
- Перемешанная цель на h=5 и h=22 пройдена с запасом: QLIKE модели 6,7–10,4 против константы 1,7–3,0 [Р].
- **Стадия «перемешанная цель» у GRU h=1 формально не пройдена:** QLIKE модели 11,03 против константы 11,68. LSTM h=1 прошёл на грани: 11,80 против 11,68 [Р].
  - Разбор по seed перестановки 42 / 1 / 2 / 3 / 4: FAIL / PASS / PASS / PASS / FAIL [Р; лог `data/run/ref_leak_permute_seeds_gru.log`].
  - Оба падения дал IRAO: QLIKE модели по пяти seed у него 28,6–36,9, константы — 20,0–32,7, то есть всё решают несколько дней с экстремальной RV. У LKOH и SBER модель не лучше константы ни при одном seed [Р].
  - С 20 эпохами картина та же. GRU: FAIL 11,03 против 11,68 / PASS / PASS. LSTM: FAIL 11,64 против 11,68 / PASS / PASS. В обоих падениях решает IRAO [Р; логи `data/run/ref_leak_permute_seeds_{gru,lstm}_e20.log`].
  - **Вывод: утечки не найдено.** Падение объясняется шумом константы на тяжёлом хвосте RV(t+1) у IRAO. «Будущее не влияет» побайтно (36 из 36), самопроверка с внедрённой утечкой проходит. Падение стадии записано, а не скрыто [Р].
- Самопроверка с внедрённым признаком «цель строки» (h=22) при 20 эпохах (patience 5): 4 из 4, ловится у обеих сетей. При 4 эпохах LSTM на (б) не ловился [Р; лог `data/run/ref_leak_selfcheck_nn_e20.log`].
