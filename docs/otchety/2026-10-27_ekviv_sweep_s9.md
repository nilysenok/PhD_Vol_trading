# Сверка оценщика перебора с боевым путём s9 (Ж-040 п. 2–3)

Статус: разработка, окна 2018 и 2019, после исправления Ж-038 (`a51cb7a`: двойной знак убран; PR #326/#328). Код `fastbt/` не менялся. Validation 2020–2021 и данные ≥ 2022 не читались (кэш A из s9 обрезан по 2019 сразу при загрузке). В сеть не ходили.

## Итог одной строкой

**Из 20 точек совпали 16 (все, у которых есть боевой эталон), 4 — «нет эталона»; расхождений нет.** Допуск объявлен до счёта (в шапке `tests/test_ekviv_sweep_s9.py` и в `ekviv_20.yaml`): позиции побайтно (0 расходящихся баров на 17 тикерах), дневной PnL `abs ≤ 1e-12`. Факт: точки Sk — max|ΔPnL| = 0 (побитно), позиции — 0 расходящихся баров; точки A — max|ΔPnL| ≤ 9·10⁻¹⁹, разница Шарпа ≤ 9·10⁻¹⁶. Мутация «двойной знак» ловится на всех шести точках (б) и не затрагивает центры (а).

## Что сверялось

* **Оценщик:** `SkEvaluator.pnl` (`sweep_sk` → `sweep_post.build_view/positions` → `_Mini.port`) в точке на всех 17 тикерах (по 6 стратегий — 102 пары в точках A).
* **Боевой путь Sk** (`fastbt/ekviv_s9.py`, только боевые функции, ничего не менялось): `get_family(sid).generate` → `Unit` → `Unit._build_rm` на строке RM точки → `ApproachA.raw_pos` (`trades_one` + `pos_from_trades`) → `execlayer.exec_layer` **всегда** (A вызывает его и при тривиальных параметрах; оценщик тогда его пропускает) → `turnover.tfilter` → `s9.Engine.port`. `sweep_post`/`sweep_sk` в этом пути не вызываются.
* **Точки A:** позиции боевой A из кэша s9 (`cache_latest_v2`): `Engine.port` против `sweep_a_core.assemble` (веса равные, лимитов нет) на тех же позициях.
* **Окна:** 2018 = `end` 2019-01-01 (год один); 2019 = `end` 2020-01-01, срез 2019 (в движке s9 окно `YEARS=(2018, 2019)`). Комиссии 0,04 % и 0,035 %. Для A: 2018 в окне 2018–2019 = −2,7113 (совпадает с `A_yakor_sverka.csv`, строка s9_A_boevaya); в таблице ниже — окно одного года (2018 — отдельно: −2,7042), потому что так считает `Sweep` (tune2018 = `end` 2019-01-01).

## Класс «нет эталона» (не подменён, в зачёт «совпало» не идёт)

| точка | причина |

| S3_v | `trail_n=60` вне `unit.TREND_TN` — боевой Unit строит RM только по списку |
| S4_v | `rm_edinitsa=sqrt_rv` — выходов в √RV в s9 нет |
| S5_v | `vf_porog=0.75` — маска после кэша сигналов (ужесточение зашитого 0,5), в боевом пути нет |
| S6_v | `rm_tip=sqrt_rv` — выходов в √RV в s9 нет (также `vyhod_dev`=0,75 и `vf_porog`=0,75 — надстройки оценщика после кэша) |

Следствие: **четыре из шести реально лучших кандидатов S{k}_top3 (S3–S6) боевым движком воспроизвести нельзя**; сверка доказывает эквивалентность пути, а не значений этих кандидатов. Закрыть можно только ближайшими точками на боевых сетках либо вводом этих надстроек (маски, √RV, `trail_n` вне списка) в боевой путь отдельным решением владельца — ❓.

## Границы сверки (честная половина)

1. Сигнал строит одна и та же функция (`get_family(sid).generate`): у A она же внутри `sigprov`; независимость проверена для RM, сделок, исполнения, фильтра оборота и счёта.
2. Это одна стратегия в одной точке; ансамбль A (топ-10, голосование, выбор `turnover.apply`) не сверялся — только `assemble` против `Engine.port` на готовых позициях A.
3. Маски в центре (`adx_min`=20, `vf_porog`=0,5, `vol_regime_max`=1,2, `svechi_min_iz5`=3, `obyom_mnozh_sma20`=1, `vyhod_dev`=0,5) равны зашитым порогам, поэтому у центров эталон есть; совпадение центров подтверждает, что эти маски — тождественное преобразование.
4. Окна 2018 и 2019 — разработка; вывод про остальные годы не делается.

## П. 3 Ж-040: какие стратегии и параметры шли через ошибочный путь

Ошибочный путь — `sweep_post.py:160–162` до `a51cb7a`: слой исполнения включался при `consec_entry > 1`, `exec_min_hold > 0`, `exec_cooldown > 0` или `min_strength > 0`, и результат `exec_layer` (он уже со знаком) умножался на знак сырой позиции ещё раз — шорты становились лонгами. Таблица — `docs/tables/sweep_e1v2/oshibochny_put.csv` (24 строки: стратегия × параметр, значения сетки, включавшие путь, значения из сетки A, включён ли в центре).

**Центр сетки путь не включал ни у одной стратегии** (все четыре параметра исходно тривиальны: 1 / 0,0 / 0 / 0), поэтому якорь A_ishodnaya и OAT по остальным параметрам затронуты не были. Затронуты только те точки, где хотя бы один из четырёх параметров ≠ 0 / > 1.

Эти результаты (Optuna, кандидаты S3–S6, сборки на них) — в перечне «недействительны: ошибка оценщика» по п. 1 Ж-040.
