## Процедуры
- **HAR-J** — как в диссертации: 8 предикторов (rv_d, rv_w, rv_m, jump, jump_annualized, jump_lag1/5/22), МНК в логах, одна модель на все тикеры, прогноз exp(ŷ). Код повторяет `gibrid_har.har_forecasts`. **Б0.1**: F = exp(s²/2), где s² — дисперсия остатков ln на val 2018, своя для каждой компоненты (оценка ord). F = 1,30 / 1,20 / 1,15 для HAR-J (h = 1 / 5 / 22).
- **XGBoost / LightGBM (gbdt)** — протокол B v2b (`tune_Bv2.py --max-bin 255`) с одним шагом:
  - сетка: ЛГК seed 42 с расширенными диапазонами из `tune_Bv2.py`; LightGBM — 100 точек, XGBoost — 40 точек и по правилу бюджета ещё 100;
  - подбор на 50% строк обучения, стратифицированных по тикеру и году;
  - отсечение на 100-м дереве;
  - ранняя остановка по l2 на val 2018: patience 30 (действующее решение владельца, протокол B v2, 25.10, 18:15/18:30: «ранняя остановка … patience 30»; 50 было в прежней версии B), не больше 1000 деревьев, max_bin 255;
  - выбор точки — по val-QLIKE; финальная модель — на всех строках обучения, seed 42.
  - Правило бюджета сработало на всех h: XGB-40 занял 1-е место из 140, поэтому XGBoost получил ЛГК-100.
  - Выбранные точки: LGBM 55 / 43 / 60, XGB 101 / 14 / 7.
- **Гибрид V1–V7** — `gibrid_schemes` «как в коде»: смешивание по RV, V7 с окном 20 и лагом h. Веса подобраны на val 2018, схема — минимум val-QLIKE.
  - Один шаг, поэтому V2 = V3 (нет предыдущего валидационного года, режим NORMAL).
  - Выбранные схемы: h=1 — V1 (LGB, w_HAR = 0,14), h=5 — V2/V3 (0,12 / 0,38 / 0,50), h=22 — V1 (LGB, w_HAR = 0,27).
  - Вариант с Б0.1: поправка ко всем компонентам; на валидации — в выборке, потому что шаг один.
- **LSTM/GRU** — табл. 2.7: hidden 64, 2 слоя, dropout 0,2, последовательность 22 дня, batch 32, Adam 1e-3, до 100 эпох, ранняя остановка с patience 10 (лучшие веса). У LSTM — ReduceLROnPlateau и clip 1,0, у GRU их нет.
  - 21 признак — список из `04_train_neural.py`.
  - Отдельная модель на тикер × h. Цель — ln RV, стандартизация по обучению.
  - Последовательность строки t — признаки дней t−21…t (всё, что известно к 18:50 дня t).
  - Ранняя остановка срабатывала на 11–34 эпохе. torch 2.8.0.
- **GARCH(1,1) / GJR-GARCH(1,1)** (`arch` 7.2.0) — по тикеру, на дневных лог-доходностях close ×100.
  - Параметры оценены по ≤ 2017; на 2018–2019 модель фильтрует с теми же параметрами.
  - Прогноз на h — среднее ожидаемых σ² за [t+1, t+h].
  - Основная строка — σ² без масштабирования, как в коде. Справочная — с множителем mean(RV)/mean(σ²) на обучении; она хуже.
  - Старый `train_garch.py` давал один прогноз на весь год (константу), здесь его не повторяли.
- **Метрики** — как в `final_test.py`: QLIKE; RMSE и MAE на уровне RV (не в логах).
- **DM**: d = L_HAR − L_модель, t > 0 — модель лучше. Три способа: номинальный (пул без HAC); NW с лагом h−1 на пуле; основной — дневной ряд средней по тикерам разности потерь (252 дня), NW с лагом h−1.

## Что изменилось и почему (по строке на пункт)
- h=5/22: QLIKE всех моделей примерно в 2 раза ниже старых, потому что цель — среднее RV за h дней (сглаженная), а не RV дня t+h. Сравнивать со старыми можно только ранги, не уровни.
- Ранги: на h=1 картина прежняя (гибрид ≈ лучший бустинг < HAR-J), но лидер среди бустингов поменялся (LightGBM 0,277, XGBoost 0,299). На h=5/22 преимущество бустинга и гибрида над HAR-J исчезло (разница не значима), впереди GRU.
- XGBoost h=1: на 50% строк лучшая точка дала val-QLIKE 0,355 при 16 деревьях. Финал на всех строках остановился на 18 деревьях с val-QLIKE 0,411. Протокол B (подбор на половине, финал на всех строках, ранняя остановка по l2) здесь даёт недообученную модель. Тест для её «починки» не использовался. Наблюдение оставлено для разбора на финальной сборке.
- Б0.1: s² берётся по val 2018 (год апрельских санкций, остатки большие), множитель 1,15–1,30, и на тесте 2019 он завышает прогноз. На валидации, в выборке, поправка гибриду помогала (h=1: 0,334 против 0,361) — классическая подгонка на один год.
- LSTM/GRU стали заметно лучше старых: последовательность включает день t, а не обрывается на t−1, как в `04_train_neural.py`; модель обучается без валидационного года, с ранней остановкой по val 2018.
- GJR-GARCH на h=1 совпал со старым числом 0,501 случайно, процедура другая. Масштабирование по среднему ухудшает QLIKE, поэтому основная строка — без него.
- Старые файлы `moex_volatility/data/predictions/test_2019/` воспроизводят числа диссертации (har/xgboost/lightgbm/hybrid/lstm/gru — до третьего знака). `garch_h*` — нет (1,80 / 1,05 / 0,73): строка GJR-GARCH 0,501 в тексте взята из другого источника.
