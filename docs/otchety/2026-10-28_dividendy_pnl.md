# Дивиденды в PnL — расследование (Ж-054 п. 2)

Статус: разработка 2018–2019 (train), до аудита; правок кода нет. Ветка `rassl-dividendy-pnl`. Даты дивидендов — dohod.ru, не сверены (`docs/issledovaniya/2026-10-27_dividendy_2017_2021.csv`), поэтому все числа ниже — **потолок**.

## 1. Механизм: дивиденды не учитываются (да, дефект)
- Цены — сырые закрытия ряда 18:50, без поправки на дивиденды: `fastbt/daily_1850.py:49` (`close = last` бара < 18:50), нет ни одной операции с дивидендом.
- Доходность строки: `fastbt/data.py:98` `lr[:-1] = log(c[1:]/c[:-1])`; в `fastbt/etap1.py:65` то же. `data/corporate_actions.csv` — применяются только сплиты/консолидации (`status=applied`), дивидендные гэпы — `question`, не применяются.
- PnL: `fastbt/s9.py:578` `net = pos * self.lr_row - sides * comm` (и `:588–589` с весами). `exec_e.py` (ряд `lr` из того же `TickerData`) и `bars5m.py` (бары без корректировок) дивидендов не содержат; grep по `fastbt/*.py` находит слово «дивиденд» только в `etap1_eval.py:36` и `sobytiya_e1.py` (ось событий E1, не PnL; сама ось выключена: даты не сверены, ❓5).
- Следствие: в день отсечки цена падает на D. Лонг через отсечку теряет D (должен получить обратно, PnL = 0), шорт «зарабатывает» D (должен заплатить, PnL = 0). Дивиденд ни разу не начисляется и не списывается.

## 2. Тест
`tests/test_dividendy_pnl.py` (синтетика, `s9.Engine.port` на минимальном движке, comm = 0): лонг и шорт через отсечку при падении цены на 5 % — `xfail(strict=True)`, движок даёт ∓log(0,95) = ∓5,13 % вместо 0. Контроль оракула: если вход несёт дивиденд (`lr += log(1 + D/c)`), движок даёт 0 для обоих знаков (проходит). Мутация: поправка с обратным знаком не обнуляет PnL (проходит, т.е. оракул её ловит). Фиксация механизма: в `corporate_actions.csv` нет применяемых дивидендов. Итог: `4 passed, 2 xfailed`.

## 3. Влияние на train 2018–2019 («A только Sk», боевой s9, σ v2, 0,04 %) — потолок
Метод: ряд A (`eng.A_row`) срезан по семье (`shag0.keep_sids`), как `zh043_lib.main_rows`; Шарп без поправки совпал с `bazy_sverka.csv` (S1 2018 −0,4942, 2019 −2,7759). Строка, держащая позицию на закрытии `last_cum_date` (последний бар ≤ даты), пересекает отсечку; поправка к `lr` строки `log(1 + D/c_след)`, знак даёт позиция (лонг +, шорт −). Учтено 52 из 54 событий 2018–2019 (MGNT, MTSS — пропущены: нет цены/бара в ряду; причина не разбиралась). Поправка = сумма по дням за год (% капитала), `eng.port` с поправленным `lr_row` даёт ту же разность (проверено на S1). Сырые цифры — `scratchpad/ocenka.csv` (исходник утерян 28.10, отчёт поглощён #370).

Честной половины нет: оценка не подбор, но 2018–2019 единственные годы; это потолок размера, не результат.

## 4. Предложение правки (не выполнено)
