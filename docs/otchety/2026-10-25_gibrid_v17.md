# Гибрид V1-V7: параметризованная сборка (проверка на П1)

Слепой тест: метрик на тестовых годах нет; все цифры ниже — валидационные годы шагов (шаг k = val-год 2015+k). Boost = П1 (LightGBM gbdt + ES) + XGBoost.

## 1. Процедура (файл:строка в `moex_volatility/scripts/`)
Шаги, пул, val = последний год обучающего окна — как `walk_forward_full.py:133-205`. Схема на шаге и h выбирается по наименьшему val-QLIKE среди V1-V7 (`gibrid_designs.select`, режим step).
- HAR-J: пересчёт `walk_forward_full.py:61-100,193-205` (`gibrid_har.py`).
- V1: `walk_forward_full.py:258-290` (w_HAR in [0;0,60], шаг 0,01, при w=0 inverse-QLIKE) + выбор лучшей ML по val-QLIKE (`walk_forward_adaptive.py:270-273`, а не фиксированный `best_ml` из `walk_forward_full.py:118`).
- V2-V5: **не в `walk_forward_adaptive_v3.py`**, а в `walk_forward_adaptive_v2.py`: сетка 3 компонент (`:53-67`, w_HAR<=0,6, шаг 0,02); V2 — среднее весов двух val-лет (`:126-158`); V3 — режим по отношению среднего RV val-года к среднему за все годы до тестового (>1,3 / <0,7), HAR-вес x1,5 (<=0,6) или x0,7 (>=0,05) (`:204-261`); V4 — сжатие к 1/3, lambda=0,3 (`:293,337`); V5 — веса V2, затем режим, затем сжатие (`:394-457`).
- V6_TrimmedW: `walk_forward_adaptive_v3.py:107-123`; V7: `:177-223`, окно 20, по тикерам (`gibrid_schemes.v7`).
- Откуда прогнозы прошлых периодов (без заглядывания вперёд): val-прогнозы шага k — модель шага k на val-годе; V2 берёт ещё val-прогнозы шага k-1 (год k-1); история для режима — val-годы шагов 1..k; V7 для val идёт по склеенному ряду val шагов 1..9 (каждая строка использует только строки раньше неё), для теста — по склеенному ряду test-прогнозов шагов (прошлые тестовые годы известны к началу следующего).

## 2. Расхождения код / текст
1. V2-V5 лежат в `adaptive_v2.py`, не в `adaptive_v3.py`; V1_Adaptive из `adaptive.py` берёт веса на **тестовых** прогнозах года k-1 (модель шага k-1), а в `walk_forward_full.py` — на val-прогнозах шага k (модель шага k). Взято второе (по заданию).
2. V1 в `adaptive.py:295` клипует w в [0,05; 0,55], в `walk_forward_full.py` — нет. Клипа нет (по заданию).
3. V3 в диссертации — «режимный выбор»; в коде — мультипликативная правка HAR-веса (x1,5 / x0,7). V5 в коде = V2+режим+сжатие, а не V3+V4. V4 — lambda=0,3 фиксирована.
4. V6_TrimmedW: у медианной модели dev=0, зажато в 1e-8, вес ~1e8 — фактически прогноз = медиана трёх моделей, а не «inverse-deviation двух оставшихся». Воспроизведено как в коде.
5. V7: окно использует loss до i-1 включительно, но rv_actual дня i-1 при h>1 содержит будущие дни (look-ahead h-1 дней в самом коде). Опция `--v7-lag h` убирает; по умолчанию lag=1 (как в коде).
6. В коде V2-V5 в 2017 нет val-года (равные веса); у нас val 2016 есть, поэтому на шаге 1 V2 использует один год.
7. Val-QLIKE схем с подбором весов (V1-V5) оптимистичен: веса подогнаны на том же val-году; V6/V7 без параметров. Выбор по такому QLIKE смещён в пользу V1-V5 — аргумент за режим minimax и критерии c1-c4.

## 4. Дизайны и критерии владельца (c1-c4; только валидация)
Критерии: c1 гибрид < HAR-J в каждом val-году; c2 не хуже лучшей одиночной более чем на 2%; c3 худший год гибрид/HAR-J лучше худшего года XGB и LGB; c4 скачок весов между соседними шагами <= 0,3. Для P1 есть только «одна точка» (ансамбль топ-5 и 3 seed — на B). Победителя среди прошедших все четыре нет: **ни один дизайн P1 не проходит**. c4 не проходит нигде (скачки весов компонент до 0,3-0,8 из-за переключения схем V3/V1/V7); при h=5, 22 нет и c1 (гибрид хуже HAR-J в отдельных годах: h=5 — 2020 (1,06), h=22 — 2016 (1,01)).
