# Гибрид V1-V7: параметризованная сборка (проверка на П1)

Слепой тест: метрик на тестовых годах нет; все цифры - валидационные годы шагов (шаг k = val-год 2015+k). Boost = П1 (LightGBM gbdt + ES) + XGBoost. Версия после решений владельца 25.10 (V7 без заглядывания, c4 для V1, Б0.1 только oos, V0, правило выбора).

## 1. Процедура (файл:строка в `moex_volatility/scripts/`)
Шаги, пул, val = последний год обучающего окна - как `walk_forward_full.py:133-205`. На шаге и h схема выбирается по наименьшему val-QLIKE среди V1-V7 (`gibrid_designs.select`, режим step) либо по минимаксу (минимум худшего val-года среди лет, доступных к шагу).
- HAR-J: пересчёт `walk_forward_full.py:61-100,193-205` (`gibrid_har.py`).
- V1: `walk_forward_full.py:258-290` (w_HAR in [0;0,60], шаг 0,01, при w=0 inverse-QLIKE) + выбор лучшей ML по val-QLIKE (`walk_forward_adaptive.py:270-273`; в `walk_forward_full.py:118` ML фиксирована).
- V2-V5: `walk_forward_adaptive_v2.py` (не v3): сетка 3 компонент (`:53-67`, w_HAR<=0,6, шаг 0,02); V2 - среднее весов двух val-лет (`:126-158`); V3 - режим по отношению среднего RV val-года к среднему за годы до тестового (>1,3 / <0,7), HAR-вес x1,5 (<=0,6) или x0,7 (>=0,05) (`:204-261`); V4 - сжатие к 1/3, lambda=0,3 (`:293,337`); V5 - веса V2, затем режим, затем сжатие (`:394-457`).
- V6_TrimmedW: `walk_forward_adaptive_v3.py:107-123`; V7: `:177-223`, окно 20, по тикерам (`gibrid_schemes.v7`).
- V0 (решение 25.10): одна компонента с поправкой (HAR-J / XGBoost / LightGBM) - самостоятельный кандидат на каждом h.
- Прогнозы прошлых периодов (без заглядывания вперёд): val-прогнозы шага k - модель шага k на val-годе; V2 берёт ещё val шага k-1; история для режима - val-годы шагов 1..k; V7 для val идёт по склеенному ряду val шагов 1..9 (строка использует только более ранние), для теста - по склеенному ряду test-прогнозов.
- V7 без заглядывания - основной (`--v7-lag h`, по умолчанию): потери окна берутся с лагом h дней. `--v7-lag 1` воспроизводит код.

## 2. Расхождения код / текст
1. V2-V5 лежат в `adaptive_v2.py`, не в `adaptive_v3.py`; V1_Adaptive из `adaptive.py` настраивает веса на тестовых прогнозах года k-1 (модель шага k-1), `walk_forward_full.py` - на val-прогнозах шага k. Взято второе.
2. V1 в `adaptive.py:295` клипует w в [0,05; 0,55], в `walk_forward_full.py` - нет. Клипа нет.
3. V3 в диссертации - «режимный выбор»; в коде - мультипликативная правка HAR-веса. V5 в коде = V2+режим+сжатие, а не V3+V4. V4 - lambda=0,3 фиксирована.
4. V6_TrimmedW: у медианной модели dev=0, зажато в 1e-8, вес ~1e8 - прогноз практически равен медиане трёх моделей, а не «inverse-deviation двух оставшихся». Воспроизведено как в коде.
5. V7 в коде при h>1 использует потери дня i-1, чья цель (среднее RV на h вперёд) частично лежит в будущем. Исходные числа V7 для h=5 и h=22 могли пользоваться этим заглядыванием. Сравнение:

|---|---|---|---|
| 1 | 0.373 | 0.373 | [] / [] |
| 5 | 0.776 | 0.765 | [] / [2, 4, 9] |
| 22 | 0.911 | 0.901 | [8] / [1, 2, 4, 5, 8, 9] |

6. В коде V2-V5 в 2017 нет val-года (равные веса); у нас val 2016 есть, шаг 1 использует один год.
7. Val-QLIKE схем с подбором весов (V1-V5) оптимистичен: веса подогнаны на том же val-году; V6/V7 без параметров.

## 4. Критерии, набор дизайнов и правило выбора
c1 гибрид < HAR-J в каждом val-году (строго); c2 не хуже лучшей одиночной более чем на 2%; c3 худший год гибрид/HAR-J лучше худшего года XGB и LGB; c4: скачок весов <= 0,3 между соседними шагами, где обе схемы непрерывные (не V1); для V1 - не более 3 смен ML-компоненты из 9. Критерии 1-3 жёсткие. Критерии 1-2 считаются относительно моделей с той же поправкой, что и дизайн (с поправкой - HAR-J и одиночные с поправкой; `bez` - без поправки).

Правило выбора (25.10, зафиксировано до B): на каждом h выбирается дизайн с наименьшим числом нарушенных критериев, при равенстве - с минимальным средним val-QLIKE. Набор: бустинг (на П1 только «одна точка») x выбор схемы (step / minimax) x {без поправки, Б0.1 oos} плюс V0.
