## Дополнения по оговоркам проверяющего (#292, Ж-029)
1. **Fail-closed.** Если `zamki.json` нет или он битый, JSON события битый или хук упал с исключением, PreToolUse отказывает с кодом 2 и сообщением «хук не смог проверить — отказ». Так происходит для Edit/Write/MultiEdit/NotebookEdit и для Bash с признаками опасного: `>`, `<<`, `rm/mv/cp/ln/dd/tee/sed/perl/awk/eval/push/reset/clean/checkout/restore`, `sh -c`, `python -c/-`, закрытые пути. Чтение и прочие события получают код 0, а сбой пишется в `audit.jsonl` (`"sobytie": "sboy_huka"`). Сценарии Z01–Z13.
2. **`docs/resheniya/resheniya.md` — только дописывание.** Edit/Write/MultiEdit проходят через `proverit(old, new)` из `scripts/kanon/proverka_append.py`. Если модуля нет, срабатывает fail-closed. Шелл-запись в файл и `git checkout/restore` на нём запрещены. Список файлов — ключ `tolko_dopisyvanie` в `zamki.json`. Сценарии D01–D07.
3. **Обход через интерпретатор закрыт.** Закрыты: `bash/sh/zsh -c`, `bash <<EOF`, `eval`, `find -exec`, а также `$(…)` и обратные кавычки внутри кавычек — внутренняя команда проверяется теми же правилами, глубина до 3. Для `python -c` и `python - <<EOF` код проверяется на запись: `open(…,'w'/'a'/'x')`, `write_text`, `to_csv/parquet`, `os./shutil.` удаление и перенос, `subprocess`, `os.system`. Сценарии B01–B16. **Известные дыры** (хук не разбирает содержимое): `python3 script.py`, `bash script.sh`, `make` — любой скрипт может писать (для fastbt есть правило `FASTBT_MAIN`); `perl -e`, `ruby -e`, `node -e` (последний закрыт правом); `awk` с `print > "f"` внутри программы; `sed` с командой `w`; `git apply` и `patch`; `cp`/`mv` поверх своих незамороженных файлов; команда через переменную (`c=sed; $c -i f`); `base64 -d | sh`; `$(…)` с вложенными скобками.
4. **`progon.py` самодостаточен.** Он сам собирает временную копию из заглушек (без git и данных) с фиктивным `.git/HEAD`, кладёт в неё хук, `zamki.json` и `proverka_append.py` и после прогона удаляет её. От `tests/test_huk_demo.py` и настоящего worktree он не зависит. Запуск: `python3 .claude/hooks/progon.py [--papka DIR] [--ostavit]`.
5. **Попутно.** SessionStart читает журнал `docs/resheniya/resheniya.md` (ключ `zhurnal`). Ссылки на правила переведены на `orkestratsiya.md`. Проверка путей пропускает команды, выдающие только имена: `ls`, `du`, `find` без `-exec`, `git log`/`ls-files`/`status`, `git diff/show --stat`. Слово с пробелами и аргументы `echo` за путь не считаются. Иначе `echo "… test_locked/ …"` и `git diff --stat -- docs/tables/strat_test` блокировались ложно.
6. **Остаются блокировки в `t2.py` проверяющего (намеренно).** Из чужой копии `pg/prov` блокируются `python3 scripts/analysis/s9_shag4.py` без `FASTBT_MAIN` (ошибка ET2) и `git push origin HEAD:kanon-v22-pereschet` (в общую ветку сливает только главная сессия через PR). ❓ Если дирижёр сливает из отдельной копии, а не из основной, нужно исключение по пути копии (для дирижёра). Умолчание — оставить запрет; срок — сутки.
