## 4. Быстрый слой (новые модули; старый путь не тронут)

- `fastbt/fast_signals.py` — A (с фильтром оборота и без) один раз на тикер × стратегию; C основного дизайна — на тикер × стратегию × σ. Ключ — хэш входов (`TickerData.digest`, yaml, область, байты σ) и кода (fastbt без модулей таблиц и fast_*, плюс исходник `s9._job`). Кэш в памяти процесса и на диске (`data/fastbt/fs_cache/`). Тикеры считаются параллельно (spawn, ≤ 4 процесса по 1 потоку). Новый σ-источник A не пересчитывает. Если изменился `s9._job`, слой переходит на запасной путь — сам `s9._job`.
- `fastbt/fast_sigma.py` — ранги σ для окон {126, 252, 504}, ранги EMA 3/5/10 на {126, 252}, медианы {22, 126, 252}, ранг σ / медиана 22 дней (для раунда владельца). Всё считается одним numba-проходом (prange по тикерам), кэш — по содержимому ряда. ≡ Ранг считается по окну [t−W, t−1] без текущего дня, как `s9_stats.past_rank`, побитно. Проверено тестом с подложенной ошибкой (вариант «с текущим днём» ловится). До Н1 маски C основного дизайна считали ранг с текущим днём (pandas `rolling.rank`); теперь всё без текущего дня (#238, #246).
- `fastbt/fast_grid.py` — выбор по валидации для всей семьи одним numba-ядром `grid_val_sharpe` (все точки × 408 пар-лет; маски, веса, частичная экспозиция 0,5). Арифметика та же, что у `masked_eval` / `scaled_eval`. Подмена горячих функций — `patched()`; таблицы строит тот же `s9.run_all_experiments`, поэтому правки СC (`--c-dop`) и FA работают сразу. - `fastbt/fast_boot.py` — IID: индексы повторов строятся один раз; numba повторяет попарную сумму numpy (побитно при n ≤ 8192); кэш Шарпов повторов по ряду, эталон A считается один раз на сетку. ЛВ: те же старты блоков, повторы в numba.
