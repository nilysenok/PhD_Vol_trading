## 1. Контракт строки ledger — формат `etap1-ledger`, `"v": "2.0"`

Листы стартуют от этого раздела. Изменение раздела — новая версия формата (`"v": "2.1"`), а не правка на месте.

### 1.1 Ключ строки (Д5)

Ключ — словарь `klyuch`. В нём все оси точки после `canon_v2` (§1.3), плюс `period`, `komissiya` и `fdr`. Значения — строки-токены:
- `tok(v) = v` для строк (`"net"`, `"rv22"`, `"bars5m"`);
- `repr(float(v))` для чисел: `1` → `"1.0"`, `1.67` → `"1.67"`, τ = 5 → `"5.0"`.

Каноническая запись — `json.dumps(klyuch, sort_keys=True, ensure_ascii=False, separators=(",", ":"))`.

`klyuch_sha = sha256(канон_json + "|" + kod + "|" + vhody + "|2.0").hexdigest()`, где:
- `kod` — `cache.code_hash()`;
- `vhody` — `E1Inputs.digest()`.

Две строки с одинаковым `klyuch`, но разным `kod` или `vhody`, — **разные** строки. В одну матрицу они не попадают: §1.6, проверка читателя.

| поле ключа | значения (порядок = соседство) | умолчание (= путь v1.0 побайтно) | откуда |
|---|---|---|---|
| сигнальные оси Sk | как `zh047_S{k}.yaml` `signal` | `ishodnoe` | `zh047_S{k}.yaml` |
| `q_sily`, `sigma`, `vhod`, `k_s`, `R`, `k_tr`, `bezubytok`, `tau`, `proverka`, `razmer`, `rezhim` | как `zh047_S{k}.yaml` `obshchie` | `yakor` | там же |
| `ed_lim` — единица смещения лимита | `sigma`, `atr14`, `diap`, `pct` | `sigma` | новая (Л-2, Л-3) |

| `lestnica` — вторая половина заявки | `net`, `0.5`, `1.0` (½ на k, ½ на k + x·u) | `net` | новая (Л-3) |

| `filtr` — фильтр входа, одна ось (заменяет `sobytiya`) | `net`, `cbr`, `div`, `post_shok`, `szhatie`, `rv_perevorot`, `obyom`, `rel_sila_imoex`, `sektor_trend` | `net` | новая (Л-4); `net`/`cbr`/`div` = прежние `sobytiya` |

| `fdr` | `"null"`, `"t0"`, `"t1"` | `"null"` | контракт #376 |

Зафиксировано вне куба, но в ключе ради полноты:
- `vyhod = "net"`;
- `sobytiya` нет — его роль играет `filtr`. Перевод старой точки: `sobytiya=net|cbr|div` → `filtr` с тем же значением; `cbr_div` в v2 не переносится.

Смысл новых осей. Буква u — единица `ed_lim` дня сигнала d, доля цены:
- `sigma` — σ̂_d выбранного источника;
- `atr14` — ATR14_d / c_d, дневные Н6 по d включительно;
- `diap` — (h_d − l_d) / c_d;
- `pct` — 0,01.

Лимит входа: L = c_d · (1 − sd · k · u_d). Стоп, тейк, трейл и размер считаются по σ̂, как сейчас. Единица u меняет **только** лимит входа (и лестницу).

Ось `zhizn`: заявка исполняется только на барах b < N дня d+1. `den` — весь день, как сейчас.

Ось `gap`, значение `propusk`: если open первого бара d+1 уже за уровнем (лонг: o₀ ≤ L − tick), заявка снимается без исполнения и сделки нет. `vhod` — исполнить по open, как сейчас.

Ось `t_vyhod` — исполнение выхода, решённого на close дня x:
- `close` — close Н6 дня x, как сейчас; открытый вопрос класса A — инвентаризация, п. 8 № 6;
- `1500` и `1700` — цена close 5-мин. бара, который кончается в 15:00 или 17:00:
  - у выхода по τ — того же дня x: момент известен заранее;
  - у выхода по сигналу — дня x+1: сигнал известен только на close x (Д2);
- `open2` — open первого бара дня x+1.

Комиссия выхода — в строке начала интервала исполнения, как у внутридневных выходов (`_row(…, at_close=False)`).

Ось `storona`:
- `long` — шорт-сигналы обнуляются;
- `short_shag1` — лонги из точки, шорт — из той же точки со сдвигом пороговой оси на 1 шаг строже. Пороговые оси: S1 `z_entry`, S2 `bb_std`, S3 `dc_window`, S4 `multiplier`, S6 `dev_mult`. На краю сетки шаг наружу не делается — шорт берётся на крайнем значении, флаг `kray`. У S5 пороговой оси нет: `short_shag1` → `obe` в `canon_v2`.

Ось `lestnica`: две независимые половины с весом w/2 и лимитами k и k + x. Выходы у каждой половины свои, от своей цены входа. Строки g, sides, expo складываются: `run_e1` линеен по весу.

Правила полей.
- **Годы и кварталы.** Ключи — строки. Квартал — календарный, по дате строки портфеля: строка t относится к кварталу даты t. Шарп квартала — по дням квартала, как `by_year`, но на его ~63 днях. Квартал с нулевым σ даёт SR = 0 (`sr_dnevnoy`). Нет дней — `nan`.
- **Целевая.** `mediana_kv` — `numpy.median` 16 значений; если среди них есть `nan`, целевая — `nan`. `dolya_pol_kv` = #(SR > 0) / 16.
- **Строка `ne_schitana`.** Это, например, `filtr = div` без сверенных дат на 2016. В ней все метрики `nan`, поле `excess` равно `null`. В N она не входит, в реестр пишется (§7).
- **mSR** остаётся полем отчёта. Отбор по mSR не идёт (Ж-078).
- **Без метрик 2020+.** Поля с годом вне 2016–2019 — ошибка читателя.

### 1.3 `canon_v2(pt) -> pt` — схлопывание неразличимых точек (в N — один раз)

1. `k_s = net` → `R = k_tr = bezubytok = net`. Прежний `canon` схлопывал только R; k_tr и безубыток без стопа ни на что не влияют (`exec_e_rules.stop_level`).
2. `k_s ≠ net` → `k_x = net`. Тейк задаёт R.
3. `vhod = rynok` → `ed_lim = sigma`, `zhizn = den`, `lestnica = net`, `gap = vhod`. Лимитной заявки нет.
4. `sid = S5` → `storona: short_shag1 → obe`.
5. Других правил нет. Например, σ влияет на вход и при `vhod = rynok`: `_decide` не входит при nan σ.

Тест: две точки, различные после `canon_v2`, дают разный `klyuch_sha` — и наоборот (§1.7, М-L1).

### 1.4 Ряды `excess` (Ж-078: по тикерам, float32)

Каталог ledger: `docs/tables/progon_e1/_ledger_v2/<S>/`. Он вне git — в нём свой `.gitignore`, в git идут только `manifest.json` и `SHA256SUMS.txt`. Подкаталог `p{NN}/` — свой у каждого процесса, без блокировок.

| файл | тип, форма | содержимое |
|---|---|---|
| `manifest.json` | JSON | `v`, `format`, `strategiya`, `period`, окна, `komissiya`, `fdr`, `kod`, `vhody`, `kod_slit`, `daty_sha`, `tikery` (17, порядок `sk.tickers`), `T`, `kub_sha` (sha256 `kub_S{k}.yaml`), `sobol_seed`, `sozdan` |
| `daty.npy` | `datetime64[D]`, [T] | даты строк портфеля периода; T = 1010 (252 + 252 + 254 + 252, замер §5.1) |
| `p{NN}/rows.jsonl` | JSON по строке | §1.2, только дополнение |
| `p{NN}/port/{shard:05d}.npy` | **float64**, [≤ 256, T] | `excess` портфеля (`df["excess"]` годов периода), побайтно как v1.0 `excess_d` подряд |
| `p{NN}/tik/{shard:05d}.npy` | **float32**, [≤ 256, 17, T] | excess тикера; `nan` — у тикера нет строки на дату |
| `SHA256SUMS.txt` | текст | строка на каждый закрытый шард (`sha256  p03/port/00012.npy`) |

Excess тикера:

`ex_t[d] = g_t − sides_t · comm − u_t · rf · cal − zaem_t`

Здесь:
- `u_t` = `expo_t` при `fdr = null` или `noch_t` при t0/t1;
- `zaem_t` = 0 в основном ряду.

Тождество при cap = 1 и L = 1 (тогда mg = 0, и Σexpo/cnt ≤ 1 снимает `max(0, ·)`):

`nanmean_t ex_t[d] = excess_port[d]`

Проверка тождества:
- во float64 до приведения — допуск ≤ 1e-12;
- после float32 — ≤ 1e-8 абсолютной (§1.7, М-L4).

Запись шарда:
- процесс копит до 256 результатов;
- пишет `*.npy.part` и переименовывает его;
- затем дописывает 256 строк в `rows.jsonl`;
- затем строку в `SHA256SUMS.txt`.

После обрыва шард без строки SHA удаляется, его точки считаются заново. Строки `rows.jsonl` без закрытого шарда отбрасываются. Потеря — не больше 255 точек на процесс.

Диск на стратегию при 30 000 точках:
- `tik`: 30 000 × 17 × 1010 × 4 Б = 2,06 ГБ;
- `port`: 30 000 × 1010 × 8 Б = 0,24 ГБ;
- `rows.jsonl`: ~3 КБ на строку, ~0,09 ГБ.

Итого ~2,4 ГБ на стратегию, ~14,3 ГБ на шесть (расчёт, §5.2).

### 1.5 API модуля `fastbt/ledger_v2.py` (Л-1)

```python
FORMAT, V = "etap1-ledger", "2.0"
def tok(v) -> str
def canon_v2(sid: str, pt: dict) -> dict
def klyuch(sid: str, pt: dict, period: str, komissiya: float, fdr) -> dict
def klyuch_sha(kl: dict, kod: str, vhody: str) -> str
def kvartaly(daty: np.ndarray, x: np.ndarray) -> dict            # {"2016Q1": SR, …}; ровно 16 ключей для train4
def tselevaya(by_quarter: dict) -> tuple[float, float]          # (mediana_kv, dolya_pol_kv)
class Pisatel:                                                  # один на процесс
    def __init__(self, root: Path, sid: str, potok: int, manifest: dict, shard: int = 256)
    def done(self) -> set[str]                                  # klyuch_sha уже закрытых строк (резюм)
    def add(self, row: dict, ex_port: np.ndarray, ex_tik: np.ndarray) -> None
    def close(self) -> None
class Chitatel:
    def __init__(self, root: Path, sid: str)                    # сверка SHA256SUMS и manifest; разные kod/vhody — отказ
    def rows(self, status="ok") -> list[dict]
    def matrica(self, rows=None) -> np.ndarray                  # T × N float64, порядок = rows
    def tik(self, rows=None) -> np.ndarray                      # N × 17 × T float32 (memmap)
    def n_unique(self) -> int                                   # различные klyuch_sha со status ok
```

### 1.6 Что проверяет читатель (отказ, а не пропуск)
- **Шард.** Нет строки в SHA256SUMS или sha не совпал → `ValueError`.
- **Версии.** `manifest.v` ≠ `"2.0"`, или строка с другим `v` → отказ.
- **Код.** В одном каталоге два разных `kod` → отказ. Исключение — явный `Chitatel(…, sverka_kod=True)` для гейта Ж-082 п. 1.
- **Даты.** В `by_year` или `by_quarter` есть год вне 2016–2019 → отказ.
- **Дубли.** `klyuch_sha` встречается дважды → берётся первая строка, `n_unique` дубль не считает. Тест — в Л-1.
