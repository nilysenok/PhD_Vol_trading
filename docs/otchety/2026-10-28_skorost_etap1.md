## 2. Что сделано (код не слит, ветка `skorost-etap1`)

- `fastbt/fast_exec.py` — автомат `exec_e_run.Run` + постобработка `exec_e.run` одним numba-проходом по дням и барам (`kernel`). Правила построчно как `exec_e_rules`: лимит — только при проходе на тик (l ≤ L − тик, h ≥ L + тик; касание не исполняет, № 2), цена — L или open при гэпе (№ 4), в баре стоп раньше тейка (№ 3), вход не раньше d+1 (Д2), трейлинг/безубыток после бара, `vyhod_lim`, `povtor`/`zakrytie_d1`, дивиденды и сдвиг стопа (Ж-060), дни pusto. Порядок операций с плавающей точкой тот же, без fastmath.
- `fastbt/fast_etap1.py`:
  - `run` — замена `exec_e.run` с теми же проверками и тем же `Result` (сделки — `Trade`); бары тикера раскладываются в массивы один раз (кэш по тождеству объектов `Day`, ссылки держатся);
  - `E1Inputs.digest` — тот же хэш, один раз на набор входов (повтор — только если все листы входов те же объекты; подмена листа — пересчёт);
  - `align_b` — один раз на (ряд режима, даты тикера);
  - `Evaluator._positions` — кэш позиций Sk по Д5: ключ = sha1(код fastbt, `series_digest` рядов Sk, sid, тикеры, база точки, сигнальные параметры, q, якорь, RM_OFF); память + диск `<основная копия>/data/fastbt/etap1_cache/` (`FASTBT_E1_CACHE`, `FASTBT_NO_CACHE=1`);
  - `patched()` — контекст, подменяет четыре места выше и возвращает всё назад; медленный путь не тронут и остаётся эталоном (якорь s9 считается им);
  - `map_points(evr, points, period, jobs=10)` — fork с общими массивами баров (Ж-082);
  - `ryady(evr, pt, period)` → (`port` float64 [T], `tik` float32 [17, T], даты) по §1.4 контракта ledger v2.0 (`docs/otchety/2026-10-28_progon_etap1.md`); `pokryto(pt)` по §1.8.
- `tests/test_fast_etap1_smoke.py` — синтетика: 400 случайных лент × параметров (`exec_e.run` против `fast_etap1.run`, побайтно `gross/cost/pos/free/fdr`, счётчики, сделки), те же ошибки на плохих барах/close, кэш головы ленты, подмена входа меняет digest. Покрытие фузза (400 случаев): выходов vremya 897, stop 465, signal 344, take 294, trail 284, bu 85, lim 73; исполнений лимита 1 370.

## 5. Не сделано и отступления

- ↺ Батч-ядро «все общие точки куба для одной сигнальной точки одним проходом» (Ж-083 п. 3) не сделано. Вместо него — пообъектное numba-ядро и кэши. Причина: после них тёплая точка стоит 0,006 с, из них ядро — 0,0005. Холодная точка упирается в сигналы Sk, а их батч по общим осям не ускоряет. Кроме того, драйвер Соболя (`progon_sobol`) зовёт оценщик по одной точке. · откат: батч по сигнальной точке поверх `fast_exec.kernel` (28.10).
- ↺ σ-источники и ранги режима через `fast_sigma` не делались: в профиле на точку их нет, они строятся один раз в `build_inputs`. · откат: не нужен (28.10).
- Точка подключения в `etap1_eval.py` / `exec_e_run.py` не понадобилась: `patched()` — контекст для драйвера (`progon_sobol --fast` уже зовёт `fast_etap1.patched()`). Медленный путь не тронут.
- Запись через `ledger_v2.Pisatel` — дело драйвера: `ryady` отдаёт ряды в формате §1.4. `EvaluatorV2` (Л-5) в базе ещё нет. Быстрый слой подменяет методы `Evaluator`, которые он наследует. Оси Run2 (`ed`, `zhizn`, `gap_propusk`, `t_vyhod`, `bar_plus`, `stop_tik`) `fast_etap1.run` отдаёт эталону `exec_e.run`; `pokryto(pt)` — только умолчания осей §1.1.
- Холодная точка (новая сигнальная точка) — 0,026–0,028 с: в допуске 0,03, но не в цели 0,02. Сигналы Sk считает старый код (`fastbt.signals`); на диске кэшируются позиции, а не сами сигналы.
- Файлы `fast_exec.py` (≈ 290 строк) и `fast_etap1.py` (≈ 300) длиннее 200 строк. `kernel` — одна функция на день `Run.step`: порядок операций держит побайтность.
