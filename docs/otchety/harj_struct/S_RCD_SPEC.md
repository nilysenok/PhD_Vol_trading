### 3.1 S-RCD — прямая коррекция под R (кандидат на проверку)
- Форма и признаки — S-CD (разд. 2.1), 6 параметров, границы `cm_model.bounds("CD")`.
- Процедура — **ровно S-RCK** (`S_R_SPEC.md` разд. 2), отличается только форма C:
  - потеря обучения L_R = mean ρ_κ(ln(RV/(m·F_j(θ)))) + λ‖θ‖², где ln F_j = (1 − π_j)·ln B_mix,j + π_j·ln C_j(θ) + β_j·g_j, π и β сохранённые, дня d_j (`r_loss.ln_f`);
  - x⁰ = RV/F(0) = RV/W5-G; c_T = Q₀,₉₉(x⁰_T), m_T = mean min(x⁰_T, c_T), κ = c/m, по T (`r_walk.stats_of(·, "R")`). x⁰ от формы не зависит, поэтому c, m у S-RCD и S-RCK на одном T совпадают;
  - сетка Λ = {θ = 0; 10⁻¹; 10⁻²; 10⁻³} (`r_loss.GRID`);
  - блоки V₁, V₂, V₃ по 126 последних закрытых пар, T_b — пары раньше V_b (`r_walk.blocks`);
  - G_{λ,b} — обычная QLIKE уровня F против ln F(0) = `Ctx.lnf0`;
  - правило `r_walk.decide(G, "blocks")`: допуск w ≥ 2 из 3; нет допущенных — θ = 0; иначе argmax w, при ничьей больший λ;
  - финал — на P с c, m по P;
  - включение |P| ≥ 630 (`r_walk.MIN_POOL`): 75 активных месяцев с 2020-08-03 (`pool.py`). До включения θ = 0, C = cfg8 копией, F = W5-G;
  - 5 перезапусков: θ = `cm_model._x0("CD", r)`, r = 0…4; итог — минимум L_R, при равенстве меньший r (как `r_loss.fit_r` у CK).
- Направление уровня у C-D есть: ∂ln C/∂θ0 = 1 на каждой дате (`nest.py`: ∂Σ ln C/∂θ0 = 2198). Поправка m при θ = 0 даёт нулевой балл уровня, как у S-RCK.
- Потеря выпукла по θ (ln F линеен по θ, ρ_κ выпукла по ln F). Перезапуски должны совпасть; разброс печатается.

### 3.2 S-CDF — обязательный контроль владельца: та же коррекция без R, качество конечного гибрида
- Форма, признаки, 6 параметров, границы, перезапуски и штраф λ‖θ‖² — S-CD.
- **Потеря обучения:** L_F = mean_{j∈P} ℓ(RV_j, F_j(θ)) + λ‖θ‖² — обычная QLIKE уровня F. ln F_j — та же формула с сохранёнными π_j, β_j·g_j, что у S-RCD. Обрезки нет, m = 1, κ = ∞ (режим `plain` `r_loss.loss_r`).
- **Отбор λ — протокол S-CD, перенесённый на уровень F (В-2):**
  - λ ∈ {10⁻⁴; 10⁻³; 10⁻²}; θ = 0 в сетке нет;
  - при |P| < 252 — λ = 10⁻² без валидации;
  - иначе — обучение на P без последних 126 пар, валидация — mean ℓ уровня F на последних 126 (замороженные π, β); минимум, при ничьей больший λ;
  - блоков нет;
  - финал — подгонка на всём P.
- Включение — 2018-07-02 (В-1), 100 активных месяцев. До него θ = 0, C = cfg8 копией.
- Информация та же, что у S-RCD и S-CD: те же пары, признаки, π, β. Сложность та же: 6 параметров, тот же штраф. Отличие от S-RCD — только процедура (обрезка, m, θ = 0 в сетке, блоки, сетка Λ, включение 630). Отличие от S-CD — только уровень потери и валидации.

### 3.3 S-CKF — контроль уровня потери для C-K (решение: включить)
- Как S-CDF, но с формой 𝓜_CK (S-CK, μ = 0): `cm_model._x0("CK", r)`, `cm_model.bounds("CK")`.
- **Зачем.** Без S-CKF план — только три угла квадрата «форма × процедура»:
  - угол без R у C-K — S-CK, обученный на уровне C;
  - угол без R у C-D — S-CDF на уровне F.
- Тогда эффект R у C-K (S-RCK − S-CK) включает смену уровня потери, а у C-D (S-RCD − S-CDF) — нет. Их разность («помогает ли R одной форме больше, чем другой») сравнивала бы несравнимое.
- С S-CKF квадрат замыкается на уровне F: {CD, CK} × {без R, R}. Эффект R разлагается для C-K на «уровень потери» (S-CKF − S-CK) и «процедуру» (S-RCK − S-CKF), как и требует дирижёр.
- Почему имеющихся рядов мало:
  - S-RCKf — это R с потерей уровня C и валидацией уровня F. Он даёт уровень **при** R, а не без R;
  - S-RCKb — R без обрезки, но с θ = 0, блоками и включением 630. Это не «без R».
- **Цена.** +1 к N (+2 к N_wide). Множитель Холма меняется с 857 до 858, на выводы почти не влияет. Счёт C-K — секунды (S-RCK — 7 с, `R/cost.json`).
- Роль — диагностика, не кандидат. Условия разд. 7 к S-CKF не применяются.

**Чего нет (не регистрируется, в N не входит):** абляции R на C-D (Rb — без обрезки, Rc — без блоков, m := 1, уровень C).
- Вопрос Ж-259 п. 2 — «R целиком против той же коррекции без R». Элементы R уже разложены на C-K (S-RCKb, S-RCKc, S-RCKm, S-RCKf).
- Повтор на C-D увеличил бы N без ответа на вопрос владельца. Если H-RCD1 выполнится, разложение элементов на C-D — отдельная регистрация.

## 4. Вложение — проверяется тестом

**(Н1) Прямое, побитно — проверено на сохранённых рядах** (`<sp>/nest.py`, без обучения):
- при θ = 0 ln C пути C-D = `torch.log(V.c8·CM.forward(0, V, "CD")["M"])` равен ln C пути C-K `r_loss.lnc_of(0, V, "CK")` побитно на 2198 датах. Отсюда x⁰, c, m и `Ctx.lnf0` у S-RCD те же, что у S-RCK;
- `Ctx.lnf0` = ln F(0) пути C-D побитно;
- `r_walk.assemble` при θ ≡ 0 во всех месяцах (C = cfg8 копией): F = `w5g.F`, X1_R = x1.F, C = cfg8 — побитно;
- exp(ln F(0)) против `w5g.F` — max отн. 3,33·10⁻¹⁶ (1 ulp; см. «Своя ошибка»). В прогноз этот путь не идёт.

Для S-CDF и S-CKF то же: до включения и при θ = 0 C = cfg8 копией ⇒ F = W5-G побитно.

**(Н2) Процедурное, побитно — для S-RCD.** Новый проход R (разд. 8) с формой "CK" вместо "CD" должен воспроизвести `R/rck.parquet` побитно (`assert_frame_equal(check_exact=True)`) по колонкам C, F, X1_R, lam, w_*, G_*, c, m, θ.
- Так доказывается, что код S-RCD отличается от S-RCK только формой C.
- Достижимо: та же арифметика `r_loss.loss_r` и `fit_r`, те же старты, границы и порядок перезапусков.

**(Н3) Процедурное, с допуском — для S-CDF и S-CKF.** Новый проход протокола S-C с уровнем, подменённым на C в обучении и в валидации (π := 1, ln B := 0, β·g := 0, как `make_ctx(·, "C")`), должен воспроизвести `CM/cd.parquet` (форма CD) и `CM/ck.parquet` (форма CK):
- λ совпадает в 100 из 100 активных месяцев;
- max отн. |C − C_сохр| ≤ 10⁻⁴;
- |QLIKE(F) − QLIKE(F_сохр)| / QLIKE(F_сохр) ≤ 10⁻⁵ на D_M.
- **Почему допуск, а не побитно.** У S-C в коде ℓ = r − ln r − 1, r = RV/F (`cm_model.py:83–85`). У уровня F — eᵘ − u − 1 (`r_loss.py:113`). Арифметика разная, и L-BFGS-B при ftol 10⁻¹⁰ останавливается в разных точках.
- **Откуда числа допуска** — оценка, не замер. Относительная остановка по потере 10⁻¹⁰ при L ≈ 0,2 и кривизне порядка 0,1 даёт ошибку θ около √(2·10⁻¹⁰·0,2/0,1) ≈ 2·10⁻⁵. Признаки порядка 1, поэтому ln C смещается на ~10⁻⁵. Допуск 10⁻⁴ — запас ×5. Фактический максимум печатается.
- Если λ расходится хоть в одном месяце — стоп и разбор до прохода основных рядов. Допуск не расширяется.

## 11. Что не проверено и риски

- Выберет ли R θ ≠ 0 у C-D, неизвестно. При θ = 0 во всех месяцах S-RCD ≡ W5-G, и H-RCD1 сведётся к «W5-G против S-CDF».
- Основной критерий сравнивает R целиком с протоколом S-CD на уровне F. В «эффект R» входит включение 630 (В-1). Его вклад виден только на общем активном окне (разд. 6.3), отдельной строкой не регистрируется.
- Н3 — с допуском. Если λ расходится в каком-либо месяце, «отличие S-CDF от S-CD только уровнем» не доказано, и нужен разбор до счёта.
- Заморозка π у всех трёх рядов — приближение первого порядка; реакция слоя показывается.
- Ограничения ρ ∈ [0; 1] у C-D часто активны: у S-CD ρ на границе в 40 / 77 месяцах из 100. Под R с λ = 10⁻¹ это может измениться — показывается в параметрах.
- Модель угроз не нужна: сети, сервера и ключей нет.
- Новых библиотек нет (torch, numpy, scipy, pandas уже в проекте).
