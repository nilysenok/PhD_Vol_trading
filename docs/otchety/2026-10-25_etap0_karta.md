## Четыре факта

1. **HAR-J оценивается пулом по 17 тикерам**, а не по каждому тикеру: `scripts/walk_forward_full.py:200-205` (`LinearRegression().fit` на всех тикерах разом). Файлы `models/har_rvj/h*/<тикер>.json` (по файлу на тикер) относятся к другому, более раннему обучению (`results/final/code/train_har.py`) и в walk-forward не участвуют.
2. **8 регрессоров + константа = 9 коэффициентов, в логах**: `rv_d, rv_w, rv_m, jump, jump_annualized, jump_lag1, jump_lag5, jump_lag22`; X и y берутся как `log(clip(x,1e-10))`, прогноз `exp(ŷ)` без поправки на смещение (`walk_forward_full.py:70-73, 193-204`). Замер: `etap0_har_timing.py` печатает 8 коэффициентов + const. В `models/har_rvj/*.json` перечислены только `rv_d, rv_w, rv_m` (без J): это не тот же набор.
3. **Валидационный QLIKE для весов гибрида (V1)**: валидационный год = последний год обучающего окна шага (`val_year = max(train_years)`, `walk_forward_full.py:111-118`), QLIKE считается на пуле всех тикеров, отдельно для каждого h; вес HAR-J `w` ∈ [0; 0,60] шагом 0,01 минимизирует QLIKE смеси `w·HAR-J + (1−w)·ML`, при `w=0` запасной вариант — обратные QLIKE (`walk_forward_full.py:258-278`). Для V2–V7 (`scripts/walk_forward_adaptive_v3.py:265`) валидационный год `test_year − 1`, расчёт тоже пулом; точное различие V2–V7 по строкам не сверено (`❓3`).
4. **Горизонт σ_pred в C/D выбирается, не фиксирован**: параметр `horizon` ∈ {h1, h5, h22} входит в сетки `C_HORIZONS`, `D_HORIZONS` и подбирается вместе с остальными параметрами для каждого (стратегия, подход, тикер, год): `scripts/strategies_walkforward_v4.py:701-702, 772-808`; итог сохранён в `results/final/strategies/walkforward_v4/tables/v4_horizon_selections.csv`. На каких данных идёт подбор (обучение или валидация), по этим строкам однозначно не видно (`❓4`). σ берётся из `results/final/strategies/data/vpred_aligned.parquet` (колонки `sigma_h1/h5/h22`).
