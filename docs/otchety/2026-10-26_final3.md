## Правило третьего круга — точные формулировки (зафиксированы до запуска)
Источник: сводный блок владельца 00:55, решения 01:05 → 01:12, уточнение дирижёра о «видевших подтверждающий».

1. **Пул.** В пул входят:
   - финалисты второго круга: D12_h1_A_d812, D12_h1_B_b0.25, D12_h1_V0, F2m_h5, D12_h5, L2v3_h5, D12_h22;
   - HAR-J с поправкой (`HARJ_corr`: дизайны `single|V0_HAR|B-*|L0` гибрида хоста; фолбэк h=22);
   - кандидаты третьего круга, у которых к запуску сборки есть OOS-прогнозы val шагов 1–9 и yaml.
   
   Одиночные модели без бустинга в пул не входят. HAR-X — только нога гибрида (решение 01:12; отменяет «Д16.4 — кандидат» из блока 00:55).
2. **Представитель кандидата** — его лучший дизайн по правилу п. 3 во всём пространстве гибрида (`gibrid_v17.py --dev-eval oos --etalon same`).
3. **Рейтинг.**
   - Ключ сортировки: число нарушенных критериев c1–c4, затем средний OOS QLIKE val 2017–2020 (шаги 2–5).
   - Критерии считаются на val 2017–2021 (шаги 2–6, OOS): параметры и s² шага t−1 применяются к val шага t. Val 2016 (шаг 1) даёт s² для шага 2.
   - Эталон критериев — модели с той же s². V0 участвует наравне и сам с собой не сравнивается.
   - h=1, tie-break владельца: гибрид ставится перед лучшим чистым бустингом (D12_h1_V0), если отстаёт от него не больше чем на 1% по 2017–2020 и нарушает не больше критериев.
4. **Отложенный 2021 (шаг 6)** — только для кандидатов третьего круга.
   - «Текущий лучший по правилу» — первый в рейтинге п. 3 среди кандидатов кругов 1–2 (финалисты второго круга и HAR-J с поправкой).
   - **Проверка: кандидат третьего круга проходит шаг 6, если его OOS QLIKE val 2021 ≤ OOS QLIKE val 2021 текущего лучшего. Допуска нет.** У каждого берётся его лучший дизайн по п. 3.
   - Не прошедший шаг 6 в финалисты не берётся.
5. **Видевшие подтверждающий** (уточнение дирижёра; в пуле — колонка «видел подтверждающий»).
   - (1) Если дизайн кандидата не прошёл подтверждающий в кругах 1–2, весь кандидат в финалисты не берётся. Варианты, отличающиеся только рычагом третьего круга, — тоже. Основа варианта берётся из ключа `osnova` yaml или из имени кандидата второго круга внутри имени файла (например, `D16_8n_F2m_h5` → F2m_h5).
     - Сейчас исключены: D12_h1_B_b0.25, F2m_h5, D12_h22.
     - HAR-J с поправкой тоже исключён: в первом круге single/V0_HAR/B-sm на v2 не прошёл. Фолбэком h=22 он остаётся.
   - (2) Прошедший подтверждающий (D12_h1_A_d812, D12_h1_V0, D12_h5, L2v3_h5) может быть финалистом с пометкой «уже прошёл подтверждающий во втором круге — повторная проверка неинформативна».
   - (3) Новые дизайны третьего круга — без ограничений.
6. **Три финалиста на h.**
   - Идём по порядку рейтинга и берём первого допущенного из каждого семейства.
   - Если допущенных семейств меньше трёх — добор следующими допущенными с пометкой ↺.
   - Кандидат без тестовых прогнозов шагов 1–9 финалистом быть не может.
   - Список пишется в `docs/otchety/dev_log.md` со временем, затем коммит и push — всё до открытия.
7. **Подтверждающий** (val 2022–2024, шаги 7–9) открывается один раз: `gibrid_v17.py --confirm --confirm-next 0`.
   - Критерии c1–c4 считаются на шагах 7–9. По М4 финал — первый прошедший по порядку финалистов.
   - h=22: если никто не прошёл или финалистов нет, финал — HAR-J с поправкой (s² по правилу п. 3).
   - h=1/5: если никто не прошёл, финал — первый финалист с пометкой.
   - Защита в скрипте: открыть подтверждающий без записи в dev_log нельзя; второй запуск блокирует замок `data/regen/final3/CONFIRM_OPENED.json`.
8. **Эталон** DM, MCS и H1 на всех h — HAR-J с поправкой (решение 01:12).
   - Столбец `harx_corr` (HAR-X с поправкой той же s²) в тестовых файлах нужен только для таблицы раскладки приложения.
   - На h=22 эконометрическая нога гибрида — HAR-J. Причина — проигрыш HAR-X в 2020 году; QLIKE по годам — в черновике FINAL, раздел 10.

```yaml

h: 22                     # или [5, 22]
semeystvo: GLM с офсетом  # семейство (три финалиста — из разных)
rychag: Д17.1
opisanie: одна строка для FINAL

test_dir: data/regen/test_locked/D17_1_h22_G22   # {boost}_{xgb|lgbm}_h{h}[_leg]_test.parquet, шаги 1-9
osnova: D12_h22           # если вариант кандидата второго круга (иначе — по имени)
step10_dir: ...           # необязательно: {boost}_{m}_h{h}_s10_val.parquet (формат final2_step10.py); без него — шаги 1-9 (↺)
step10_lock: ...

```
