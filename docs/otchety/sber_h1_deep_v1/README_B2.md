Единственная группа, у которой выигрыш виден и по внутреннему критерию, и в описании по всем трём периодам, — **F4 (Parkinson/диапазон High–Low, RQ/MedRV исключены правилом корреляции, vol-of-vol, HHI)**: QLIKE 0,2125 против 0,2205 у Б-2; 2017–2021 0,1548 (HAR-J(б) 0,1553, у Б-2 0,1630), 2022 0,4818 (0,4877), 2023–2025 0,2347 (0,2432). ## Отступления (до выводов)
1. Realized Kernel не считался (не обосновано заранее); из F4 правилом корреляции исключены `f4_rq` (0,951 с `ln_rv`), `f4_medrv` (0,970 с `ln_bv`), `f4_hhi_chg` (0,975 с `f4_hhi`).
2. LOYO для rolling/весов — по ближайшим к проверяемому году парам (в LOYO нет «конца окна»); для weekly/monthly/CUSUM `crit_loyo` не определён, перспективность — только описательная (`crit_wf`), с пометкой (принято дирижёром).
3. Правило допинформации считалось по строкам ≤ 2016; `f6_since` в этом окне константа (корреляция не определена) — по объявленному правилу принят; его вклад отдельно не проверялся.
4. Лучшие 2 и 3 группы (top2/top3) выбраны по `crit_loyo` по всем годам 2017–2026 — выбор структуры на всей выборке (потолок).
5. SHAP/gain — модели на первой дате сетки каждого года по обучающим парам; диагностика, не доказательство.
6. Вспомогательные скрипты `diag_cusum.py`, `verify_b2.py` лежат в `data/regen/v2_sber_h1_deep_v1/b2/`, а не в `models_v2/s5/b2/`, чтобы не менять sha кода (ключи кэша и шапки таблиц).
7. Процессов: счёт — пул из 4 процессов (+ главный); системная загрузка показывала > 400 % CPU из-за многопоточности numpy/pandas в главном процессе.
8. В файлах `tests/test_s6sb_*` кто-то другой изменил файлы после начала моей работы (не мои); моих правок вне владения нет.
