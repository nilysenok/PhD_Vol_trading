## Отступления
- ↺ Optuna ищет по всей сетке (CLI не умеет сужать до «параметров с эффектом»); фиксированные по OAT параметры в поиске остаются свободными. Увеличивает N честно (всё в ledger).
- ↺ Топ-3 в `S{k}_top3.csv` — как выдал движок, включая краевые точки (`edge=True`); выбор по плато с ≥ 3 соседей — отдельным файлом `_top3_plato3.csv` (фильтр поверх CSV, кода движка не менял).
- Сетка OAT v1 повторно пересчитана с нуля (старые OAT-таблицы без √RV заменены новыми; ledger пуст до запуска).
- Для запуска понадобились симлинки `data/*` из основной копии (не коммитятся).

## ❓ (для T1)
1. `sweep_run_iter.plateau_sparse`: у разрежённых точек Optuna плато = цель самой точки (соседей 1–2), топ-3 по нему — по сути пики; `edge` не исключает точку из `top3`. Нужен отбор только `edge=False` либо локальная доплотнка вокруг точки.
2. Параметры, не влияющие при данном условии (trail_atr_mult/trail_n при sqrt_rv, vf_porog в S3, gamma_hold везде), порождают дубли с разными ключами пробы: раздувают N и «соседей». gamma_hold во всех S1–S3 даёт ровно 0 — похоже, не подключён в ядре kind=2.
3. `tune_oborot_y` равен `tune_sdelok_y` во всех строках — проверить, что оборот не дублирует число сделок.
4. q_sily: размах Шарпа tune S1 0,001, S2 0,087, S3 0,225 (число сделок у S1 меняется 8,29 → 8,17) — эффект малый; стоит проверить, что маска силы режет сигналы как задумано.
