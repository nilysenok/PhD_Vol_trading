## HAR-CJ `_emb_d0`

Регрессоры, OLS в логах, шаги и обработка пропусков — те же, что у `gibrid_har.har_forecasts`. Подбора нет. Изменены только два места.

1. **d0.** C_d = BV_d, C_w = среднее BV_{d−4..d}, C_m = среднее BV_{d−21..d}. J_d, J_w, J_m строятся так же по jump дня d. Нулевой BV заменяется последним положительным BV тикера, как в ноге `_d0` у `r2_nogi.py`.
2. **Эмбарго по концу цели.** Строка t обучает шаг k, только если год строки t+h тикера < vy_k. В s² для Б0.1 идут только остатки, цель которых кончается до года применения.

Проверки:
- Свой драйвер в версии «как в коде» повторяет `gibrid_har.har_forecasts` на шагах 1–9 до 5·10⁻¹⁴ (`check_driver.csv`).
- Что дала каждая из двух правок, h = 1 / 5 / 22:
  - только эмбарго — 0,3320 / 0,2285 / 0,2190;
  - только d0 — 0,2869 / 0,2078 / 0,2070.
  
  Весь выигрыш даёт d0. Эмбарго справочно стоит до +0,9% на h = 22. Основная версия — `_emb_d0`, выбора нет.
- Детектор «будущее не влияет» (`leak_harcj_d0.csv`) — **PASS**: срезы 28.06.2019 и 30.06.2021 (середина года) и 31.12.2018 (граница года), h = 1 / 5 / 22.
  - Входы rv/bv/jump после среза и цели, чей горизонт заходит за срез, умножены на U(0,5; 2).
  - Середина года: прогнозы val до среза, коэффициенты и F шагов с vy ≤ года среза совпадают побайтно. Прогнозы после среза меняются (2 210 строк).
  - Граница года: коэффициенты и F шага 2019 совпадают побайтно. Без эмбарго (`_d0`) они меняются, то есть утечка через цель была бы видна.
  - Подложенная утечка C_d := BV дня d+1 **поймана**: на каждом срезе 17 расхождений, по одному на тикер, в строке среза.
