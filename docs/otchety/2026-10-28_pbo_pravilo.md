# PBO (CSCV) в отборе этапа 1: какое правило выбора внутри (чтение кода, 28.10.2026)

Статус: разработка 2018–2019, только чтение, ничего не считалось.

## 1. Правило внутри CSCV
- (а) argmax по среднему дневному избытку: `fastbt/sweep_drivers.py:160-171` (`agg` — среднее по строкам блоков; `best = max(range(N), key=a_tr[j])`). Ранг выбранной на test — `:173-176`, PBO = доля логитов ≤ 0 (`:177-181`).
- Вход: `fastbt/etap1_poisk_vorota.py:199-200` (`pbo` -> `sd.pbo_cscv(M.tolist(), 8)`); матрица `:189-196` — столбец на каждую точку ledger периода, строки — дневной избыток 2018+2019 подряд (`series(res)` = `excess_d`, `:66-68`). Фильтра допустимости, края сетки и ворот нет: в M входят все точки Морриса, факторного и проб плато.
- Вызывают: `etap1_poisk.py:160-161` (run_strategy, до `pick_center`), `zh051_plato.py` (`vybor`: `V.pbo(V.matrix(led, period))`), `zh051_iter_t.py:90,154`, `etap1_ansambl_run.py:110,123-124`.

## 2. Правило реального отбора
- Центр плато, не пик: `etap1_poisk.py:55-66` (`pick_center`): `sd.pick_by_plateau` (радиус 1, ≥ 3 соседей, `sweep_drivers.py:74-92`) -> допустимые (`dopustima`, не `vyrozhdena`) -> TOPK -> ворота `gates` -> `pick_best` по `plateau`, ничья ≤ 0,05 — меньшая `sigma126` (`etap1_poisk_vorota.py:78-84`). Итерации Ж-051 — то же: `zh051_plato.py` (`vybor`: `sd.plateau_score`, `pick_best`).
- PBO в отборе — только ворота G1: `pbo < 0,2` (`etap1_poisk_vorota.py:152`, `zh051_plato.py` `gates_plus`); одно число на стратегию, на выбор точки не влияет.

## 3. Совпадают ли
Нет. Внутри CSCV — (а) argmax среднего дневного избытка, без плато, соседей, допустимости, σ126 и ворот. Реальный выбор — (б) центр плато по min mSR. PBO измеряет вероятность переобучения правила «возьми пик по среднему избытку», а не нашего. Знак смещения по коду не определить. Гипотеза (не измерение): пик по среднему на половине шумнее усреднения по соседям, значит PBO, вероятно, завышен (пессимистичен). Честная половина — прогнать оба правила на одной M.

Что изменить (описание): в `pbo_cscv` на каждом разбиении выбирать не argmax, а ту же процедуру, что `pick_center`/`vybor`: на train-половине посчитать целевую каждой точки (min mSR по годам) и плато (среднее по соседям ±1 по осям факторной сетки, край < 3 точек не берётся, допустимость, ничья по σ126), взять центр плато; ранг этой точки смотреть на test-половине по той же целевой. Для этого `pbo_cscv` должен получать не плоскую матрицу, а координаты точек в сетке (оси, соседи) и функцию целевой/допустимости. Матрицу ограничить точками факторной сетки (без проб Морриса), как у кандидатов. Старый argmax-вариант оставить справочно, оба числа — в таблицу.

## 4. Целевая внутри CSCV
Не min mSR. Это среднее дневного избытка по блокам (`sweep_drivers.py:160-168`): без нормировки на σ, без разбивки по годам и без «min по годам». Целевая отбора (Ж-043, `etap1_poisk_vorota.py:52-58`, `obj`) — min mSR по годам train (nan -> год не пройден). Не совпадают. Блоки CSCV (8 смежных, около 63 дней) не равны календарным годам, поэтому min mSR по годам на половине из 4 блоков не определён без перестройки (mSR считается по году целиком).
