### Кластер 7 (уровень итога)

| ключ | правило |
|---|---|
| `ens.agg` | mean / median уровней по seed × lib (mean — как both_avg R1) |
| `ens.ec` m5 / m10 | Д23.1. ē_m берётся из `d23_ec.ebar_from_e` без изменений: e(s) = ln RV_{s+1} − ln ŷ¹(s), среднее e(t−1..t−m) по тикеру. Затем ln ŷ_h += κ_h·ē_m. κ — МНК без константы по OOS шагов < t с концом цели < 1 янв. vy; ≤ 50 строк → κ = 0. Источник ошибок: на h = 1 — сам ряд, на h = 5 и 22 — F_d0_h1 |
| `ens.range_guard` | ln ŷ шага обрезается в [min, max] ln цели тикера на обучении шага (эмбарго h) |
| `ens.uncert_shrink` | ln ŷ = ln ŷ_ноги + w·(ln ŷ_анс − ln ŷ_ноги), w = 1/(1 + Var_seed/τ). τ ∈ {0,001; 0,003; 0,01; 0,03; 0,1} — варианты `tau=…`, выбор внутри складки делает r2_loyo |

### Кластер 8

| ключ | правило |
|---|---|
| `ens.seeds` | 1 / 3 / 10 → seed 42 / 42–44 / 42–51 |
| `ens.lib_agg` | avg — агрегирование по lib вместе с seed; best_by_LOYO — варианты `lib=…` для выбора внутри складки |
| `ens.window_ens` | нога переобучается на трёх окнах (расширяющееся, скользящее 3 и 5 лет, эмбарго h), уровни усредняются |
| `ens.leg_ens` | equal / median. qlike_shrunk_05 и _075: w = λ/K + (1−λ)·w*, где w* — минимум QLIKE на симплексе по прошлым OOS; на шаге 1 веса равные. λ = 0 — ошибка до счёта |
| `ens.ticker_bag` | нога-пул без одного тикера × 10 (16 из 17, rng 20261026 + h), уровни усредняются |
| `ens.stack` nested_oos | ln y = c + Σ b_k ln ŷ_k, b ≥ 0 (NNLS) — только на прошлых OOS; на шаге 1 — среднее |

Порядок на уровне итога: seeds → lib_agg/agg → uncert_shrink → stack → ec → range_guard.

### Кластер 13 (`leg.moe*`)

- **Режим строки t.** z = ln y_h − медиана ln y тикера на обучении шага, где y_h — средняя RV за [t+1, t+h]. При k2 режим — z > 0, при k3 — терцили z на обучении.
- **Эксперты** — HAR-X МНК на подвыборке режима с усадкой к общей модели: ln ŷ_r = 0,5·ln ŷ_all + 0,5·ln ŷ_r^sub.
- **Привратник** — logit (StandardScaler + LogisticRegression) или LGBMClassifier на [ln HAR-J, слагаемые], обучение — годы < vy.
- **Изотонная калибровка** — по классам, на прошлых OOS привратника (шаги < t, конец цели < 1 янв. vy), затем нормировка.
- **Смесь** — мягкая, Σ p_r·ŷ_r. При `moe_hard = 0.7` и max p ≥ 0,7 берётся эксперт argmax.
- **AUC** привратника считается на отложенном году каждой складки (k3 — макро one-vs-rest) и пишется в `moe_auc`.
- **Вероятности режима наружу** (для ворот `regime` агента G). Публичная функция `moe_proba(M, h, terms, mode='k2', gate, calib, seed, steps, tickers)` возвращает DataFrame со столбцами date, ticker, year, step, p0..p{K−1} (после калибровки), p*_raw и lab (−1 — цели нет). Строки — все дни val-года шага. Режим 0 — спокойный, поэтому p0 = P(спокойно).
  - Общий генератор `_moe_steps` даёт ровно те вероятности, которые смешивает `moe`.
  - Проверено: QLIKE дыма до и после выноса совпадают, Δ = 0 на 69 рядах; AUC из `moe_proba` равен `auc_calib` смеси.
  - Детектор `moe_proba_k2_iso` — OK.
  - Отличие от копии G: изотонная калибровка идёт по каждому классу с нормировкой, у G — только по p0. Для k2 это близко, но не тождественно.

## Находки

1. **PyYAML читает `off`/`on` как False/True** и в схеме, и в дизайнах. Ядро S нормализует это одинаково с O; в E значения приводятся к 'off'/'on' после `r2_core.validate`. Побочный эффект в схеме: ключ `selection.sigma.on: finalists` разбирается как `'True': finalists` (видно в `r2_core.py show`). Это для S и O (❓, на хэш не влияет: правило единое).
2. **Пустой `ens: {}`** в дизайне `r2_core.validate` считает неизвестным листом «ens». Пустые разделы в E не передаются.

## Вопросы (❓, умолчание действует; срок — до ворот E)

1. range_guard. **Умолчание:** [min, max] ln цели тикера на обучении шага.
2. uncert_shrink. **Умолчание:** усадка — к ноге дизайна; сетка τ — по yaml E.
3. qlike_shrunk. **Умолчание:** w* — минимум QLIKE на симплексе по прошлым OOS; усадка λ — к равным весам.
4. ec для h = 5 и 22. **Умолчание:** ошибки берутся из h = 1 ряда F_d0 (аналог финалиста h = 1 в Д23.1).
5. MoE: метка — по медиане тикера, κ = 0,5, признаки привратника — ln HAR-J и слагаемые S-набора. **Умолчание:** как в yaml.
6. (для L) window_ens, ticker_bag и MoE переобучают ногу локальным подгонщиком: HAR-J или HAR-X МНК, S1–S5 через `harx.TERMS`. Для HEAVY, MIDAS и прочих нужен API ноги L вида `fit(A, h, mask) -> ln на всех строках`.
7. (для S и O) Входы E (ряды B и M по дизайну) нужно сопоставить через `r2_core.SHARED['E_inputs'](design, h, seeds, steps, tickers)`. Без этого берутся `inputs` yaml E — старые ряды `R2/cache/{VYR,E,B2}`.

## Пакетный run (драйвер S, PR #184)

`python3 scripts/analysis/r2_ens.py run --designs <yaml> --h <h> --seeds <…> --steps <…> --workers <N>`. Контракт — `r2_S_driver.yaml`, `docs/server_r2.md` §10, схема — `schema_v2` ядра.
- **Вход.** yaml с ключом `designs: [...]` или один дизайн. Дизайн без `h` получает `--h`; дизайны другого h пропускаются.
- **Счёт.** На каждый h — один `r2_core.run_phase('E', …, fn_E)`: пул из `--workers` (fork), DONE_E_h{h}_s{seed}, готовое пропускается, ворота D проверяются. Ключ `--no-gate` — только для ручных прогонов. Прежний `--design` оставлен.
- **Входы.** `chain_inputs`:
  - гибрид — ряды последнего модуля цепочки (G > M > L3 > BG > B > R > P > L) в каталоге того же дизайна (`r2_core.load_series`), по seed × lib;
  - ноги — ряды L;
  - ряд h = 1 для ec — `inputs.base_1` дизайна;
  - если каталог пуст — inputs yaml E.
- **Проверки.**
  - Дым: пакет из 2 дизайнов × 3 h — 48 рядов, сдвиг argmax = 0, детектор OK.
  - Гибрид h = 5 из рядов модуля B совпал со входом.
  - CLI: 4 дизайна, `--workers 2`, ошибок 0.

## Сервер

Пакетом: `python3 scripts/analysis/r2_ens.py run --designs <пакет>.yaml --h 5 --seeds 42 43 44 --steps 1 2 3 4 5 6 --workers N`.
