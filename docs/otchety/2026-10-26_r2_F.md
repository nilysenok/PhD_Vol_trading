## v2 (16:30): разбор трёх столбцов, заблокированных O (PR #167)
O заблокировал `g7_ln_amihud_w`, `g7_ln_amihud_m` и `g4_jbig_n22`: максимум корреляции с RV на сдвиге +1. **Ошибки в коде нет.** Разбор — `python3 scripts/analysis/r2_features.py --stage razbor`, таблицы `docs/otchety/r2_F/razbor_3stolbca.csv` и `razbor_3stolbca_sdvig.csv`.

**Как устроены окна.**
- `roll_t` — `groupby(ticker).rolling(w, min_periods)` по строкам, отсортированным по (ticker, date). Окно хвостовое (`center=False` по умолчанию): строки d−w+1 … d.
- min_periods 3/13 только требует минимум прошлых наблюдений.
- ffill в G7 нет. В G4 ffill есть только у «дней с последнего скачка», и он идёт от прошлого к будущему. На `jbig_n22` он не влияет.
- Amihud дня d — из крейта: |ln C_d/C_{d−1}| / оборот_d, бары дня d и close прошлого дня. Объём и скачок дня d+1 нигде не берутся.

**Проверки.**
- Пересчёт «в лоб» на 3000 случайных строках 2017–2021, только по рядам с датами ≤ d: расхождение ≤ 8e−13 у Amihud и 0 у `jbig_n22`.
- Детектор на каждом из трёх столбцов отдельно, 3 среза: без утечки Δ = 0. Подложенная утечка поймана: 17 ячеек у Amihud и 7–9 у `jbig_n22` на срез.

**Почему максимум на +1.**
- Amihud_d = |r_d| / оборот_d. Обе части сильнее всего связаны с RV дня d, но с разными знаками. ρ(ln|r_d|, ln RV_{d+s}) = 0,46 при s = 0 и 0,36 при s = +1. ρ(−ln оборот_d) = −0,58 и −0,42.
- В отношении они почти гасят друг друга. У ln Amihud_d профиль плоский: 0,0987 при s = 0 против 0,0983 при s = +1.
- У приращений w/m остаток в сотые доли (|ρ| ≤ 0,06) перевешивает в сторону +1. У `jbig_n22` |ρ| ≤ 0,035 — это шум.
- У этих столбцов проверка сдвига не имеет силы. Даже подложенная утечка (окно d−w+2 … d+1) не даёт у них уверенного +1: у `ln_amihud_w` с утечкой argmax 0, у `jbig_n22` с утечкой — 0.

**Решение (по поручению дирижёра).** Три столбца убраны из G4 и G7. Остальные столбцы не менялись.
