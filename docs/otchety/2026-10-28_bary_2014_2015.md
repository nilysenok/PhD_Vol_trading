## Главное

1. **Расхождение 54 % против 88 % снято: это два разных 10-мин parquet.** `moex_discovery/data/final_v6/candles_10m/stocks/` (он же `dataset_final/01_stocks/candles_10m/`, байт в байт, sha256 совпал у LSRG и PHOR) содержит не все бары. `moex_discovery/data/raw/candles_10m/` — тот, что читает код проекта (`fastbt/daily_1850.py:build`, `sigma_real.load_rv`, `vselennaya_kachestvo.bars_per_day`) — полнее. Цифры архитектора (54 %) взяты с `final_v6`, исследователя (88 %) — с 1-мин файлов; `raw` ≡ 1-мин.
2. **Пересобранный из 1-мин ряд совпадает с `raw` бар в бар** (294 590 баров 26.08.2014–31.12.2015, 17 тикеров: 0 лишних, 0 недостающих, 0 расхождений OHLCV). С `final_v6` — 0 расхождений на общих барах, но в `final_v6` не хватает 5 891 бар (2,0 %). Поэтому правило Ж-116 («минутные полнее») верно относительно `final_v6`, но **не относительно `raw`**: сам код проекта и цифры 2014–2015 от пересборки не меняются (RV: max |Δ| = 5,5·10⁻¹⁷).
3. Главу 3 (п. 4): GARCH-скрипты `moex_volatility/scripts/garch_10min*.py` берут `final_v6/candles_10m/stocks` (стр. 34, 33, 43, 34), загрузчик `moex_volatility/src/data/loader.py` по `configs/paths.yaml:11` — `dataset_final/01_stocks/candles_10m` — тот же файл байт в байт. То есть 10-минутки главы 3 — из того же неполного parquet; по Ж-116 п. 1 — отметка в журнале, модели не трогать. (Какие именно модели считали 2014–2016 на этих файлах, я не прослеживал: сказано по коду, не по запуску.)

## 2. Пересборка

Скрипт `scripts/data/peresborka_10m_2014_2015.py`, тест `tests/test_peresborka_10m.py`. Выход (в PR только журнал): `data/regen/candles_10m_2014_2015/{T}.parquet` (17 файлов, 02.05.2014–31.12.2015; в основную копию переносит дирижёр), `sha256.txt`, `sverka.csv`.

Допуск объявлен до счёта: цены |Δ| ≤ 1e-9, объём точно; «полный день» — число баров в обоих рядах равно. Итог: 0 расхождений на полных днях и на всех общих метках, против обоих источников.

Тест (8, проходят): агрегация сохраняет OHLCV (вход не по порядку — open/close по времени); бары вне 09:50–18:50 отбрасываются; мутация «бар 18:50–19:00 вошёл» (окно +10 минут) ловится; дыра не заполняется; сверка ловит подмену объёма и цены, допуск цен работает; константы окна равны `daily_1850`. Мутация сверки: прогон на подмене `volume`/`close` даёт `bad_on_equal_days = 1`.

Расширение: в 1-мин файлах есть 25 торговых дней 02.05–06.06.2014, которых нет в `raw` (там с 09.06.2014). Они вошли в пересборку (все тикеры, вне торгуемого окна 26.08.2014).
