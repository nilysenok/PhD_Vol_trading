## 2. Граф зависимостей и чем продлевается каждый узел

X1 = M^(1−π)·C^π, где M = √(K2·K3), C = cfg8, π = π^(e_d) (`models_v2/s15/de_e1_state.py`). ZB = X1·exp(e_d·(b + a·s_d)) (`models_v2/s16/x1_z_walk.py`).

```
бары SBER ─┬─ N1 календарь (+ сессии IMOEX) и дневной ряд ─┬─ N2 K1 ───────────────────────────┐
           │                                                ├─ rv_d, jshare, цель RV ──────────┤
бары 16 ───┤                                                │                                  ├─ N7 Z(9) ─┐
IMOEX ─────┴─ N3 K2, K3 (рыночный блок: 17 бумаг + IMOEX) ─ N4 M ────────────────────────────┘           ├─ N8 cfg8 ─┐
бары SBER ── N5 склад и X_w5 ─┬─ N6 z (энкодер TCN-w5 2026, 5 seeds, без переобучения) ──────────────────┘            ├─ N10 X1 ─ N11 ZB
                              └─ N9 e_d, s_d ───────────────────────────────────────────────────────────────────────────┘
```

| Узел | Модуль, функция | Входы |
|---|---|---|
| N1 | `models_v2/daily.build_daily` (правило IMOEX); `s10/hp_daily.ticker_daily` → дневной ряд SBER (rv, j, rv_w, rv_m, seg) | бары SBER; сессии IMOEX |

## 3. Календарь, даты и расписание обновлений (из архивного кода)

**Календарь пар:**
- канонические дни SBER — `build_daily(bars, index_days = сессии IMOEX)` на склейке архива и новых баров;
- t⁺ — следующая каноническая строка (`hp_har.target_of`);
- сетка прогнозов — пересечение рядов H ∩ K2 ∩ K3 с конечными положительными значениями (`v7_0_ctrl.aligned`);
- X1 и ZB — на датах X1.

До замка календарь строится **только по столбцу `begin`** новых файлов SBER и IMOEX: считается число баров основной сессии и наличие сессии IMOEX. Цены, объёмы и RV не читаются. Получившийся список дат и **фактическое число пар** n_new записываются в `FREEZE.json`. После замка скрипт открытия строит календарь полным `build_daily`, включая правило `rv > 0`, и сверяет его с замороженным. Если хоть одна дата не совпала — это `↺`-запись в отчёте, и применяется полное правило.

| Узел | Правило обновления (код) | Даты в новом периоде |
|---|---|---|
| K1 | МНК на всех парах s⁺ ≤ d; переоценка **каждый день**; строки — пар ≥ 252 | каждый d |
| K2, K3 | **дневная переобучка** на расширяющемся окне пар ≤ d (`block_job`, `run_days`); ранняя остановка И1: блок — последние 252 пары, эмбарго 1, терпение 100, потолок 3000 деревьев, финальная модель на всех парах (`s4/fit.py`); seed 42. Гиперпараметры И2 **года 2026** — из `k23_meta_SBER.json`, выбраны LOYO по годам ≤ 2025 | каждый d; новый выбор И2 не делается (период < 01.01.2027) |
| Склад и X_w5 | нормировка окна — накопленные суммы сессий ≤ d; `vol_rel` — медиана слота строго до дня | каждый d |
| z (N6) | энкодер TCN-w5 **2026** (5 seeds, обучен на барах < 01.01.2026), PCA — из артефакта. **Не переобучается**: период < 2027 | каждый d |
| M | √(K2·K3) | каждый d |
| cfg8 | первый торговый день месяца (`v6_1_wf.refit_positions`): пары t⁺ ≤ d0; валидация — последние 126 закрытых; λ_g × λ_LB (4 точки); 5 seeds; z всех строк — от энкодера года переоценки (2026) | первые канонические сессии марта … ноября |
| X1: π, η | π обновляется **каждый день** парами, закрытыми к d (t⁺ ≤ d); η = 1/медиана QLIKE обеих моделей по всем закрытым парам | каждый d |
| X1: α | помесячно (первый день месяца в индексе X1) — по последним 126 закрытым парам состояния, решётка {0,01; 0,02; 0,05} | те же даты, что у cfg8 |

| e_d | порог — 99-й перцентиль \|r\| всех баров сессий строго до d | каждый d |

Ожидаемые первые сессии месяцев: 03-02, 04-01, 05-04 (или 05-01, если у IMOEX 1 мая была сессия), 06-01, 07-01, 08-03, 09-01, 10-01, 11-02. Фактические даты записываются в `FREEZE.json` из календаря.

**Начальное состояние на 2026-02-27** (снимок для сверки, а не вход). Бегун пересчитывает всё детерминированно с начала ряда, а снимок служит проверкой. В `FREEZE.json` записываются:
- π₀, π₁, η, α₀, α₁ X1 на d = 2026-02-27;
- λ, b, a ZB на февраль 2026 (переоценка 2026-02-02);
- λ cfg8 февраля по seeds;
- И2 2026 K2/K3.

## 4. Последовательность: прогноз дня d — только по данным ≤ d

**Момент выпуска прогноза** — конец основной сессии SBER дня d (последний бар основной сессии стартует в 18:40 и закрывается в 18:50). Входы дня d:
- бары основной сессии SBER;
- бары основной сессии 16 бумаг и IMOEX дня d (`s4/mkt.py`: «по барам ≤ 18:50 дня d»).

Вечерняя сессия и сессии выходных не входят.

**Сверка архива.** Каждый узел считается на склейке «архив + новые» тем же кодом. Затем все архивные строки сверяются с замороженными файлами — побитно; для torch, XGBoost и LightGBM — с допуском 1e-12, если побитное равенство недостижимо при тех же версиях пакетов. Если узел использует статистику всей выборки, старые значения изменятся — сверка упадёт, и это стоп.

**Тест обрезки** (образец — `hp_har.corrupt_after`) на каждом узле. Бары **всех 18 инструментов** после d0 умножаются на случайный множитель — прогнозы, признаки и состояния на d ≤ d0 обязаны не измениться.

**Цель RV:**
- то же определение (`build_daily`);
- на перекрытии 20–27.02 RV совпала с архивом (F4);
- в открытии RV новых дней строится бегуном и сверяется с `rv_fwd_SEALED.parquet` по общим датам, после замка.

**Энкодер 2026:**
- модули `models_v2/s17/fwd_*` не импортируют `v7_1e_pre.train_encoder`, `v7_1b_sta.compute`, `train_missing`, `fit_pca_past` — AST-тест, класс № 141;
- веса и PCA берутся из артефакта, `content_hash` сверяется с заморозкой;
- z дней 2026-01-05…02-27, пересчитанные бегуном, равны z артефакта.

**Порог e_d** — по барам строго до d (`past_end(p) = p`; мутация `p + 1`).

**Переоценки** — только в даты из `FREEZE.json`. Бегун отказывает, если фактическая дата переоценки не совпала с замороженной.

## 5. Оценка: семейство гипотез, статистика, правило вывода

### 5.1 Семейство: 7 односторонних гипотез «ряд A лучше ряда B»

| № | Гипотеза | Смысл |
|---|---|---|
| H1 | X1 < K2 | основная цель: гибрид против самостоятельного XGBoost |
| H2 | X1 < K3 | основная цель: гибрид против самостоятельного LightGBM |
| H3 | ZB < K2 | основная цель |
| H4 | ZB < K3 | основная цель |
| H5 | ZB < X1 | добавочный эффект специализированной поправки |
| H6 | X1 < K1 | против HAR-J (базовый бенчмарк) |
| H7 | ZB < K1 | против HAR-J |

**Почему одно семейство из 7.** На новом периоде делаются ровно эти 7 проверок, отбора на нём не было. Одно семейство не даёт выбрать «лучшего» кандидата: каждый кандидат отчитывается по всем своим сравнениям (Ж-248 п. 5).

**Поправка** — Холм по m = 7, α = 0,05. Она контролирует FWER при любой зависимости гипотез, а здесь они сильно положительно зависимы: X1 и ZB совпадают вне дней e_d = 1. Это продолжение правила плана Z, раздел 8 («Холм по числу кандидатов проверки»), расширенное на основные цели по Ж-248 п. 5. Холм по N программы (749 и т. п.) здесь не применяется: новый период — отдельный раунд с одним открытием.

### 5.2 Статистика

- **Окно** — все общие пары пяти рядов: t⁺ ∈ (2026-02-27; 2026-11-10], n_new — из `FREEZE.json`.
- **Ряды.** Отчитываются: абсолютный QLIKE каждого ряда (`models_v2/metrics.qlike`, среднее по парам), точные первая и последняя даты d и t⁺, n.
- **Δ_AB** = 100·(Q_A − Q_B)/Q_B — в % QLIKE базы B. Одно определение для всех таблиц нового периода (Д7).
- **Основной p** — DM односторонний «A лучше» (`models_v2/s13/v6_1_eval.dm_one`: Ньюи–Уэст, лаг 5, d = QLIKE(B) − QLIKE(A)).
- **Интервал** — блочный бутстрап средних разности (`models_v2/s5/d/stats_d.block_idx`, `boot_means`): 90 % двусторонний (соответствует одностороннему 5 %), 2000 повторов, seed 0, **блок 10**.
  - Обоснование блока: автокорреляция дневных разностей потерь семи пар на архиве — лаг 1 от −0,01 до 0,32, средняя по лагам 6–20 ≤ 0,04 (`power.py`).
  - Блок 10 покрывает зависимость и окно Ньюи–Уэста (лаг 5) с запасом и даёт ≈ 18 блоков при n ≈ 180. Блок 20 дал бы ≈ 9 блоков и грубые перцентили.
  - На мощность выбор блока практически не влияет (`POWER.csv`, строки block 10 и 20).
  - Объявлено одно значение — 10; других интервалов в отчёте нет.
- **Холм** — `models_v2/s3/dm.holm` по 7 p (порядок H1…H7), без дополнения до N.

### 5.3 Правило вывода (по каждой гипотезе отдельно)

- **«Подтверждено на новом периоде»** — p Холма (m = 7) < 0,05. Одностороннее малое p означает Δ_AB < 0.
- **«Не подтверждено на новом периоде (n = …)»** — иначе. Это не «опровергнуто»: рядом обязательно стоят Δ, интервал и строка мощности из `POWER.csv` для фактического n.
- **Без выбора лучшего.** Таблица всегда содержит все 7 строк в порядке H1…H7. Вывод о кандидате — только по его строкам. Фраза «лучший гибрид на новом периоде» запрещена.

### 5.4 Только описание (без вывода, после таблицы семейства)

## 7. Репетиция (Ж-248 п. 6) — до заморозки, только на архиве

- **Что.** Для каждого из 38 дней выпуска прогноза пар с t⁺ в 2026 году (d = 2025-12-30 … 2026-02-26) бегун запускается на данных, обрезанных по моменту выпуска: бары всех 18 инструментов с `begin` ≤ d 18:40 и дни ≤ d (`v7_0_seq.truncate`).
- **Сверка по каждому узлу** (`docs/otchety/harj_fwd/REHEARSAL.csv`, строка на день × узел):
  - прогнозы K1, K2, K3, M, cfg8, X1, ZB дня d;
  - состояния: π₀, π₁, η, α X1; λ, b, a ZB; λ cfg8 по seeds; И2 года;
  - рыночные признаки дня d — 17 столбцов BASE + IDX против строки `dz0` архива;
  - z дня d против артефакта;
  - e_d, s_d;
  - календарь переоценок: 2026-01-05, 2026-02-02 и декабрьская 2025-12-01 для d = 2025-12-30.
- **Допуск** — 0 (побитно). Если нельзя — заранее объявленный 1e-12 отн. только для узлов torch, XGBoost и LightGBM; причина записывается.
- **Доступность к выпуску.** Для каждого d и каждого из 17 инструментов (16 + IMOEX) — максимальный `begin` бара, вошедшего в признаки дня d, ≤ d 18:40. Нет бара инструмента в день d — NaN, как в архиве, со счётчиком. Мутация «бар вечерней сессии d или бар d+1 в рыночном блоке» ловится.
- **Расхождение** — разбор причины до записи заморозки; архивные ответы не подгоняются. Если причина в недетерминизме пакета — фиксируется допуск и пакет; иначе стоп.
