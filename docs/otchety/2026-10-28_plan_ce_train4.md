## 3. Строгое исполнение дневной позиции (контракт листа CE-1, формат `strogoe` v 1.0)

Позиция пары `pos[t]` решена на close t (данные ≤ 18:50 t). По Ж-086 п. 1–2, 4 она исполняется по **open 5-мин бара 10:00 дня t+1**: вход `rynok` — open d+1, выход по сигналу и τ — open x+1. Тогда доход строки t (интервал close t → close t+1) раскладывается на две ноги:

- ночь: `n[t] = ln((o10[t+1] + D·0,87)/c[t])` — держит **прежняя** позиция `pos[t−1]`; D — дивиденд дня гэпа t+1 (`dividendy.gap_divs`, НДФЛ 13 %, Ж-060);
- день: `dn[t] = ln(c[t+1]/o10[t+1])` — держит **новая** позиция `pos[t]`.

`g_strog[t] = pos[t−1]·n[t] + pos[t]·dn[t]`; стороны `|pos[t] − pos[t−1]|` в строке t; занятость на 18:50 дня t `noch[t] = |pos[t−1]|` (новая позиция входит только утром). Тождество: при `o10 ≡ c` (синтетика) строгий путь обязан совпасть с `Engine.port` побайтно — это и связь с якорем s9.

- **o10** — open 5-мин бара, начинающегося в 10:00 (`exec_e_vremya.bar_at(day, 600)`); бара нет — запасное правило толкования [Ж-086 п. 4] (первый бар позже 10:00 того же дня; иначе 10:00 следующего торгового дня). Число подмен — в манифест.
- **Граница окна пары (аналог Н5).** Позиция, которую держат в ночь с последнего дня окна T, закрывается по o10[T+1] с комиссией выхода; решение close T не исполняется (его исполнение было бы за окном).
- **Плата за шорт (Ж-089).** В строке t: `zaem[t] = s · max(0, −pos[t−1]) · cal[t] / 365`, где `cal[t]` — календарные дни [t, следующий торговый день) (`msp.cal_days`), s = 5 % годовых основная, 0 / 10 / 15 % справочно. Сумма по сделке = s × календарные дни между датой входа и датой выхода; шорт внутри дня (вход и выход в один день) на 18:50 не держится → 0; пятница → понедельник → 3 дня; лонг → 0. «Стоимость короткой позиции» — вес позиции в долях капитала на 18:50 (❓ 7).
- Ставка на свободный капитал — `Engine._finish(…, noch_)` (Ж-065 п. 3), без новой ставки.

API (новый модуль `fastbt/strogoe.py`, `V = "1.0"`):
```
def o10_ryad(eng, days_by_ticker) -> tuple[np.ndarray, dict]          # [тикер, бар] open 10:00 d+1 и счётчик подмен
def nogi(eng, o10, div) -> tuple[np.ndarray, np.ndarray]                # (n_row, dn_row) по строкам Engine
def port_strogiy(eng, pos_row, comm, zaem=0.05, nogi=None) -> pd.DataFrame  # колонки Engine._finish + zaem, noch
@contextmanager
def patched(eng, nogi, zaem=0.05)                                       # Engine.port(pos, wgt=None) → port_strogiy; иное — ValueError
ISPOLNENIE = {"vhod": "open1000_d1", "vyhod": "open1000_x1", "v": "1.0"}  # пишется в строку ledger_ce (раздел 5)
```
`patched` нужен, чтобы `konveyer_bcd`, `shag_c.evaluate`, `fast_kontrol` шли **тем же кодом**, а менялось только исполнение (Ж-088 п. 2 «тем же конвейером»). Вызов `port` с `wgt` (P1) под `patched` — отказ, а не молчаливый close.

## 4. Как C, D, E строятся поверх A_strogaya и как пересчитываются поверх A′

**Поверх A_strogaya (этапы CE-5, CE-7):**
- C, D: позиция = `A_row × g` (как в s9), исполнение — `strogoe` под `patched`. к2 — сдвиг g, исполнение строгое (CE-3); к3 — A_strogaya без S5/S6; база для Δ — A_strogaya (g ≡ 1). Смена затвора на close d исполняется по open 10:00 d+1 — это и есть «выход по сигналу на open x+1» для затвора.
- E: длинная сторона A_strogaya — через `exec_e2` с правилами E: E0 и E2 входят `rynok` по open 10:00 d+1 (вместо close d), E1 — лимит по барам d+1 (как было); выход по смене позиции A и по τ — `t_vyhod = open2`; тейк/стоп E2 — по 5-мин барам (не close). E1 `f = zakrytie_d1` (вход по close d+1) — **справочная** строка (❓ 3). Короткая сторона — строгой формулой раздела 3 с платой за шорт. Тождество: **E0 при q = 0 ≡ A_strogaya** (≤ 1e-12 по дневному excess; аналог мутации № 28).

**Поверх A′ без нового отбора (Ж-088 п. 2), лист CE-9:**
- Точки C/D/E, выбранные на A_strogaya, замораживаются файлом `docs/otbor/ce_tochki_A_strogaya.json` (sha256 в журнал до пересчёта). Пересчёт поверх A′ берёт **только** этот список; отбор не вызывается; к2, к3 и лестница — в тех же точках. Строки пересчёта идут в ledger с `baza = "A_prim:<sha>"`, `istochnik = "perescet"`, в N не входят. Мутация: «пересчёт заново выбирает точку» → тест красный (множество точек ≠ замороженному).
- Если исход этапа 1 — (в) (A′ = A_strogaya), пересчёт не нужен: строки на A_strogaya и есть строки на A′.
- Если A′ ≠ A_strogaya, A′ — портфель конфигураций Sk на `exec_e2` с весами Ж-090 п. 2. Умножить сделки на g нельзя. Умолчание (❓ 2): затвор C/D действует на каждую компоненту Sk как фильтр входа (`filtr`-маска «вход запрещён» при g = 0) плюс принудительный выход по open 10:00 следующего дня, если затвор закрылся при открытой позиции; при g = 0,5 (C2W, D7) — вес сделки × g. Веса A′ — по рядам компонент после затвора, тем же правилом Ж-090 п. 2. E поверх A′ — по Ж-047 п. 1: та же конфигурация A′ с источником σ, заменённым на σ̂ (константа → наивная → HAR-J (б) → гибрид), без перебора (N = 4 ступени).

- `osnovnaya` — функция **только параметров** (`ispolnenie` в ключе), не исходов: True ⇔ ни одно поле `ispolnenie` не содержит `close`. Строка без `ispolnenie` — `ValueError`, не «основная».
- Читатель (`Chitatel_ce`) отказывает: строка `osnovnaya = true` с `close` в `ispolnenie`; разные `kod`/`vhody` в одной матрице; годы вне окна; ряд за 2020+ при `period = train_ce`.

**Тест «любая точка C/D/E с close в основной строке — красный»** (пишет тестировщик T-CE до кода, `tests/test_ce_bez_close.py`):
1. **Статический.** Перебрать все точки `C_setka_e3`, `D_setka_e3`, `E_setka_e2` × ступени лестницы × комиссии → ключ строки → если `osnovnaya`, в `ispolnenie` нет `close`. Отдельно: E1 `f = zakrytie_d1` даёт `osnovnaya = false`.
2. **Динамический на синтетике** (open 10:00 ≠ close, известный ответ): основная строка C на маске с одним переключением даёт доход строгой формулы раздела 3. Мутации, которые обязаны ронять тест:
   - М-CE1: `port_strogiy` берёт весь `lr[t]` на `pos[t]` (исполнение по close d);
   - М-CE2: `patched` пропускает вызов `port` без подмены (конвейер считает по close);
   - М-CE3: E0/E2 входят по close d (E0 q = 0 ≠ A_strogaya);
   - М-CE4: τ у E выходит по close x;
   - М-CE5: к2 считается старым ядром `shift_sharpe` (close) при строгой точке;
   - М-CE6: на конце окна позиция закрывается по close первого дня после окна, а не по open 10:00.
3. **Читатель.** Строка с `osnovnaya = true` и `vyhod = close_x` → `Chitatel_ce` отказывает.

Мутации платы за шорт (Ж-089, три случая владельца): шорт внутри дня → 0; пятница → понедельник → 3 календарных дня; лонг → 0 всегда. Плюс М-CE7: плата берётся с шорт-экспозиции по барам (внутридневной шорт платит) → тест «внутри дня = 0» красный.
