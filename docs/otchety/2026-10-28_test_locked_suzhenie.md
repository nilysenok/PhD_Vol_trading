## 3. Процедура (исполнитель — скрипт `scripts/dannye/suzhenie_test_locked.py`, пишет kodir, запускает дирижёр после «да»)

### Ш0. Условия старта
- «да» владельца с датой и ссылкой на этот документ (SHA файла — в журнал);
- нет запущенных счётов, читающих `data/`;
- свободного места — не меньше суммарного размера классов T и M по манифесту Ш1, плюс 10 %.

### Ш1. Манифест «до» — без открытия значений
По каждому файлу классов T, N, M:
- путь, размер, mtime, sha256 — sha читает байты, но не разбирает их;
- для parquet — схема (имена столбцов) и число строк из метаданных;
- min и max **только столбца даты**, по статистике row-group. Если статистики нет — чтением одного этого столбца.

Столбцы значений не читаются и не выводятся. Выход — `docs/resheniya/manifest_test_locked_do.tsv`: только имена, размеры, sha, счётчики, граничные даты. Хэш манифеста — в журнал.

### Ш2. Классификация файла по дате
1. **Дата строки** — день, для которого значение используется: торговый день бара, целевой день прогноза. Не день выпуска прогноза (Д3, point-in-time).
2. **Строки с горизонтом h** (прогноз RV на h дней, цель на окне): строка идёт в Z2, только если всё целевое окно ≤ 31.12.2024. Иначе — в Z3 (как № 15 `mutations.md`, сдвинутый на границу 2025).
3. Итог по файлу:
   - (а) все строки < 2025 → целиком в Z2;
   - (б) все ≥ 2025 → остаётся в Z3;
   - (в) смешанные → резка Ш3;
   - (г) нет столбца даты (json, pickle, модели) → остаётся запечатанным, перечисляется в отчёте;
   - (д) `OPENED_*.json` — история открытий, не трогается.
4. Имена столбцов даты — белый список: `date`, `Date`, `datetime`, `timestamp`, `TRADEDATE`, `begin`, `d0`. Другого имени нет → (г).

### Ш3. Резка смешанных файлов — строки по дате, без чтения значений
1. `pyarrow.dataset` с фильтром по столбцу даты. Пишутся две части, исходник переносится целиком (не удаляется) в `test_locked/_ishodnye/<прежний путь>`:
   - `<база>__t1.parquet` — строки 2022–2024 (база — имя без `_test`, чтобы не ловилось правилом `_(test|…)`) → Z2;
   - `<база>__h25.parquet` — строки ≥ 2025 → Z3.
2. Кроме того, у файлов M строки ≤ 2021 сохраняются на старом пути. На этом пути лежит усечённая копия ≤ 31.12.2024, код и фильтры не меняются.
3. Проверки на файл (скрипт печатает только их):
   - строк в частях в сумме = строк в исходнике;
   - max даты части Z2 ≤ 2024-12-31, min даты части Z3 ≥ 2025-01-01;
   - схемы совпадают;
   - срез ≤ 2021 усечённой копии совпадает с тем же срезом исходника: сверка sha по сериализованному срезу, без вывода значений.
4. Часовой пояс — МСК, граница — 01.01.2025 00:00.

### Ш4. Хэши «после» и хэш hold-out
- `docs/resheniya/manifest_test_locked_posle.tsv` — та же форма, что «до»;
- сохранение: каждая строка «до» = сумма своих частей «после», sha исходника в `_ishodnye` = sha «до»;
- **хэш данных hold-out** (Ж-112 п. 1) = sha256 отсортированных строк манифеста по Z3 (путь, размер, sha). Одно число — в журнал.

### Ш5. Замок на 2025+
1. `zamki.json`, `zakryto_chtenie`:
   - остаются `(^|/)test_locked(/|$)` и `OPENED_*`;
   - добавляется `__h25\.`;
   - `^data/regen/test1_2022_2024/` — читается только при открытом раунде реверса (хук сверяет последнюю строку `docs/reverse_log.md`: «раунд N открыт», N ≤ 5).
2. Скрипт открытия hold-out — отдельный лист, после финальной точки:
   - замок `test_locked/holdout_2025/OPENED_HOLDOUT.json` через O_CREAT|O_EXCL до чтения;
   - отказ без «да» владельца со ссылкой на SHA предрегистрации;
   - отказ при несовпадении хэша hold-out из журнала.
