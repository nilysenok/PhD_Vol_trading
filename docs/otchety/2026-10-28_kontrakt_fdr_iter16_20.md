## 1. ФДР внутри дня и выход лимиткой (Ж-065 п. 3)

### 1.1 Как устроено сейчас (адреса — база f6099c5)
- Ставка на свободный капитал начисляется в одном месте — `s9.Engine._finish` (`s9.py:609`): `fdr = max(0, 1 − cap·exp_)·rf·cal`, где `exp_` = среднее `expo` по строкам даты. Плечо — `s9.py:611` (`mg`). При cap = 1 и L = 1 оно равно нулю.
- Этап 1 подаёт `expo` из `etap1_run.run_e1` (`etap1_run.py:61`): `expo = (1 − res.free)·w`. `res.free` строит `exec_e.run` (`exec_e.py:96`): `free[t] = 1 − used(t+1)/nb`. Это доля 5-минутных баров **следующего дня**, которые позиция провела в рынке.
- Следствие: если сделка открыта лимитом и закрыта стопом внутри дня d+1, то ночь d частично считается занятой: ставка за [d, d+1) срезается на долю баров d+1. Ночь d+1 свободна. Ночь, после которой выход был внутри дня, частично свободна, хотя позиция на 18:50 была открыта.
- A и «A только Sk» (`Engine.port`) торгуют только по close, `exp_ = |pos|`. Это уже правило «свободен на 18:50, T+0».
- Выход по сигналу и по времени — рынком по close Н6 дня решения (`exec_e_run.py:122`, `:124`). Лимитного выхода нет.

### 1.3 Формулы
Обозначения: строка t — интервал [close t, close следующего торгового дня). `rf·cal` — ставка ЦБ / 365 × календарные дни [t, t_next) (`msp.cal_days`). У сделки tr: вес w_tr (`w[tr.d_sig]`, у ансамбля — `× mag`), `entry_day`, `exit_day` (None — открыта на конце окна). Дни `pusto` входят в диапазоны индексов, позиция на них переносится (как `Result.pos`).

**А. Занятость на 18:50 по тикеру** (`fastbt/fdr.py`, новый файл, чистые функции):
- T+0: `noch0[t] = Σ_tr w_tr · 1[entry_day ≤ t < exit_day]`. Сделка, открытая и закрытая внутри одного дня (entry_day = exit_day), не занимает ни одной ночи. Позиция, открытая по close d, занимает ночь d. Выход по close x освобождает ночь x.
- T+1: `noch1[t] = min(1, noch0[t] + Σ_tr w_tr · 1[t = exit_day])`. Выручка от продажи в день x освобождается вечером x+1, так что ночь x занята (вместе с выходными до следующего торгового дня: `cal` строки x). Покупка забирает деньги сразу, без ночи «в долг». Это худший сценарий: деньги покупки не остаются в ФДР до расчёта. min(1, ·) — слот тикера не больше 1 при перевороте позиции по close.
- По позициям A (`Engine.port`, дробная `pos`): `noch0 = |pos|`. Это совпадает с нынешним `exp_` побайтно. `zakryto[t]` = |pos[t−1]|, если знак сменился, иначе max(0, |pos[t−1]| − |pos[t]|); на первой строке пары — 0. Тогда `noch1 = min(1, |pos| + zakryto)`.

**Б. Ставка портфеля** (`Engine._finish`): `used_fdr = cap · bincount(noch)/cnt`, если `noch_` задан; иначе `used_fdr = used` (старый путь). `fdr = max(0, 1 − used_fdr)·rf·cal`. Плата за плечо `mg` остаётся на старом `used`: при cap = 1 и L = 1 она равна нулю. В худшем сценарии внутридневное плечо платит, как раньше. `total`, `excess`, `excess_gross` — по прежним формулам с новым `fdr`.

**В. Выход лимиткой** (`exec_e_run.Run`, правила — существующие функции `exec_e_rules` с зеркальной стороной −sd):
1. Если в `step` на close d срабатывает выход `signal` или `vremya` и включён `vyhod_lim`, позиция не закрывается. Ставится заявка `xorder = {X, due = j+1, reason}`, где `X = limit_level(−sd, close_d, k, σ̂_d, tick)`. Лонг продаёт выше close на k·σ̂ с округлением к тику в сторону, где исполнить труднее. k — тот же, что у входа точки (`Params.k`).
2. В день d+1 по барам b = 0…: сначала стоп (как сейчас: в худшем сценарии стоп раньше всего). Затем лимит выхода: `limit_mask(−sd, h, l, X, tick)` — только проход на тик сквозь уровень (лонг: h ≥ X + tick), касание не исполняет. Цена — `limit_px(−sd, o, X)`: X или open при гэпе через X. Тейк на d+1 снят: одна заявка на продажу, ОСО. Трейлинг и безубыток обновляются, как сейчас.
3. Не исполнилось к закрытию d+1 — выход рынком по close Н6 d+1 с прежней причиной (`signal` / `vremya`). Позже d+1 выход не переносится. Пока заявка висит, проверки `tau` и сигнала на d+1 не ставят второй выход.
4. Комиссия: исполнение внутри дня — в строке начала интервала (`_row(…, at_close=False)`), выход по close — в строке d+1. Н5: заявка, висящая на последней строке окна, — это открытая позиция и платит выход в последней строке.
5. Счётчики: `Result.x_orders`, `Result.x_fills` (новые, по умолчанию 0). `n_orders` / `n_fills` входа не меняются, поэтому `dolya_ispolneniya_limita` прежняя. Причина исполненного выхода — `"lim"`.
6. С дивидендами (#370): позиция, перенесённая через ночь d→d+1 из-за заявки, получает `dv` и сдвиг стопа, если d+1 — день гэпа. Это уже делает `step` (`s.dv`, `s.sh`), новой ветки не нужно. Тест — §1.5 М-В4.

**Г. Строка v1.1.** Новые поля пишутся, только если включён хоть один флаг: `"v": "1.1"`, `fdr` (`null|t0|t1`), `vyhod` (`net|lim`), `prichiny.lim`, `dolya_ispolneniya_vyhoda` (= x_fills / x_orders). Со всеми флагами выключенными строка остаётся v1.0, байт в байт.

  - «Δ ФДР к базе, % годовых» = разность этих сумм с колонкой «дивиденды»;
  - «Δ mSR к базе» = mSR(excess колонки) − mSR(excess базы) по годам.
- **Что следует из устройства, без счёта.** У A и «A только Sk» все сделки идут по close, поэтому «+ФДР T+0» совпадает с базой побайтно (Г3). Для паспорта A он не считается, в P1 — отдельной колонкой «+выход лимиткой» при T+0.
- **Порядок величины — потолок, не замер.** Ставка ≈ 7,5 % годовых. На один торговый день ставка за [d, d_next) ≈ 0,029 % (среднее cal ≈ 1,4 — оценка). При 100 сделках в год на Sk, весе 1 и 17 тикерах:

- **Это новые стратегии T16–T20, а не фильтры к S1–S6.** У каждой свой вход, удержание и размер; они кандидаты в A′ наравне с S1–S6. Код — новые файлы, `s12/s34/s56`, `etap1_eval.py` и `sweep_drivers.py` не меняются.
- **Точка решения.** Close Н6 дня d, данные до 18:50 d (Н6).
  - `c_d` — close Н6 (`ohlcv_daily_1850.parquet`); для сигналов — ряд с поправкой на дивиденды (#370, Ж-059/060).
  - `r_d = ln(c_d / c_{d−1})`.
  - σ̂_d — `sigma_real` rv22 тикера (RV 10-минуток [09:50; 18:50), известна на 18:50 d).
  - `z_d = r_d / σ̂_{d−1}`.
  - IMOEX: `R_d` — по close 18:50 (`rezhim_e1.imoex_daily`), `Z_d = R_d / sig_mkt_{d−1}` (rv22 индекса, тот же файл).
  - Особенность: σ̂ — внутридневная, без ночного гэпа, поэтому |z| по close-to-close систематически выше. Центр порога остаётся словами владельца; соседи на сетке закрывают сдвиг калибровки.
- **Вход.** Рынком по close Н6 дня входа e ≥ d+1 (Д2): у 16, 17, 19, 20 e = d+1; у 18 — по §2.4.
  - Реализация через `exec_e`: `Params(k=None, tau=τ, b=None, reentry=False, check="bary", tick, stop_touch=True)`.
  - `sig_T[e…e+τ] = сторона`, дальше 0.
  - Событие принимается, только если e ≥ (последний день прошлой сделки тикера) + 2. События во время сделки отбрасываются и сделку не продлевают.
- **Выход.** По времени: close Н6 дня e + τ. В досчёте G4 — σ-стоп k_s по 5-минутным барам. Выход лимиткой (§1) к T16–T20 не применим: вход рынком, уровня нет.
- **Размер** — «сила × 1/σ» (Ж-065): `w = min(1, сила · 0,20 / (σ̂_d · √252))`, `сила = 1 + (x − порог)` в единицах условия (↺ выше). Вес фиксирован на сделку (`w[e]` := вес события d), L = 1, 0,20 — `razmer_ves` по умолчанию.
- **ФДР.** Вход и выход — по close, поэтому при T+0 строки совпадают с нынешним правилом (§1.7). Сетка считается с `fdr = None`; разница возможна только в двух точках досчёта со стопом.
- **Общие мутации** (каждая итерация):
  - вход по close d (`sig_T` без сдвига, Д2);
  - вес по σ̂_{d+1};
  - условие с данными d+1;
  - Д1: у каждого нового ряда (z, Z, Rg, V, U) корреляция с исходной дневной величиной (r_d, объём_d, диапазон_d) при сдвигах −2…+1 — максимум на 0. Первой строкой журнала счёта.
- **Контроли без модели** (§4 п. 2) в N и PBO не входят, пишутся с меткой `kontrol`:
  - (б) циклический сдвиг маски событий по тикеру на ≥ 63 дня, 20 лагов;
  - (а) случайные дни входа с тем же числом событий в тикеро-годе, 20 seed;
  - p = (1 + #≥)/21 ≤ 0,1.

### 2.2 Итерация 16 — пост-шоковый возврат (T16, лонг, N = 38)

- **Оси:** z0 {2,5; 3; 3,5}, m0 {0,5; 1; 1,5}, τ {2, 3, 4, 5} (центр — слова владельца: −3σ, ±1σ, τ 2–5). 36 точек + досчёт k_s {2; 3} в центре плато = **38**.

### 2.3 Итерация 17 — сжатие диапазона и пробой (T17, обе стороны, N = 29)
- **Диапазон:** `Rg_d = (max h_{d−W+1…d} − min l_{d−W+1…d}) / c_d`, h и l — дневные Н6.
- **День сжатия c:** `Rg_c ≤ min Rg_{c−L+1…c} + 1e−12`.
- **Пробой:** первый день d ∈ (c, c+W], где `c_d > H_c = max h_{c−W+1…c}` (лонг) или `c_d < L_c` (шорт). Один пробой на эпизод. Вход close d+1, τ. `сила = 1 + |ln(c_d / граница)| / σ̂_d`.
- **Оси:** W {10, 20, 30}, L {60, 120, 240} (центр 20 / 120 — слова владельца), τ {5, 10, 20} (владелец τ не задал). 27 + 2 = **29**.
- **Мутации:** окно Rg или H_c захватывает d+1; день сжатия считается по min с d+1; пробой по close d+1 с входом в тот же close.

### 2.4 Итерация 18 — закрытие дивидендного гэпа (T18, лонг, N = 14)
