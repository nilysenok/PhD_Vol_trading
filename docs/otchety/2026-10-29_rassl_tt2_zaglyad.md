# Расследование: «стоп бара t знает бар t» (trend_run, tt=2 и др.) — 29.10.2026

**НЕ БЛОКЕР.** Это не заглядывание: исполнение стопа в fastbt, SW и v4 — по close бара t, а стоп бара t строится по данным, которые все известны к close[t]. Находка П3 (PR #589) верна только для модели П3, где стоп исполняется по уровню внутри бара.

Пометка: разработка, данные ≤ 2021, после аудита; код fastbt не менялся. Ветка от `kanon-v22-pereschet` @ 57b78839.

## 1. Где именно

`fastbt/engine_trend.py::trend_run`, бар u (u > e), kind 0 (ATR):
- tt 0/1 (fixed_atr/chandelier), строки 46–47 и 59–60: `tsl = rh[u] − k·atr[u]`; в `rh[u]` входит high[u] (так задумано, `tests/audit_fastbt/test_18_trail_exec.py`, строка 3);
- tt 3 (atr_trail), строки 48–50 и 61–63: `ext = max(ext, high[u])`, затем `tsl`;
- tt 2 (parabolic), строки 51–55 и 64–68: новый экстремум по high[u] → `step += ps` → `tsl = sl + step·(ext − sl)`;
- безубыток, строки 56–57 и 69–70: условие по close[u];
- проверка, строки 87 и 96: `low[u] ≤ sl` / `high[u] ≥ sl`. Выход `tx = u` (строка 107).
- kind 2 (σ, B), строки 72–82: `rh[u]`, `sigma[u]`, `close[u]` — схема та же.

Цена выхода: сделка d занимает [e, x), доход `lr[t] = log(c[t+1]/c[t])` (`fastbt/stats.py::seg_stats_trades`, строки 50–72). Значит, выход по **close[u]**, не по уровню и не по open (`tests/audit_fastbt/test_15_gap.py`, «выход на том же баре по close»).

Легаси: `git show c22a4b36:moex_volatility/scripts/strategies_walkforward.py`, `bt_trend_v3` (строки 756–863). Порядок тот же: трейл/экстремум/безубыток по бару t → `low[t] ≤ sl` → `pos[t] = 0`, цена выхода в журнале `close[t]`. v4 импортирует `bt_trend_v3` из SW (v4.py, строка 44), Шарп — `pos·lr`, где `lr[t] = log(c[t+1]/c[t])` (v4.py, строки 359–372 и 1051–1052). Медленный эталон `fastbt/vyhody_v5_medl.py` — та же договорённость (строка 3).

## 2. Гипотезы и проверки

| Гипотеза | Проверка | Итог |
|---|---|---|
| (а) заглядывание: решение бара t использует данные, неизвестные в момент исполнения | Тест причинности `test_prichinnost_trend_run[tt∈{0,1,2,3} × bth∈{нет, 1}]`: данные после каждого бара k заменены, сделки, решённые к close[k], не изменились; сделка, открытая на k, не закрылась на ≤ k. Мутации «бар t+1 в стопе бара t» (rh, ext tt=2, ext tt=3, close в безубытке) тест ловит | **отброшена** |
| (б) оптимистичный порядок внутри бара (подтяжка по high до касания low, как № 3 `mutations.md`) | Порядок внутри бара влияет на цену, только если исполнение по уровню внутри бара. Здесь исполнение по close[t] при любом пути цены внутри бара, поэтому на цену порядок не влияет; он влияет только на то, *какой бар* закрывает сделку | **отброшена как смещение цены**; остаётся определением правила |
| (в) правило закрытия: «на close[t] посчитать sl_t по OHLC бара t; если low[t] ≤ sl_t — выйти по close[t]» | Решение и исполнение на одном close — та же договорённость, что у входа (`test_21_a_entry_close.py`; Д2 «по закрытию d, если явно объявлено»). Тест воспроизводит: бар, где порядок меняет исход | **подтверждена** |

Воспроизведение (`tests/test_rassl_tt2_zaglyad.py`):
- `test_tt2_stop_po_high_t_srabotal_po_low_t`: вход 100, бар 2 — high 110, low 99, close 105. Текущий код: стоп 102,8, выход на баре 2 по 105 (не по 102,8). По правилу «стоп по t−1» стоп 98,5 — выход только на баре 3;
- `test_bezubytok_po_close_t_srabotal_po_low_t`: безубыток по close[2] = 102 и выход по low[2] = 99,8 на том же баре;
- `test_tt3_maksimum_s_tekushchim_barom`: то же для atr_trail.

**Причина находки П3.** В `fastbt/vyhod_parabolic.py` (#589) стоп исполняется по уровню `min(sl, open[u])` внутри бара (строки 41–42). В такой модели стоп бара u, который знает high[u] или close[u], был бы заглядыванием, поэтому порядок П3 для его модели верный. Но текст ↺ (строки 8–9: «в v4 … заглядывание внутри бара») к v4 не относится: в v4 внутри бара ничего не исполняется.

## 3. Масштаб

Договорённость «стоп по OHLC бара t, выход по close[t]» используют: A (S3/S4, все RM тренда tt 0/1/2; `approach_a`); B (`approach_b._trend_one`, kind 2); C/D (берут позиции A); `sweep_post`, `sweep_sk`, `rm_sqrt_rv`, `ekviv_s9` (через `batch.trades_one`); печать предзащиты v4 (SW `bt_trend_v3`). Утечки нет нигде.

A_strogaya / `exec_e*` устроены по-другому, исполнение по уровню: `exec_e_rules.stop_hit` по open/уровню, а экстремум и безубыток обновляются **после** бара (`exec_e_run.py::_after_bar`, строки 146–154). Для их модели это правильно, находка их не касается.

Оценка Δ (только для расследования). A на train4 (годы метрик 2016–2019, прогрев 2015, `s9.set_period("train4")`, дизайн `designs/final/main.yaml`, комиссия 0,05 %), 17 тикеров. Сравниваются текущий `trend_run` и копия «стоп бара u по состоянию на u−1» (rh/atr/ext/step/безубыток на u−1, обновление после проверки). Копия подменена в `batch` только в скрипте вне репозитория. Шарп годовой, ddof = 1. Δ = текущий − «t−1»:

| | медиана Шарпа, текущий | медиана, t−1 | медиана Δ | среднее Δ | Δ > 0 | портфель 1/17: текущий / t−1 / Δ |
|---|---|---|---|---|---|---|
| S3 | −0,133 | −0,065 | +0,063 | −0,020 | 10 из 17 | −0,055 / +0,030 / −0,085 |
| S4 | −0,552 | −0,521 | −0,009 | +0,050 | 8 из 17 | −0,786 / −0,917 / +0,131 |

Знак Δ меняется, систематического завышения у текущего порядка нет. При утечке был бы систематический плюс. Это один период и сравнение двух равноправных правил, а не размер смещения; статистикой не является.

↺ Оценка без фильтра оборота (`turnover.apply`) и без σ̂: σ̂ для kind 0 не нужна, а `align_sigma` подменена на NaN, чтобы не читать файл σ̂ с историей ≥ 2022. Откат: прогнать через `s9._job` (29.10).
