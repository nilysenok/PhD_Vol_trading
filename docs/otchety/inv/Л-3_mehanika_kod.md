## П. 2. Деньги

**2.1 Капитал, занятый позицией: с какого бара по какой.**
- Вход рынком (`k=None`) — по close Н6 дня d, бар `nb−1`: `fastbt/exec_e_run.py:179-180` (`_decide`) → `_enter` `:44-50`, `i0 = nb`. Day d в занятость не входит: `used[d]` не увеличивается на входе.
- Лимитный вход — заявка на d+1 (`due=j+1`, `exec_e_run.py:171-173`); занят с бара исполнения `b` (`_try_order :184-198`, `_enter(..., i0=b)`).
- Занятость по барам: `used[i] += b + 1 − i0` в `_exit` (`:56-65`), на переносе через close — `used[i] += nb − s.i0` (`:151-154`). Выход внутри дня на баре b считает занятыми бары `i0…b` включительно; выход по close — весь день до последнего бара.
- Строка t = интервал [close t; close следующего торгового дня): `free[ix[j−1]] = 1 − used[i]/len(days[i].c)` (`fastbt/exec_e.py:100-103`), `expo = (1 − free)·w` (`fastbt/etap1_run.py:66`). То есть доля баров следующего дня, не календарное время. Открытая на последней строке окна: `free = 1 − |pos|` (`exec_e.py:104-105`).
- У якоря (все сделки по close, `k=None`, `check=zakrytie`) занятость — `|pos|` целиком (`etap1_eval.py:56-59`, docstring `etap1_run.py:11`).

**2.2 Ставка на свободные деньги: с какого момента; выход 15:00; отсечка 18:40/18:50; календарные дни.**
- База (`fdr=None`): `fdr = max(0, 1 − cap·exp_)·rf·cal`, `rf = kr/365`, `cal = msp.cal_days(dates)` — календарные дни [d, d_next): `fastbt/s9.py:496-497, 612-616`; `_Mini` (оценщик этапа 1) то же — `fastbt/sweep_sk.py:36-40`; `fastbt/msp.py:44-56`. Пт→пн = 3 дня на строке пятницы.
- Выход по close x: строка x−1 теряет ставку за долю дня x, строка x получает ставку на всю ночь — ставка со строки x, т.е. «с вечера выхода», docstring `exec_e.py:11-13`. Выход внутри дня (стоп/тейк на баре b): свободна доля баров `1 − (b+1−i0)/nb` дня x, ставка идёт по этой доле на весь календарный интервал строки x−1 (`exec_e.py:100-103`). Выход в 15:00 как отдельное время в коде **нет**: есть бар 5 мин, к ставке приводит доля баров. Отсечка: окно баров `09:50–18:50`, close Н6 — последний 10-мин бар с началом < 18:50 (`fastbt/daily_1850.py:32-33, 46`; 5-мин `bars5m.py:33`). 18:40 как отсечка в коде **нет** (бар 18:40 входит в день и покрывает аукцион закрытия, `daily_1850.py:11-12`; 5-мин бар 18:40–18:45 структурно пуст, `bars5m.py:12-13`).
- Режимы ФДР внутри дня: `Evaluator(fdr="t0"|"t1")` — `etap1_eval.py:87-92`; занятость на 18:50 `noch` — `fastbt/fdr.py:16-36`; в ставке `used_fdr = cap·noch_` — `s9.py:615-616`, `port_rows(noch=…)` `:596-610`; в оценщике `etap1_eval.py:174-175`. Без `fdr` — ставка по доле баров (выше).

**2.5 Деление капитала между тикерами и стратегиями; приоритет, лимит позиций; встречные сигналы.**
- Тикеры: равный слот на строку — `r = Σ net / cnt`, `cnt` — число строк (тикер×дата) на дате: `s9.py:605-610`; `_Mini.cnt` `sweep_sk.py:35`; `Evaluator._engine` `etap1_eval.py:152-165`. Знаменатель — число торгующихся в этот день тикеров (дни остановки не дают нулей: `tests/audit_fastbt/test_08_halts.py:1-3`).
- Вес на сделку: `w = 1` при `razmer=ravnyy`, иначе `min(L=1, цель/(σ·√252))` (`etap1_eval.py:144-146`, `rezhim_e1.py:30-46`); фиксируется на сделку (`etap1_run.py:10, 60-61`).
- Стратегии: Оценщик этапа 1 считает **одну** Sk (`Evaluator(sid, …)`, `etap1_eval.py:87`), стратегии не смешиваются. В A (`s9.Engine`) строка = пара (тикер, стратегия), пары получают равный вес `EW по парам` (`s9.py:446-501`, `msp.py:107-111`).
- Приоритет, лимит числа позиций, общий бюджет на сделки: **нет в коде** (`grep max_pos|prioritet` — только `reestr_otbora.PRIORITET`, это приоритет режима поиска, не сделок).
- Встречные сигналы разных S по одному тикеру: **не сворачиваются** — каждая пара (тикер, S) имеет свою позицию, комиссию и ставку по `|pos|` (`s9.py:569-582`: `dp` по паре, `exp_ = Σ|pos|/cnt`). Свёртка (нетто) есть только в `msp.portfolio(agg="ticker")` (`msp.py:111-113`), этап 1 её не использует.

**2.6 Ставка при экспозиции > 100 % (`mg`).**
- `mg = max(0, used − 1)·(kr + 0,02)/365·cal`, `total = r + fdr − mg`: `s9.py:617-619` (то же `msp.py:138-139`). Доплата — ключевая + 2 п.п. (константа `0.02`).
- В этапе 1 экспозиция ≤ 1: вес `≤ L = 1` (`rezhim_e1.py:30,46`; `etap1_eval.py:144-146`) и слот на тикер = 1/cnt, поэтому `mg = 0` всегда. Проверка в #401 — остановка при `mg ≠ 0` (`pasport_fdr.py:proverka_mg`). Сценарий «маржа 20 %» (`cap_share=0.2`) — `fastbt/margin.py:22, 38-41`, к этапу 1 не относится.

## П. 4. Исполнение по коду

**4.1 Касание или проход на тик.**
- Стоп: `stop_touch=True` в сетке — стоп при касании `l ≤ S` (`exec_e_rules.py:65-69`; `etap1_eval.py:65`); якорь — `stop_touch=False`, `l < S`.
- Тейк и лимитный вход: при заданном `tick` — только проход на 1 тик сквозь уровень (`exec_e_rules.py:72-78, 87-91`); `tick=None` — строго сквозь (`h > T`, `l < L`). В сетке этапа 1 `tick = inp.tick[t]` (`etap1_eval.py:64`).
- Цена: уровень или open при гэпе (`exec_e_rules.py:65-69, 72-78, 94-96`). Стоп раньше тейка в одном баре (`exec_e_run.py:104-110`).
- Внутри бара экстремум/безубыток обновляются после бара (`exec_e_run.py:88-94`). Вход и тейк на баре входа: тейк в баре входа не проверяется (`exec_e.py:18`), стоп — проверяется (`exec_e_run.py:193-195`).
- Родные выходы Sk (в якоре) — дневной движок: стоп/тейк по `low/high` дня, вход/выход по close (`fastbt/engine.py:4-6, 115-126`), тика нет.

**4.2 Шаг цены и лот; округление лимитной цены.**
- Шаг цены вычислен из данных: максимум по годам окна от минимальной положительной разности различных цен OHLC 5-мин баров (`etap1_data.py:31-38`, комментарий о консервативности `:6-7`). Не из ISS; шаг по ISS **нет в коде**.

- Лот: **нет в коде** (размер — доля капитала, цены дробные, штук нет).

**4.3 Объём в баре и доля участия.** `volume` в движке исполнения не используется (`grep volume fastbt/exec_e*.py fastbt/etap1_run.py fastbt/etap1_eval.py` — пусто; в `etap1.py:65` объём читается только для сигналов Sk). Ограничение на долю участия — **нет в коде**: заявка исполняется целиком, если цена пересекла уровень.

**4.4 Аукционы, укороченные дни, остановки.**
- Аукцион закрытия: close Н6 — close последнего 10-мин бара с началом < 18:50 (`daily_1850.py:11-12, 46`); 5-мин бар 18:40–18:45 структурно пуст, сделка аукциона печатается минутой 18:45 (`bars5m.py:12-13`). Исполнение «по close» идёт по цене этого бара, отдельной модели аукциона **нет в коде**.
- Аукцион открытия: окно 09:50–18:50 включает предоткрытие (`daily_1850.py:32`, `bars5m.py:33`); вход на d+1 по лимиту может исполниться в баре 09:50 на любой цене бара — **нет в коде** отдельного правила.
- Дискретные аукционы: **нет в коде**.
- Укороченные дни: **нет в коде**; бары, которых нет, дают `pusto` (`bars5m.py:5, 70`; `exec_e.py:5-6`).
- Остановки/дни без баров: день `pusto` выпадает из ленты, позиция переносится, доходность паузы — на последнюю строку до неё, в τ день не считается (`exec_e.py:4-6`, `exec_e_run.py:17`; тест `tests/audit_fastbt/test_08_halts.py`).
- Плохие бары (пусто/NaN/≤0) — `ValueError` (`exec_e.py:83-89`).

Дополнительного штрафа сверх комиссии **нет в коде**. Комиссия `comm` за сторону: `exec_e_run.py:44-50, 56-65`, в портфеле `net = g − sides·comm` (`s9.py:604`); значение по умолчанию 0,0004 (`etap1_eval.py:87`, `etap1.py:126, 141`); для 0,035 % — аргумент `commission=0.00035` (набор `T1_COMMS_V2`, `s9.py:106`).

## П. 6. Учёт результата

**6.1 Ряд для mSR.** Дневной `excess = total − rf·cal` (`etap1_eval.py:187-190`; `s9.py:621`), где `total = r + fdr − mg` — PnL позиций за вычетом комиссии, **плюс ставка на свободные деньги**, минус ставка на весь капитал. То есть со ставкой на свободное и с вычитанием ставки (избыточная). `mSR = mean·252/mVaR₉₅` Cornish–Fisher, `ddof=1`, `nan` при mVaR ≤ 0 (`metriki_e.py:55-61`); год по календарному году строки (`split_years`, `etap1_eval.py:46-49`); `tselevaya = min(mSR по годам)` (`etap1_eval.py:199`, `etap1_poisk_vorota.py:52-58`). Годовой Шарп — `sr_dnevnoy·√252` (`metriki_e.py:32-36`).
**6.2 Агрегация по тикерам.** Среднее по строкам тикеров на дату (см. 2.5): `s9.py:604-610`; тикеры без бара в дату не дают нулей. Границы окна — правило Н5 (`etap1_run.py:7-9`).
**6.3 Определения.**
- N в DSR — число уникальных точек за все периоды в `Ledger` (`etap1_poisk_vorota.py:35-49`; `docs/resheniya/tolkovaniya.md:75-76, 120`); DSR — `sweep_drivers.expected_max_sharpe` (`sweep_drivers.py:129-133`), справочно `etap1_data.psr_dsr` (`:103-113`, `var SR` по столбцам M).
- PBO — CSCV, `NBLK = 8` (`etap1_poisk_vorota.py:17, 199-200`; `sweep_drivers.py:147-153`), ворота `PBO_MAX = 0,2`, `MIN_SDELOK = 30`, `TIE = 0,05`, `WIN = 126` (`:17`).
- Плато — точка не хуже соседей более чем на `PLATO_NET = 0,1` по целевой; «≥ 3 положительных соседа в сумме и ≥ 1 на оси» (`:109-138`).
**6.4 Якорь s9.** `etap1.anchor_s9_diff` — макс |Δ excess| режима «якорь» против `SkEvaluator.pnl` (= `ekviv_s9.run_sk`), годы 2018 и 2019, комиссия по умолчанию 0,0004; ворота `≤ 1e-12` (`etap1.py:126-138, 150-154`); тест `tests/test_etap1_run_yakor.py`, `tests/test_exec_e_anchor.py`, `tests/test_dividendy_yakor.py`.
**6.5 Ключи кэша (Д5).**
- etap1: `E1Inputs.digest()` = `cache.key("etap1_inputs", …)` от σ, баров, close Н6, режима, событий, тика, ставки (значения и даты ряда), дат тикеров, дивидендов `div`, `DIV_NALOG`, ряда Sk (`series_digest`: даты, O/H/L/C, объём скорректированных баров) и **хэша всех исходников `fastbt/*.py`** (кроме `tests`) — `etap1.py:51-56`; `cache.py:22-44`. Строка оценщика пишет `kod` и `vhody` (`etap1_eval.py:208-209`).
- **Пробел:** комиссия не входит в `E1Inputs.digest()` (она аргумент `Evaluator.__init__`, `etap1_eval.py:87`); в строке она есть как `comm_pct` (`:207`), но ключ `Ledger` — `(pkey(params), period)` без комиссии и без хэша кода (`etap1_poisk_vorota.py:31-45`). Пересчёт на 0,035 % даст тот же ключ ledger, если ledger переиспользован между экземплярами `Evaluator`.
- s9: `s9.cache_key()` = sha1 от `code_hash`, `MAIN_YAML`, файлов σ-источников, `OHLCV`, `CORP`, `dividendy.digest()`, при `SCOPE != dev` — границ периода (`s9.py:397-410`). **Ставка ЦБ в ключ s9 не входит** (`docs/otchety/2026-10-28_stavka_2013_2017.md`, п. 8); комиссия — тоже нет (применяется в `port`, не в кэше A).
- 5-мин бары: `bars5m._key` — хэш CSV периода, кода, тикера, периода, окна (`bars5m.py:23-24`, `_key`).
