**Полное описание финальных дизайнов.** Во всех трёх дизайнах схема V0: одна компонента, без смешивания с HAR-J, без усадки (L0). Поправка Б0.1 — множитель F = exp(s²/2). На валидации s² оценивается вне выборки (оценка шага t−1), на тесте шага k — оценка шага k.
- **h=1.** Модель — XGBoost B v2b: ЛГК-100 с последовательным отсечением 100 → 50 → 25 → 15, max_bin 255. Признаки — `features_pit_v2`, цель — `rv_target_h1`. Нога top5 — среднее прогнозов RV пяти лучших точек шага на шагах 1–6. Топ-5 на шагах 7–9 не строится, поэтому там берётся точка шага 6, как в `sigma_pred_h1_v2`. Оценка s² — sm: дисперсия объединённых остатков ln трёх последних val-лет. Это тот же дизайн, что зафиксирован владельцем в 18:50 для σ_pred(h=1). Тестовый прогноз совпадает с `sigma_pred_h1_v2.parquet` до 0,1%.
- **h=5.** Модель — обёртка уровня 2: среднее V9-LightGBM и V9-XGBoost по RV, до поправки. V9 — бустинг на ln RV − ln HAR-J (MSE), Д8.12 (ln HAR-J как признак), блок Д7 (`features_pit_v2_d7_h5`), точка optuna-30 из `L2_h5`. Цель — `rv_target_mean_h5`. Оценка s² — smrob: (1,4826·MAD)² по объединённым остаткам трёх val-лет. Поправка ставится к усреднённому прогнозу, как в `wrap_v9.py`.
- **h=22.** Модель — V9-XGBoost из поиска `L2_h22` (optuna-30), нога seeds3: среднее seed 42/43/44 лучшей точки. Цель — `rv_target_mean_h22`. Оценка s² — smrob. Это не LightGBM linear_tree: в рейтинге уровня 2 он был победителем, а здесь правило выбора гибрида поставило его ногу single/V0_LGB/B-sm на 5-е место из-за c2.
- Множители F по шагам 1–9: h=1 (sm) — 1,22–1,46; h=5 (smrob) — 1,11–1,25; h=22 (smrob) — 1,08–1,25. Ни один не больше 2, по М3 объяснений не требуется.
- **Проверка s² для V9 (исправление не нужно).** В файлах `L2_h*` колонка rv_pred содержит итоговый V9 (ln HAR-J + коррекция бустинга, затем exp), см. `l2_lib.fit` (стр. 599) и `tune_L2_optuna.py` (стр. 30). `gibrid_bias.resid` считает остатки по прогнозу каждого слота, поэтому s² у V9-ноги берётся по остаткам итогового V9, а не HAR-J.

## Процедура сборки
- Скрипт — `scripts/analysis/gibrid_v17.py`, режим `--dev-eval oos`: параметры шага t−1 применяются к val шага t, критерии и средний QLIKE считаются на шагах 2–6 (2017–2021). Схемы: 14 на h=1 и 13 на h=5/22 (кандидаты V3, V7-полураспад, V10_MinQ, V10_Pool, V11, Med3, Gate_L2, EQ, ML2_Pair — последняя только при h=1; плюс G3 и V0 × HAR-J/XGB/LGB/HAR-CJ). V10_Fix исключён. Использованы четыре оценки s² и вариант без поправки, усадка 0/0,25/0,5, смешивание rv/log, V7 с lag=h. Эталон c1–c3 — модели с той же оценкой s². V0 участвует в отборе наравне со схемами, сам с собой не сравнивается.
- Ноги: h=1 — `Bv2b` single/top5/seeds3; h=22 — `L2_h22` single/top5/seeds3; h=5 — `L2_h5` single/top5/seeds3 и новая нога **wrap**. В ноге wrap LGB-слот = обёртка (среднее V9-LGBM и V9-XGB), XGB-слот = V9-XGB. Тогда V0_LGB этой ноги в точности равен дизайну обёртки: совпадение с `wrap_h5_val.parquet` до 2e−15, с `test_locked/wrap` до 5e−15. Для шагов 7–9 обёртка собирается из single-файлов `L2_h5`: это точки шага 6, как в `wrap_v9.py`. HAR-J и HAR-CJ считаются на `features_pit_v2`.
- Изменения кода:
  - `gibrid_io.load_boost`: добавлены нога wrap и запасной вариант top5 → single на шагах без топ-5; тест закрытых вариантов читается из `test_locked/<boost>/` только при `test=True`.
  - `gibrid_v17.py`: добавлены `--legs`, `--build-test`, `--test-out`. Блок `--confirm` переписан по М4: проверяются все финалисты, затем до 25 следующих по рейтингу до первого прошедшего. Если не прошёл никто, берётся первый финалист с пометкой. Метрики шагов 7–9 записываются только для проверенных дизайнов (`confirm_*.csv`), в `designs_val_*` их нет. Подтверждающий прогон не увеличивает счётчик дизайнов.
- Выходы: `data/regen/gibrid_final/{Bv2b,L2_h5,L2_h22}/`. В каталогах лежат ranking_*, designs_val_*, confirm_*, final_confirmed_*, bias_factors_*, har_specs_val_*.
