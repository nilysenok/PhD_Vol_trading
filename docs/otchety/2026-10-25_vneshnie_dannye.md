## 3. Цель и лаги собственных признаков

Код цели: `00_prepare_data.py:47-48` — `df[f'rv_target_h{h}'] = df.groupby('ticker')['rv'].shift(-h)`. Модель берёт `log(target + 1e-10)` (`regen_boosting.py:58`, `walk_forward_full.py`). Лаги: `intraday_features.py:354-386` (rv_d = RV(t−1), rv_w/2w/m/q = среднее за 5/10/22/66 дней по t−1), `:390-418` (jump_lag1/5/22). Сам `rv` (день t) тоже входит в признаки.

Тест на синтетике (`m0_cel_test.py`, тот же оператор из исходника через `ast` и та же `add_har_lags`/`add_extended_lags` на polars; ряд rv_t = t):

| Проверка | Результат |
|---|---|
| h=1: цель = RV(t+1) = среднее за [t+1, t+1] | **проходит** |
| h=5: цель = среднее за [t+1, t+5]? | **не проходит**: код даёт RV(t+5) (при t=10: 15 вместо 13) |
| h=22: цель = среднее за [t+1, t+22]? | **не проходит**: RV(t+22) (32 вместо 21,5) |
| признаки только по t включительно (возмущение будущего не меняет прошлые признаки; rv_d, rv_w, rv_m по t−1) | **проходит** (0 изменённых ячеек) |
| сдвиг цели по строкам тикера, а не по календарю | при пропуске строки цель берёт следующий имеющийся день |

На реальной матрице: `rv_target_h5/h22` = RV(t+h) по строкам в 100 % строк, равенство среднему за [t+1, t+h] — в 0,01 %. Корреляция ln точечной цели с ln среднего: 0,774 (h=5) и 0,623 (h=22). В 3,7 % (h=5) и 6,5 % (h=22) строк строка t+h не совпадает с днём t+h общего календаря (пропуски тикера). Утечки здесь нет, но определение цели h=5/22 расходится с текстом. В `features_pit.parquet` добавлены колонки `rv_target_mean_h5`, `rv_target_mean_h22` (среднее за следующие h строк тикера). Колонки `rv_target_h*` не изменены; какое определение брать — решает владелец.

## 7. Повтор B на features_pit (М7, лист решений 25.10)

Механизм — `moex_volatility/scripts/tune_B.py` из `origin/etap5-B`. В эту ветку он взят как есть, плюс ключи `--features <parquet>`, `--tag <префикс>`, `--hs <список h>`. Без ключей поведение прежнее: `data/prepared`, префикс `B`, h = 1, 5, 22. Ключи читаются до загрузки данных, поэтому их видят и дочерние процессы spawn. Проверка: модуль с `--features data/regen/features_pit.parquet --tag Bpit --hs 1` загружает 50 906 × 266, одна задача (lgbm, h=1, шаг 1, точка 0) считается за 2,4 с.

Очередь — `scripts/analysis/m0_B_pit_queue.sh`, запущена через nohup в 17:48 (pid в `data/run/m0_B_pit_queue.pid`, лог `data/run/m0_B_pit_queue.log`). Она ждёт три условия: чужие `tune_B.py` и `regen_boosting.py` завершились (основной прогон B, `--extra`, `--watch`); в копии B появились `B_{xgb,lgbm}_h1_val.parquet` (`agent-afcfa1385cb335411/data/regen`); 1-минутная нагрузка ниже 10. Потом запускается `tune_B.py --features … --tag Bpit --hs 1 --workers 4` под nice: 1 800 задач, по замеру B 12 с на задачу, около 1,5 ч. Сравнение — `m0_B_pit_cmp.py`: валидационный QLIKE только по шагам 1–6, по формуле и агрегату `etap5_B_val.py`, B на исходной матрице против Bpit, по каждой модели. Строки дописываются в `docs/otchety/m0/B_pit_cmp.csv`. Если |сдвиг| < 2 % у обеих моделей, остальные h не перегоняются (пометка в CSV и логе). Выходы: `data/regen/Bpit_{xgb,lgbm}_h*_{val,test}.parquet`, `Bpit_selected.csv`, `Bpit_trials.csv` (в репозиторий не входят). Результат в этот отчёт вписать после прогона.

## Ограничения

- IMOEX-признаки (`close_IMOEX`, `rv_IMOEX`, `idx_IMOEX_*`) и признаки остальных индексов на днях с обрезанными 10-минутками не пересчитывались (решение владельца Д2, 25.10). На 10 % дней (IMOEX: 291 из 2 875, с 2022 года 106 из 1 020) они посчитаны по 5–30 барам до 10:30–13:40; RV в эти дни занижена, `close_IMOEX` отличается от дневного ISS до 6,7 %. В матрице есть только служебный флаг `imoex_low_bars`.
- Даты публикации месячной макро не восстанавливались (без сети): взят консервативный лаг «конец периода + 30 дней». Для PMI и безработицы США он избыточен на 3–25 дней, для ИПЦ — близок к реальному.
- Время среза Brent/золото (расчётная цена или последняя сделка Yahoo) не сверено. Вердикт от этого не зависит: оба варианта позже 18:50.
- В старой матрице собственные признаки акций с 22.06.2020 включают вечернюю сессию до 23:50; в v2 они пересчитаны по срезу 18:50 (п. 8).
- Цель h=5/22: в коде RV(t+h), в тексте — среднее за [t+1, t+h]. В v2 есть обе колонки; выбор за владельцем, B на h=5/22 после этого решения.
- Дни с последнего обновления у месячной макро считаются от консервативной даты доступности (конец периода + 30 дней), а не от реальной публикации.
