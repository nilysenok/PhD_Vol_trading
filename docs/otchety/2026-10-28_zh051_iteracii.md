## 1. Общая схема

Для быстрого варианта действует §0. Снимок `golden_P1.csv`, реестр `e1_filtry` и правка `etap1_eval` ниже заменены подклассом `PlusEvaluator` и сравнением с родительским оценщиком; остальное без изменений.

**База итераций 2–9 — точка P1.** Это последняя строка `S{k}_itog_v2.csv` (`zapusk 2026-10-28T00:36:00`, sha256 — в каждом yaml). Каждая итерация добавляет один механизм к P1. Остальные оси стоят в значениях P1: так итерации независимы и сравнимы с одной базой. У всех P1 выходы k_s, R, k_tr и безубыток выключены, размер равный, режим и события `net`. Стоп по времени τ: S1–S3 — 1, S4 и S6 — 20, S5 — нет.

**Точка решения.** Все новые ряды строятся на close d по данным до 18:50 d (Н6). Решение — о входе по close d. Исполнение — по оси `vhod` точки P1, как в итерации 1: лимит — по барам d+1 (S1–S5), рынок — по close Н6 d (S6, исключение Д2 из Н6; ❓7). Новые механизмы только **запрещают вход** (сделка Sk пропускается целиком, `etap1_data.gate_trades`) или распределяют слоты (итерации 3 и 9). Открытую позицию они не закрывают. Исключение — итерация 2: она меняет сам сигнал.

**Место в боевом пути (толкование [Ж-051] (а)).** Всё встраивается в `etap1_eval.Evaluator`, его же вызывает якорь s9.
- Фильтры входа 4–9 подключаются в `_rows` через реестр `fastbt/e1_filtry.py`. На тикер и день он отдаёт `(allow_long, allow_short)`; сторону задаёт знак позиции в день начала сделки.
- Распределитель слотов (3 и лимит сектора в 9) работает вторым проходом `_rows`: сначала сигналы всех тикеров, затем распределение, затем `run_e1`.
- Ансамбль (2) работает так. Режим `srednee` усредняет строки g, sides и expo соседей перед одним вызовом `port_rows`; это линейно и совпадает с `Engine.mix`. Режим `golos` применяет `execlayer.vote` к позициям в `_positions`.
- `is_anchor` проверяет и новые оси: если любая из них ≠ net, точка не считается якорем.

**Golden «выключено = старый путь побайтно».** До любой правки кода снимается `docs/tables/zh051/golden_P1.csv`: `excess_d` точки P1 на train по S1–S6 с текущего кода `7089747`, плюс sha256, `kod`, `vhody`. Тест после каждого слияния проверяет:
- (а) P1, у которой все новые оси = net, даёт `excess` через `np.array_equal` с golden;
- (б) якорь `anchor_s9_diff` ≤ 1e-12 на 2018 и 2019;
- (в) при выключенной оси модуль не вызывается совсем — проверяется подменой модуля на бросающий исключение.

Ключ входов `E1Inputs.digest` (Д5) включает каждый новый ряд: индексы секторов, ставку, позиции других Sk, тень. Тест «подмена ряда при том же ключе → промах» обязателен (`mutations.md` № 7).

Модель угроз не нужна: сети, сервера и ключей в этих блоках нет.

### 2.3 Топ-k по рангу |сигнал|/√RV (`zh051_it3.yaml`, N = 4)
- **Определение.** Балл s_t,d = |strength_t,d| / σ_t,d. strength — сила сигнала Sk (`u.strength[0]`, та же, что у `q_sily`). σ — источник σ точки P1, известен на close d. Кандидаты дня d — тикеры, у которых сделка Sk начинается в d (после фильтров).
- **Слоты.** Занятость слота — от начала до конца сделки Sk по сигнальной позиции. σ-выходы только укорачивают сделку, поэтому это оценка сверху без заглядывания. Свободные слоты k − открытые заполняются по убыванию балла; ничья — порядок `data.TICKERS`. Вытеснения нет. Вес 1/17 (↺ выше).
- **Вырожденность.** k ≥ максимума одновременных сделок P1 в 2017 (прогрев, ex-ante) — точка совпадает с P1 и считается в N один раз.
- **Уже есть:** strength в Sk, σ в `inp.sigma`, деление на `cnt` в `port_rows`. Распределителя по тикерам нет нигде: топ-10 в A выбирает конфигурации, а не тикеры.
- **Мутации:**
  - вес по будущему — балл по σ_{d+1} или strength_{d+1};
  - d+1 — занятость по позициям Sk дня d+1;
  - текущий день — выход сделки, закрытой по close d, освобождает слот для входа на том же close; правило: слот свободен со следующего дня, как блок повторного входа 2.16;
  - контроль — баллы перемешаны внутри дня (20 seed);
  - golden: `top_k = net`.

  - вес по будущему — σ_a с будущими строками;
  - d+1 — занятость сектора по позициям d+1;
  - контроль — сдвиг маски тормоза; для лимита — случайные секторы той же численности;
  - golden: обе оси net.

**Общие тесты для всех итераций.**
- Статический тест 2.9 расширяется на новые модули `e1_*.py`: нет импорта `sigma_e`, `vpred`, `ch4_dev`.
- Даты ≥ 2022 → `PermissionError`.
- Тест на синтетике с известным ответом — на каждую функцию ряда.
- Мутации подкладывает проверяющий в отдельной копии.

## 3. Критерий «прошла» для элемента ([Ж-051] (б), фиксируется до счёта)

P_i — центр плато по осям итерации. Выбор: `pick_by_plateau(radius = 1)` среди допустимых точек (стороны ≥ 0,5 базы, сделок ≥ 30 в год, не вырождена). При ничьей ≤ 0,05 выигрывает меньшая σ126 (Ж-043). Элемент **прошёл**, если выполнено всё:

| № | Условие | Почему так |
|---|---|---|
| П1 | Δ = tsel(P_i) − tsel(P1) ≥ 0,10 mSR | 0,10 — допуск владельца для «не хуже» (Ж-048). Улучшение должно выйти за полосу равенства |
| П2 | mSR_y(P_i) ≥ mSR_y(P1) − 0,10 в 2018 и в 2019 | min по годам нельзя улучшить, отдав другой год |
| П3 | у соседей P_i по осям итерации (±1, кроме net) Δ > 0 не меньше чем у min(2, число соседей) | рост на плато, а не всплеск одной точки (Ж-047 п. 4) |
| П4 | ворота не хуже, чем у P1: сделок ≥ 30 в год; s9/golden зелёные; G4 по k_s, R, τ — не хуже P1 (досчёт ≤ 6 точек, в N); общий PBO после итерации ≤ PBO до неё + 0,03 | 0,03 ≈ 2 из 70 разбиений CSCV (8 блоков) — шаг сетки PBO |
| П5 | контроль без модели (§4 п. 2): Δ(P_i) больше Δ контроля хотя бы в 19 из 20 сдвигов или перестановок, p = (1 + #≥)/21 ≤ 0,1. Для итерации 2 — только контроль (в) = P1, то есть П1 | фильтр, который просто срезает экспозицию, не должен проходить. Сдвиг сохраняет долю разрешённых дней и автокорреляцию |
| П6 | для режимов 4, 5, 6: в каждом году train ≥ 2 переключения режима и доля разрешённых дней в [0,1; 0,9] | иначе режим — фиктивная переменная года |

**Итерация 10.** E — прошедшие элементы с их значениями P_i. Считается факторный план «вкл/выкл» по E: 2^|E| точек, не больше 256, плюс досчёт плато k_s, R, τ. Выбор — центр плато, ворота Ж-044 и Ж-048…Ж-050 без изменений. Если ни один элемент не прошёл, итерация 10 — пустая строка «нечего сочетать». Остановка раньше 10 (Ж-051) проверяется на границе каждой волны: стратегия, у которой точка P_i прошла все ворота train, из следующих волн выходит.

  - итерация i загружает `ledger_it{i−1}.pkl` (у 3 и 4 — `ledger_it2.pkl`) и сверяет sha256 до использования;

- **Восстановление**, если pickle удалён: `etap1_ansambl_run.restore` (Моррис с тем же seed + `S{k}_faktor.csv` + пробы плато).
- **Ворота восстановления** — честные N по `SHA256SUMS.txt`:
  - `ledger_it1`: S1 3 790, S2 1 801, S3 2 765, S4 2 298, S5 689, S6 1 151;
  - `ledger_it2`: на 6 больше (3 796 … 1 157);

  - Моррис и факторный план обязаны дать `N_do_dosheta` (иначе `SystemExit`).
- **Сверка.** Перед вердиктом каждой итерации 5 случайных строк ledger перевычисляются текущим кодом, `array_equal`.
- **Что из этого следует.** Итерации 3 и 4 добавят до 4 + 60 конфигураций и до 12 проб плато; полный вариант — до 206. Это 4–30 % к итерации 1, где PBO 0,41–0,80; после итерации 2 PBO не сдвинулся. Поэтому, вероятнее всего, сработает правило остановки Ж-054.
