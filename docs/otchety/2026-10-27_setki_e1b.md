## 1. Что такое «точка» и «исходное значение»

У A нет единой точки: на каждый (тикер, год) отбирается топ-10 из сетки и идёт голосование (паспорт A §4). В Э1 точка — **одна конфигурация**: сигнал, RM и исполнение фиксированы и общие для 17 тикеров, годового переотбора нет. Исходная A (ансамбль) остаётся эталоном (`etalon: A_ishodnaya`) и в N не входит.

- `ishodnoe` — база OAT: центр сетки A по каждому параметру. Это умолчание, см. §5 ❓1.
- `v_A` — значения из сетки A.
- Значения A, попавшие внутрь диапазона, входят в `setka`.

## 2. Формат `sweep-setka` v1 (предложение для `fastbt/sweep.py`)

```yaml
v: 1                      # версия формата
format: sweep-setka
obekt: {tip: strategiya|A_sborka|C|E|B|D, sid: S1}
period: {tsel: tune2018, kontrol: ctrl2019, validation: zakryto}   # имена — контракт §4
komissiya: {otbor: 0.0004, pereschet: [0.00035]}                   # доли на сторону
bloki:
  <блок>:
    uslovie: {<параметр>: <значение>}   # необязательно: блок активен только при этом значении
    parametry:
      - {imya, ishodnoe, setka: [...], v_A, edinitsa, dostup: kod|obertka|pravka, pravka_znach, obosnovanie}
faktornyy: {<p1>: [3 уровня], <p2>: [...], <p3>: [...]}
optuna: {n_trials: 100, sampler: TPE, seed: 20261027}
N: {oat, faktornyy, optuna, itogo}
```

Блоки и классы параметров по контракту §3:

| Блоки | Класс | Ключ кэша сигналов |
|---|---|---|
| `signal` | сигнал | входит |
| `filtry_zashity`, `q_sily`, `vyhod_dev` | пост-сигнал | не входит |
| `rm*`, `ispolnenie` | PnL | не входит |

Значения `dostup`:
- `kod` — значение проходит в fastbt как есть.
- `obertka` — делает sweep.py поверх массивов fastbt, ядро не трогается. Зашитые пороги так можно только ужесточать: маска на `sig`. √RV-выходы идут через ядро B `kind=2` (`batch.py`, слот σ — наивная √RV_w).
- `pravka` — нужна правка fastbt.

Для кодера движка (WIP `sweep-engine`). В WIP `Spec` плоский: `base` + `grids`. Чтобы принять v1, нужны три вещи:
1. развернуть `bloki` с `uslovie` в base/grids;
2. снять ограничение «RM — узел `grids.rm_grid`»;
3. добавить пост-сигнальные маски.

## 3. Таблица N

Правило счёта:
- **OAT** = 1 (база) + Σ(|сетка| − 1) по всем параметрам. Условный блок варьируется от базы с подставленным условием, и точка самого условия уже посчитана у параметра-переключателя.
- **Факторный 3³** = 27, считается брутто: совпадения с OAT не вычитаются, N получается консервативным.
- **Optuna** = 100.
- Пересчёт при 0,035 % в N не входит.
- Значения `pravka`, если правки не будет, N не уменьшают: N — верхняя граница, DSR строже.

| S | Параметров | OAT | Факторный 3³ (предварительно, по экономике) | Optuna | **N** |
|---|---|---|---|---|---|
| S1 | 25 | 95 | ma_window {10,20,40} × z_entry {1,5;2;2,5} × max_hold {10,20,40} | 100 | **222** |
| S2 | 24 | 91 | bb_window {10,20,40} × bb_std {1,5;2;2,5} × max_hold {10,20,40} | 100 | **218** |
| S3 | 25 | 92 | dc_window {10,20,40} × trail_atr_mult {2,3,5} × trail_n {10,15,30} | 100 | **219** |
| S4 | 25 | 94 | atr_period {7,14,30} × multiplier {2,3,4} × trail_atr_mult {2,3,5} | 100 | **221** |
| S5 | 29 | 91 | filter_set {2,3,4} × max_hold {5,8,15} × tp_target {P, next_R, half} | 100 | **218** |
| S6 | 29 | 103 | vwap_window {10,20,40} × dev_mult {1;1,5;2} × vyhod_dev {0,25;0,5;0,75} | 100 | **230** |
| Сборки Э1-г | 3 | — | полный 3 × 4 × 3 | — | **36** |

- Итого по стратегиям: 157 параметров, OAT 566, N = 1 328.
- N в DSR — своё для каждой стратегии (222 … 230). Сборки — отдельное N = 36.
- При повторном взгляде на validation N удваивается (Ж-031).
- Факторный план окончательно задаётся после торнадо OAT. Если пара параметров сменится, N не меняется: по-прежнему 27.

Почему у части параметров меньше 5 значений: это переключатели и счётчики (`pivot_period`, `dir_bias`, `breakeven`, `consec_entry`, `svechi_min_iz5`, `parabolic_*`, `gamma_hold`), у которых 5–7 значений по экономике нет.

## 4. Что в A зашито (не параметр)

**В сетку включено как `obertka`** (без правки fastbt; ослабляющие значения помечены `pravka_znach`):
- S1/S2: `vol_regime < 1,2`, ≥ 3 свечи из 5, объём < SMA5 (только `pravka`);
- все: `vf_pass` 0,5·SMA20;
- S3/S4: ADX > 20;
- S3: объём > SMA20;
- S6: выход `|close−VWAP| < 0,5·dev` — пересчёт из `extra`;
- S5: `filter_set=1` есть в коде, но в A не бралась;
- все: квантиль силы `q_sily` {0; 0,5; 0,67; 0,75}, окно 252 (как E0).

**Помечено, в сетку не входит** (нужна правка fastbt):
- окна индикаторов ATR14, ADX14, SMA50(ATR), SMA20/SMA5 объёма;
- нормировки силы (/3, /0,5·STD, /35, /1,5·ATR, /2·dev);
- S2: выход по пересечению SMA;
- S3: окно выхода = окно входа;
- S4: ATR полос = SMA(TR);
- S5/S6: пороги внутри fs1–fs4, выход по ADX > 30, уровни входа S1/R1;
- S6: окна MA50/MA200 в `dir_bias`;
- у тренда нет временного стопа в ATR-RM (есть в √RV-блоке через `gamma_hold`);
- `partial_exit`;
- процедурные пороги отбора A (Шарп > 0, MDD > −30 %, экспозиция > 5 %, ≥ 1 сделки в год) — это процедура, а не точка.

## 5. Вопросы

1. ❓ (владельцу) Что брать базой OAT: центр сетки A (умолчание) или самую частую конфигурацию отбора A по (тикер, год)? Второе требует расчёта п. 7.3 паспорта. Срок — сутки, иначе умолчание.
2. ❓ (владельцу) Цель Optuna на `tune2018` вырождается в Шарп 2018 (σ по одному году = 0). Умолчание — так по контракту §4; альтернатива — σ по кварталам 2018. Срок — сутки.
3. ❓ (для `sweep-engine`, кодер) Нужно измерить на 2018 медиану ATR14/(√RV_20·P) по тикерам. Базы `k_sl` в √RV-блоке взяты при оценке ≈ 1,3; если медиана другая, сдвинуть базу к ближайшему узлу сетки — сетка и N не меняются.
4. ❓ (для `sweep-engine`) Сборки Э1-г — отдельный адаптер `A_sborka` (контракт §2): веса, лимиты, FIFO, вес слота 1/L.
