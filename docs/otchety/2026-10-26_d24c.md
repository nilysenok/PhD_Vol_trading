## Протокол
- **Данные** (общий `data/regen/features_pit_v3.parquet`, 17 тикеров, 2014-06-09 … 2026-02-03): доходность — лог-разность `close` ×100 (close-to-close), RV — столбец `rv` ×10⁴ (срез 18:50), цели — `rv_target_h1`, `rv_target_mean_h{5,22}` (как у остальных моделей).
- **Окно.** Шаг k = 1…10, год оценки vy = 2015 + k, тест ty = 2016 + k. QMLE один раз на расширяющемся окне (годы < vy), затем фильтр с теми же параметрами на vy и ty (как `garch_sv.py`); подбора на vy нет. 170 подгонок на модель (17 тикеров × 10 шагов), около минуты.
- **HEAVY.** Два уравнения, раздельная Гаусс-QMLE (SLSQP, три старта, α + β ≤ 0,9995): h_t = ω_r + α_r RM_{t−1} + β_r h_{t−1} (лог-правдоподобие Σ ln h + r²/h) и μ_t = ω + α RM_{t−1} + β μ_{t−1} (Σ ln μ + RM/μ). Прогноз RV — по итерации μ_{t+s} = ω + (α+β) μ_{t+s−1}; среднее за [t+1, t+h].
- **Realized GARCH** (лог-линейная (1,1)): ln h_t = ω + β ln h_{t−1} + γ ln x_{t−1}; ln x_t = ξ + φ ln h_t + τ₁ z_t + τ₂ (z_t² − 1) + u_t; совместная QMLE (σ_u² профилируется, 7 параметров, ограничение β + γφ ≤ 0,999). Прогноз по итерации в логах: l_{s+1} = ω + γξ + (β + γφ) l_s, E ln x_{t+s} = ξ + φ l_s, уровень = exp(E ln x) (без поправки на Йенсена — её делает Б0.1 по правилу).
- **Горизонты.** h ∈ {1, 5, 22}; для ноги Д18.1 / Д18.3 — среднее за [6..22] и [2..22] по тем же траекториям.
- **Оценка.** `gibrid_v17.py --boost GARCH_sv{heavy,rgarch} --legs single` (общие файлы не менялись: модель стоит в слоте V0 через префикс `GARCH_sv`), четыре оценки s² и вариант без поправки; c1–c4 оттуда же. Д18: `--boost D24_6_d18{h,r} --regen data/regen/D24_6 --legs single`.
- **Отложенный 2021** — шаг 6; s² и спецификация выбирались по шагам 2–5 (правило третьего круга), 2021 смотрелся после.

## Детектор «будущее не влияет»
`d24_6.py selftest`: для SBER, LKOH, IRAO и шагов 1, 3, 6, 9 все `close` и `rv` после 30 июня года оценки возмущаются (случайный сдвиг цены, множитель RV 0,2–5), параметры и прогнозы пересчитываются заново. Прогнозы на датах ≤ отсечки совпадают до 0,0 (максимум расхождения 0); после отсечки меняются (минимум 1,3) — контроль, что возмущение дошло. 96 проверок (3 × 4 × 2 × 4 горизонта), все OK. Параметры берутся по годам < vy, фильтр использует доходность и RV только до t включительно; цель в фильтре не участвует.

## Ночные умолчания (отступления)
- ↺ Вход фильтра: RM ограничен 1,0, |r| ≤ 70 (×100) — затронута ровно одна строка (IRAO 2015-01-20: rv = 21,9, r = 467% — выброс данных). Цели не менялись. Откат: убрать `RM_CAP`, `R_CAP` в `d24_6.py`. Нули RV (4 строки, 2025) — пол 10⁻⁷ для ln x.
- ↺ Среднее доходности не вычиталось (нулевое среднее, как в Hansen et al.); у `garch_sv.py` была константа в `mean`.
- ↺ Выбор s² и «представитель» одиночной модели — по варианту V0 (модель в XGB-слоте, пять вариантов s²), как в `garch_sv_compare.py`. Если считать представителем лучший дизайн всего пространства гибрида (`ranking_*.csv`), он смешивает модель с HAR-J (RG h = 1: `minimax/B-smrob`, h = 5: `g3/B-sm`) и в таблицу не вошёл.
- ↺ Для Д18 представитель — V0 в XGB-слоте (структурный прогноз сам по себе). По строгому правилу «лучший дизайн пространства по числу нарушенных критериев» представителем стал бы чистый HAR-J (1 нарушение против 2 у любого дизайна с ногой), прирост нулевой; лучший дизайн с ногой — `g3/B-sm/L0.5`: 0,2241 по 2017–2020 (+4,9% к HAR-J), 2020 — 0,5038 (−11%), 2021 — 0,1369 (+5,8%), c1, c2 нарушены.
- ↺ yaml HEAVY/RG помечены `odinochnaya: false` (поручение владельца 26.10 02:15 — «кандидат V0» — позднее решения 01:12 о том, что одиночные модели в пул не входят). Откат: `odinochnaya: true` — тогда они останутся справкой.
- ↺ Прошёл ≠ в финалисты: критерии c1–c4 нарушены у всех трёх, рейтинг и отложенный 2021 против «текущего лучшего по правилу» решит `final3.py select`.
- Шаг 10 для D24_6_heavy и D24_6_rgarch выложен (формат `final2_step10`: `data/regen/D24_6/step10`, `test_locked/D24_6_*/step10`); для D24_6_d18r шага 10 нет — final3 берёт шаги 1–9 (↺).
- `arch` не использован (спецификации собственные, `scipy.optimize` SLSQP). 2 из 170 подгонок HEAVY (IRAO, шаги 1 и 3; в каждой по два уравнения) без флага сходимости, результат оптимизатора использован как есть; RG — 170 из 170 сходятся.
