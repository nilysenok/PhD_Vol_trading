## Протокол
- **Спецификация** — как в диссертации и в `test2019_v3.stage_garch` (`arch` 7.2.0): по тикеру, дневные лог-доходности close ×100, `mean=Constant`, `dist=normal`, GJR — p=1, o=1, q=1; GARCH — o=0. Данные — `features_pit_v3.parquet`, 17 тикеров.
- **Окно оценки.** Шаг k = 1…10: год оценки vy = 2015 + k, тестовый год ty = 2016 + k (шаг 10: val 2025, прогноз янв.–фев. 2026). Параметры оцениваются один раз по расширяющемуся окну — все годы < vy (с 2014‑06‑09); на vy и ty модель фильтрует с теми же параметрами. Подбора на годе оценки нет: параметры шага t оценены по годам < vy, как параметры шага t−1 у справочного GRU. 340 подгонок (17 × 10 × 2), 9 с.
- **Прогноз h ∈ {1, 5, 22}.** Среднее ожидаемых σ² за [t+1, t+h] по формуле GJR (при персистентности ≥ 1 — долгосрочная дисперсия = дисперсия обучения), делится на 10⁴. Масштаб как в коде диссертации: без множителя к RV. Цель — `rv_target_h1` (h=1) и `rv_target_mean_h{5,22}` (среднее RV за [t+1, t+h]), как у остальных моделей.
- **Б0.1.** `gibrid_v17.py --boost GARCH_svgjr --legs single --features features_pit_v3.parquet`: модель стоит в слоте V0; четыре оценки s² (ord, rob, sm, smrob) и вариант без поправки, s² шага t−1, OOS. Выбор по правилу (число невыполненных критериев, затем средний QLIKE шагов 2–6). Для GARCH(1,1) — тот же прогон (`GARCH_svgarch`). В `gibrid_io.py` одиночная модель распознаётся по префиксу `GARCH_sv` (тестовый каталог — `test_locked/GARCH_sv`).
- **Метрика.** OOS QLIKE на годах оценки 2017–2021 (шаги 2–6, 21 471 строка). DM основной способ: дневной ряд средней по тикерам разности потерь, NW с лагом h−1; d = L_сравн. − L_GJR (t > 0 — GJR лучше), p = 1 − Φ(t). Сравнение — `garch_sv_compare.py` (функции `gru_sv_compare.py`).

## Оговорки
- 8 из 340 подгонок `arch` без флага сходимости: GJR — IRAO, шаги 4–10; GARCH — IRAO, шаг 10. Результат оптимизатора использован как есть (правило «как в коде»), прогнозы не исключались; IRAO — один тикер из 17.
- Уровень прогноза (в 2 раза выше RV) — свойство спецификации диссертации (доходности close-to-close), а не ошибки сборки; сопоставление масштаба с RV сделано так же, как в `test2019_v3.py` (деление на 10⁴, без множителя).
- Условие информации: σ²_{t+1} строится по доходности дня t до close, признаки v3 — срез 18:50; как и в `test2019_v3.py`.
