## (б) Шорт

**Что есть.**
- A: позиция {−1, 0, +1} (паспорт §1).
- Этап 1: `exec_e` поддерживает `sig ∈ {−1, 0, +1}`, `side = ±1`, зеркальные уровни, тест 2.5. Значит, шорт в P1 уже торгуется.
- Правило шорта есть у всех шести: S1 `z > z_entry`, S2 — касание верхней полосы, S3 — пробой минимума, S4 — пересечение сверху, S5 `close > R1`, S6 `close > VWAP + m·dev` (при `dir_bias = ON` — только при MA50 ≤ MA200).
- «Sk без шорта» в коде нет. Только лонг исполняет семья E: `sem_e.py:4`, «шорт не исполняется».

**Варианты.**
- **б1. Ось «сторона» {oba, tolko_long, tolko_short} в этапе 1** — новая итерация от P1. Это фильтр входа по стороне: `gate_trades` уже получает `(allow_long, allow_short)` из `e1_sektor.allow`. N = 2 на Sk, плюс 20 контролей и плато. Отдельная «семья шортов» — та же ось со значением `tolko_short`.
- **б2. Шорт в E**: `sig = sign(pos)` вместо `pos > 0` в `sem_e`. По Ж-057 E не начинается, поэтому только после её открытия.
- **б3. Стоимость шорта.** Сейчас шорт платит только комиссию, а капитал под шортом не получает ставку (`free = 1 − |pos|`). Данных о плате брокера и РЕПО за перенос шорта, о списках бумаг, доступных для шорта (НКЦ, брокеры, по датам), и о запретах регулятора в репо **нет**. Умолчание: все 17 доступны для шорта, плата 0. **Время б1.** Код — 20 / 40 мин, параллельно тесты. Проверка — 15 / 30, перезапуск — 5 / 10, счёт — 2 / 5, вердикт по §3 Ж-051 — 10 / 20. Итого **55 мин / 1 ч 50 мин** от слияния PR дивидендов.

## (г) Walk-forward (Ж-063 п. 2; правила ниже фиксируются до счёта)

**Правило.** В начале каждого квартала Q точка выбирается заново: центр плато `pick_by_plateau(radius = 1)` по окну [Q − W; Q), W ∈ {1 год, 2 года}, других вариантов нет. Ничью решает σ126 (Ж-043). Выбранная точка действует в квартале Q, вне выборки.
- Целевая в окне. При W = 1 — mSR окна. При W = 2 — min(mSR первых 4 кварталов, mSR последних 4): аналог min по годам Ж-043 для скользящего окна.
- Смена точки на границе квартала. Открытая сделка доживает по старым параметрам, новые входы идут по новым. Принудительного выхода и лишней комиссии нет: так же устроены фильтры Ж-051 §1.
- План поиска. Моррис считается один раз — на первом окне, до первого квартала вне выборки. Оси факторного плана фиксируются по нему. Факторный план считается один раз на всём отрезке, `excess_d` лежит в ledger. Выбор в квартале — срез `excess_d` по окну, без нового счёта. Если брать оси по Моррису на всём train, вне выборки окажутся кварталы, по которым план уже выбран, — это утечка.

**Кварталы выбора внутри train** (окна не заходят до начала train):

| Train | W = 1 год | W = 2 года |
|---|---|---|
| 2018–2019 (сейчас) | 4 (2019 Q1–Q4) | 0 |
| В1: 2016–2019 | 12 (2017 Q1 – 2019 Q4) | 8 (2018 Q1 – 2019 Q4) |
| В2: 2015–2019 | 16 (2016 Q1 – 2019 Q4) | 12 (2017 Q1 – 2019 Q4) |

Если окнам на train 2018–2019 разрешено заходить в 2016–2017 (как расширяющемуся окну A), получается 8 и 8 кварталов. Сигналы для этого есть с конца марта 2015, а START σ и режима сдвигается, как в В1. Это вопрос 1.

- Сравнение с базой — ряд walk-forward против статичного центра P_i на тех же кварталах, по разности табличных Шарпов (`mutations.md` № 13).
