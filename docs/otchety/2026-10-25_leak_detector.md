Адаптеры моделей: `p1` (настоящий `moex_volatility/scripts/regen_boosting.py`, вариант P1, один шаг), `harj` (`scripts/analysis/gibrid_har.py`), `gibrid` (V1-V7, `gibrid_v17.compute`, V7 с lag=h), `gibrid_v7lag1` (V7 как в исходном коде, lag=1), `pipeline` (`python3 -m models run --design <yaml> --smoke`, ветка models-pipeline; пока не подключён — стадия пропускается с пометкой SKIP).
Адаптеры стратегий: `v4` (старый код c22a4b3, маска `[0]`), `v4_mask1` (тот же код, маска `[1]`), `fastbt` (ветка origin/fastbt, `python3 -m fastbt.dev --smoke --data-root` + позиции через `fastbt.pipeline.run_unit`, маска `[0]`), `fastbt_mask_old` (режим `--leak-mask-old`).
Код выхода: 0 всё в порядке; 1 упала стадия; 2 не сработала самопроверка. Падение стадии останавливает только эту стадию (решение М8): остальные проверяются, в конце — список «стадия, дата t, расходящийся выход, гипотеза причины».

## Что проверяется

**(а) «Будущее не влияет».** Три даты t: 2019-06-30, 2021-12-31, 2023-06-30. Мир данных (части `data/prepared` для моделей; дневные бары и σ_pred для стратегий) копируется, после t все числовые входы заменяются шумом (фиксированный seed 20251025, dtype и маска NaN сохраняются):
- признаки и внешние ряды строк с date > t — бутстрап значений столбца до t;
- цели `rv_target_h`: цель строки s использует RV за [s+1, s+h], поэтому шумом заменяются строки с индексом торгового календаря > pos(t)−h (цель на дату t−h+1…t законно зависит от будущего);
- бары (open/high/low/close/volume) — синтетический лог-ряд с волатильностью до t (high ≥ max(o,c), low ≤ min(o,c)); σ_pred (`sigma_h1/h5/h22`) — бутстрап до t по тикеру.
Конвейер прогоняется на эталоне и на зашумлённом мире; сравниваются побайтно (`tobytes`) прогнозы моделей (val и test) и позиции стратегий (A/B/C/D) на датах ≤ t, но только для шагов, у которых окно обучения+валидации с горизонтом закончилось не позже t−h (шаг с тестовым годом ty: данные до 31.12 ty−1, `pos(31.12.ty−1)+h ≤ pos(t)`). Лишние/пропавшие строки тоже ошибка; «нет сравнимых строк» — ошибка (проверка вхолостую). Это и есть правильный walk-forward: шаг с обучением до t−h обязан давать те же прогнозы до t, что бы ни происходило после t.

**(б) «Сдвинутая цель».** Цели `rv_target_h*` переставляются случайно внутри тикера (seed 42). Модель обучается на таком мире; val-QLIKE разработочного набора (val-годы ≤ 2021) обязан быть не лучше константы — средней по тикеру RV обучающего окна шага (годы ≤ ty−2). Строки с rv_actual ≤ 1e-12 исключаются, как в `gibrid_io.merged`. Для стратегий (б) не применяется (цели нет).

Допущения и пределы: (1) признаки в `data/prepared` предрассчитаны, поэтому утечку внутри построения признака (признак на s использует данные s+1) детектор не видит; он видит всё, что случается после готовых признаков (обучение, валидация, маски, гибрид, стратегии). Для конвейера `models run` шум должен применяться к сырым входам — это задача его адаптера. (2) Для гибрида (б) компоненты не переобучаются, проверка слабая (QLIKE модели ≫ константы). (3) Для стратегий на t=2021-12-31 маска `[1]` в принципе не ловится: шум начинается ровно после конца тестового года 2021. Ловят даты 2019-06-30 и 2023-06-30. (4) Чувствительность стратегии зависит от выбора: на S1 SBER старая маска [1] ловилась только в 2019 г., на S3 (Donchian) — в A (2019) и B/C (2023); поэтому по умолчанию S3, SBER.

## Устройство (модули ≤ 200 строк)

`tests/leak_detector.py` (CLI) и `tests/leak/`: `noise.py` (шум, перестановка), `world.py` (мир данных), `compare.py` (побайтное сравнение, QLIKE, гипотезы), `runner.py` (прогон проверок), `models_p1.py`, `models_har.py` (HAR-J, гибрид), `strat_v4.py`, `strat_fastbt.py` + `fastbt_run.py`, `registry.py`, `selfcheck.py`.
- P1: настоящий `regen_boosting.py` копируется во временное дерево рядом с зашумлёнными `data/prepared`; в копии (с проверкой наличия шаблонов) шаги берутся из переменной `LEAK_STEPS` и `n_jobs=1`; сам скрипт не изменён.
- v4: код c22a4b3 извлекается `git show c22a4b3:…`; исправленная маска — механическая замена во всех строках `_, X = _year_bounds(d, Y)` на `X = _year_bounds(d, Y)[0]` (включая начало валидации B/C/D `val_start = [0]` = 1 янв 2020).
- Как подключить конвейер `models run`: реализовать класс с методами `load/cal/make/noise/permute/run/steps/info_end/target_frame/permute_steps` (см. `registry.py`), `run` возвращает длинную таблицу `stage, kind, ty, date, ticker, rv_actual, rv_pred`.
