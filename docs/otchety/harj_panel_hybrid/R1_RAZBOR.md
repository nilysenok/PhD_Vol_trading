Статус: расследование (код, тесты, данные не менялись). Скрипты воспроизведения — `docs/otchety/harj_panel_hybrid/r1/`. Дата 07.11.2026.

## Находка 1: `tests/test_v2_hp_k23.py::test_loyo_ne_vidit_celi_goda_Y` падает в полном прогоне

**Причина (одной фразой).** Не порядок тестов, а недетерминированный порядок результатов: `select.run_loyo` -> `runner.map_jobs` берёт результаты через `Pool.imap_unordered` (2 процесса, `chunksize=4`), порядок строк `df` и строк `out` (`groupby(sort=False)`) зависит от того, какой процесс ответит первым; тест сравнивает `a["score"].tolist() == b["score"].tolist()` — списки в порядке прихода, а не словари по метке. При другом порядке прихода в `a` и `b` метки идут в разном порядке — равенство списков ложно, хотя значения по меткам равны.

**Воспроизведение.**
- Детерминированно: `python3 -W ignore docs/otchety/harj_panel_hybrid/r1/r1_loyo_poryadok.py det` — подмена порядка прихода (`reversed`) даёт «списки равны: False, словари по метке равны: True, макс. |Δ| = 0.0».
- Естественно: `python3 -W ignore docs/otchety/harj_panel_hybrid/r1/r1_loyo_poryadok.py nat 15` — 15 прогонов `run_loyo` на том же мире: 2 варианта порядка меток и 2 варианта списка score (3 копии скрипта шли одновременно — нагрузка повышает шанс).
- Прогон `pytest tests/test_v2_hp_*.py` в этой сессии: 88 passed (140 с); отдельный тест 3 раза из 3 passed. Падение из задания не повторилось -> событие вероятностное, не привязанное к соседу.

**Гипотезы.**
1. Подмена атрибута модуля/класса без восстановления (классы № 43/110): отброшена — все подмены в `tests/test_v2_hp_*.py` через `monkeypatch.setattr` (восстанавливается фикстурой; `monkeypatch.undo()` в hyb_b/hyb_d — внутри теста), прямых `X.attr = ...` нет; `GRID132` подменяется тем же способом.
2. `NUMBA_NUM_THREADS`/`os.environ`/`chdir` (№ 52): отброшена — в тестах и `models_v2/s4`, `hp_k23*` нет `environ`/`chdir`/numba.
3. Общий кэш/файл на диске: отброшена — тесты hp пишут только в `tmp_path` (hyb_run, hyb_d), остальные читают; `run_loyo` на диск не пишет.
4. Seed/глобальное состояние: отброшена — `corrupt_after(seed=7)`, `SEED` в XGB фиксирован, `nthread=1`; воркеры `spawn` (свежий импорт, глобальное `_S` заполняется `_init`); значения по меткам одинаковы с точностью |Δ|=0.
5. Порядок прихода результатов `imap_unordered`: ПОДТВЕРЖДЕНА (выше). Вторичный эффект: порядок суммирования в `groupby.mean` тоже зависит от прихода (возможна разница в последнем бите значений; в `det` разница 0.0 на этом наборе).
Какой тест «ломает» — такого нет; что остаётся изменённым — ничего.

**Что затронуто.** Только проверка теста. Боевые числа: `choose_i2` берёт `pick` по словарю меток (порядок не важен; ничья |Δ| ≤ 1e-12 решается `order_key`), т.е. выбор И2 от порядка не зависит; последние биты `score` теоретически могут различаться между запусками (не проверялось на боевых данных; в `det` — 0.0). Результаты P1a (K2/K3 SBER, AFLT, ALRS, GCHE) HP выбирают по этому пути — риск только на ничьих ≈ 1e-12.

**Починка.** (а) Тест (`tests/test_v2_hp_k23.py`, владелец теста — не автор кода): сравнивать `a.set_index("label")["score"].to_dict()` с `b...`, а не списки. Тест, падающий без правки: подмена `runner.map_jobs` на `reversed(...)` (как в `r1_loyo_poryadok.py det`) — старый тест падает, новый проходит. (б) Код `models_v2/s4/select.py::run_loyo`: отсортировать `res` по порядку `jobs` до построения `df` (детерминированный порядок и суммирование); это затрагивает общий слой s4, поэтому — отдельным PR с проверкой, что побайтно совпадают сохранённые И2 (`P1_K23_I2.csv`).

## Находка 2: inf в сыром дизайне K2 бумаги RGSS на 26.01.2024

**Причина (одной фразой).** Столбец 4 дизайна K2 = `ln_bv` (`models_v2/s2/features.py:  X[:, 4] = np.log(dly["bv"])`), а у RGSS 26.01.2024 дневная бипарная вариация `bv = 0.0` (`log 0 = −inf`; после `normalize` — всё ещё −inf).

**Откуда нуль.** Бар основной сессии 51, close во всех барах 0,391 (бумага стоит), нулевых 10-минутных доходностей 50; ненулевая — только первая (`ln(close/open)` первого бара, `rv = 14,889`, `j = rv`). `bv = π/2 · Σ|r_i||r_{i−1}|` — ни одной пары соседних ненулевых -> 0. Объём не нулевой (мин 1000), дыр нет. Не ноль в знаменателе, не нулевой объём, не дыра: вырожденный (почти замёрзший) торговый день.

**Воспроизведение.** `python3 -W ignore docs/otchety/harj_panel_hybrid/r1/r1_inf_k2.py RGSS` (все 28: без аргументов, ~3 мин; `r1_inf_posledstviya.py` — последствия).

**Другие ячейки.** Скан всех 28 бумаг (P.TICKERS, F.X и сырой X дизайна K2): ±inf ровно одна — RGSS, 26.01.2024, столбец 4 (`ln_bv`). Столбцы F4 (`b2feat.build`) inf заменяют на NaN (feat.py:125), поэтому они чисты. SBER: ±inf 0 (K2/K3 SBER не затронуты; в `k23_SBER.parquet` inf 0). AFLT, ALRS, GCHE: inf 0.

**Что затронуто.** A4 (`z_a4_4`, RGSS 26.01.2024): заменено на NaN; соседние z конечны (кэш A4: ±inf 0). K2/K3 RGSS ещё не считались (в `data/regen/harj_panel_hybrid/` только 4 из 28), поэтому риск впереди: `fit.pair_index` проверяет конечность только столбцов `need=(0,1,2,3)`, строка с `ln_bv = −inf` не отбрасывается и попадёт в обучение/прогноз XGB K2 (как значение −inf) — прогноз K2 RGSS на 26.01.2024 и модель, обученная с этой парой, могут быть искажены. Уже посчитанные числа (SBER, AFLT, ALRS, GCHE; A1–A3) не затронуты.

**Починка.** Решение уровня дизайна (замена на NaN в A4 — правильна, но недостаточна для K2 RGSS): в `models_v2/s2/features.py` или `design.make` зажать `bv` снизу (`np.maximum(bv, HOUR_FLOOR)` как для `h1/h2`) либо заменить −inf на NaN (XGB умеет пропуски) — отдельный PR, меняет данные дизайна для RGSS (для SBER и прочих бит-в-бит совпадение, т.к. bv>0), и строку в журнал решения (Д4). Тест, падающий без правки: синтетический день с одним ненулевым баром -> `build(bars)` не должен давать нефинитных `F.X[:, 4]` (сейчас −inf); плюс тест «0 нефинитных на 28 бумагах реальных данных» (`real`-маркер). Пока не исправлено — K2/K3 RGSS не считать как «чистый» результат.
