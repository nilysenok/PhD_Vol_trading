## Вывод
Поле ledger **верно**; ошибся счёт разбора (`prichiny_vyhoda`), и только в одной колонке. Ворота «сделок ≥ 30 в год» (Ж-044, итерации #466, #472), берущие `sdelok_y`, не ошибались. Мутация № 41 по-прежнему верна.

## 1. Как считается `sdelok_y`
- `fastbt/etap1_run.py:78` — на каждую сделку, пересекающую окно, +1 в `cnt` в строке входа и +1 в строке выхода (вход обрезается до начала окна `a`, выход — до `b−1`).
- `fastbt/etap1_eval.py:202` — `sdelok_y[y] = Σ_тикеры cnt[строки года y] / 2`; годы — только годы периода (train4: 2016–2019, прогрев 2015 не входит; вход и выход сделки в разных годах дают по ½ — отсюда значения 2,5 / 5,5).
- Единица счёта: вход+выход одного тикера = 1 сделка, по всем тикерам вселенной, без открытых на конце сверх «выхода на b−1».
- `fastbt/etap1_run.py:42` (`sum_rows`, лестница Л-5): `cnt` ступеней **усредняется** (`/len(rs)`), а список `trades` **склеивается**. Две ступени одного решения: в `cnt` это одна сделка, в `trades` — две.
- `fastbt/etap1_eval_v2.py:198` копирует поле из v1 без изменений.

## 2. Как считал разбор
`scripts/analysis/prohod1_rezhimy.py::prichiny_vyhoda` брал `len(done)` по `evr._last[4][*].trades`, то есть склеенные сделки обеих ступеней. Ступень присутствует, когда `lestnica ≠ net`.

## Причина расхождения
Проверка по ключам строк из ledger (чтение `rows.jsonl`): лучшая устойчивая строка S1 имеет `lestnica = 0.5`, S3 — `lestnica = net`. Отношение «пересчёт / сумма `sdelok_y` за 4 года» (по `prohod12_aktivnost.csv` и `prohod12_prichiny.csv`, ветка `prohod12-razbor`): S1 40/19 = 2,1; S2 39/18 = 2,2; S4 172/78,5 = 2,2; S6 189/90,5 = 2,1; **S3 59/55 = 1,07** (без лестницы). Остаток сверх ×2 — сделки прогрева 2015, переносимые в окно, и ступень, не исполнившаяся по лимиту (вес ½ в `cnt`).

## 3. Что «правильное» по контракту
Контракт §1.2 (`2026-10-28_progon_etap1.md`, строка 95) даёт только имя и форму поля. Определение, которое реализует код: сделки портфеля за год, ступени лестницы усреднены (решение = 1). Оно согласовано с `storony_y` (стороны = 2 × сделки без лестницы) и с весами в `E1Rows`. Второе определение — «ноги» (каждая ступень отдельной сделкой) — вдвое больше у лестничных строк; в ledger его нет. Основным оставляю первое (Д7: одно определение); решение по основному — дирижёру.
