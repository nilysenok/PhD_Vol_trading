## Поправка к спецификации (п. 8, 17): как собраны печатные ряды МСП
По логике `stage5_msp.py` (сначала среднее по стратегиям внутри тикера, комиссия 0,05% от |Δ средней позиции|) получается A/C/D = 1,35 / 2,42 / 2,55, печати это не воспроизводит. Печатные ряды `MSP_{A,C,D}_inst.csv` собраны иначе:
- `trading_ret` — среднее валовой доходности по **имеющимся парам (стратегия, тикер)** на дату, без комиссии;
- `exposure` — среднее |pos| по тем же парам.

Оба столбца совпадают с рядами из позиций fastbt до 1e-16. Для C пар 97–102 (строки C пропущены), поэтому среднее берётся по имеющимся. Свободный капитал и excess считаются как в ST5:213-233. Шарп по формуле FB:20-22 (mean(excess)/std(excess)) даёт печати до 4-го знака. В fastbt это `msp.portfolio(agg="pairs")` (по умолчанию); вариант stage5 — `agg="ticker"`.

## Что сделано в ядре (`fastbt/`, каждый модуль ≤ 200 строк)
- `engine.py`, `engine_trend.py` — движки сделок (ATR, уровни pivot/VWAP, σ_pred; тренд с трейлом и parabolic). Результат конфигурации — список сделок. Плоские участки пропускаются прыжком к следующему сигналу.
- `stats.py` — статистики по годовым сегментам (N, Σnet, Σnet², экспозиция, входы, моноид просадки), окно = сумма сегментов (приёмы 7–8); побитово равны счёту по ряду позиций.
- `batch.py` — прогон полной сетки (сигнал × RM) за один numba-вызов, один раз на единицу: позиции причинны, поэтому прогон до train_end — префикс полного.
- `approach_a.py` (фазы 1–3, устойчивые сортировки — ничьи как в старом коде), `approach_b.py`, `approach_cd.py` + `masks.py` (C/D — булевы фильтры над позицией A с дедупликацией масок по хэшу, приёмы 9–10), `execlayer.py`.
- `cache.py` — кэш сигналов на диске по хэшу входов и кода (приём 14). `sigprov.py`: сигналы берутся из семейств, а при `FASTBT_SIGNALS=legacy` — из старого кода.
- `config.py` — режимы. `--leak-mask-old` = ворота (маска [1], комиссия отбора 0,40%, без исправлений и корпоративных событий). По решению С1 после ворот по умолчанию: маска [0] и шесть исправлений ВКЛ, комиссия 0,05% во всех подходах; каждое исправление выключается флагом `--no-fix-*`.
- `msp.py`, `report.py`, `bench.py`, `chapter4_a.py` — МСП, ΔШарп с бутстрапом, бенчмарки H3, подход A по гл. 4.
- `dev.py` — режим разработки (2017–2021, маска [0]). `--scope test` без `docs/otchety/FINAL_DESIGN_strategies.md` падает. Журнал — `docs/otchety/dev_log_strategies.md`. `--smoke --data-root DIR` — для детектора утечек.
- Тесты `fastbt/tests/test_core.py`: сетки = c22a4b3, дымовой набор ворот 3 × 2 × 2, эквивалентность на SBER, сделки = ряд, замок test, печатный ряд MSP_A.

## Как трактованы исправления (С1, С5)
1. Маска `[0]`: A учится до 31.12.Y−1, валидация B/C/D — [1.01.2020; 1.01.Y). C у S1/S2 валидируется по полным позициям A (`fix_c_s12_val`).
2. Медиана σ в B считается по барам до начала тестового года (`fix_b_median`).
3. σ в D переведена в годовые единицы (×√252), как target/floor/cap (`fix_d_units`).
4. Ставка — решения ЦБ (`moex_discovery/.../key_rate_cbr.parquet`).
5. Шарп МСП — mean(excess)/std(excess).
6. Нет допустимой C у S3/S4 → C = A (запасной вариант закоммиченного V4) вместо пропуска строк (`fix_c_fill`).

Голосование оставлено как в коде.
