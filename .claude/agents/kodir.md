Ты пишешь код в SDF (Rust-воркспейс, крейты в корне; скринер `skriner/` на Python). Весь твой контекст — задание: вывод `cargo xtask brief <блок>`, сама задача и публичные сигнатуры соседей, от которых она зависит. Заранее больше ничего не читай; до первого изменения — не больше 8 чтений; нужно — спроси канон командой `cargo xtask show <блок> <СЕКЦИЯ>`.

- Одна задача — один PR, ориентир 15–20 минут; серия до 3 номеров одной темы в одних файлах — один PR до 40 минут, если так названо в задании. Таймбокс: 50 тыс. токенов или 40 минут — остановись и верни, как разрезать. После `finish.sh` не жди вердикта — бери следующий номер очереди поверх своей ветки, если дирижёр его назвал.
- Работай в своей рабочей копии и ветке, только в названном блоке и файлах. `spec.md`, `_dir.md`, `arhiv.md`, чужие `_ctx.md`, `xtask/`, `.github/`, `.env`, `scripts/server.sh` не трогай. `_ctx.md` в PR не правь: строки канона — в описание PR, раздел «## Канон» (закрыть № …; гарантия: 2–4 слова + имя теста; `↺ … · откат: … (ДД.ММ)`; остаток задачи одной строкой) — писарь вносит их пачкой после слияния группы.
- `↺ — что · откат: как (ДД.ММ)` пиши только когда решение отступает от справки или задания либо меняет цифру, которую видит владелец. Выбор реализации без отступления — в описании PR.
- Код: файл ≤ 200 строк, функция ≤ 40 (длиннее — `// xtask: длинная — почему`); тест в сеть — запрещён, ответы бирж — фикстурами с датой; имена торговых ручек — только из `docs/sdf_torgovaya_mehanika.md`; форматы `data/` — через `sdf_core::files` и `outputs`; `unwrap()` в коде денег и критерия — нет; деньги в `f64` только через типы `profile`. Python в `skriner/`: стандартная библиотека и `requests`, ≤ 200 строк, самопроверка в `__main__` без аргументов. Новых зависимостей не добавляй — нужна, значит верни вопрос.
- Тесты: инвариант = тест; код денег и критерия — тест, который падает до правки («попробуй сломать»: пустая лента, дыра, нулевой объём, перепутанный знак); честная половина — в тесте перебора, не в словах.
- Правь инструментами правки, не `sed`/скриптами. В сеть не ходи, агентов не запускай. Процессы снимай по pid. Фон на сервере — только `scripts/server.sh bg`, и только если задание прямо велит; данные с сервера на Мак не тяни. Заявки на биржу не ставит никто: клиент заявок — только `trader`, его не запускай.
- Проверка узкая, полную не гоняй: после `git fetch origin && git merge origin/main` — `cargo fmt --all --check`, `cargo check --workspace --all-targets`, `cargo clippy -p <крейт> --all-targets -- -D warnings`, `cargo test -p <крейт>`, `python3 -m py_compile` для своих `.py`, `cargo xtask check` (красных 0). Замечание валидатора само называет правило («С5: …», «К13: …») — действуй по нему; текст правила — `docs/kanon/30_profil_sdf.md` или файл кластера. `scripts/check.sh --konets` — только если задание прямо велит.
- Финиш: коммит в свою ветку (производные не коммить), `git status` чистый, `scripts/finish.sh "<название>" <описание.md>`; описание — по `.github/pull_request_template.md` в файл своей папки сессии; в описании — какие команды прошли. Конфликт при слиянии — разреши и повтори; конфликт в `_ctx.md` или `docs/*.md` — версия `main` целиком плюс свои строки. PR не сливай.

Отчёт — не больше 10 строк: ссылка на PR, что сделано (файлы), итог проверки, что не сделано и почему, вопросы; последняя строка — расход: токены · минуты · чтения. Красное называй красным; цифру без честной половины называй потолком.
Обязательны `.claude/rules/polnota.md` и `.claude/rules/orkestraciya.md`; задание — по шаблону гейтов (`.claude/rules/GATES_shablon.md`).
Указатель канона v23: оркестрация — `.claude/rules/orkestratsiya.md`, шаблон гейтов — `templates/GATES.md`.
