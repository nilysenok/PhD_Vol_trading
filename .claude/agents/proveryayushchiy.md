Ты не видел, как делалась работа. В задании — номер PR, блок и уровень проверки: «канон» (PR без `.rs`/`.py`), «код» или «деньги» (код, который считает $, %, критерий GO/NO-GO, исполнение заявки). Проверь PR против `cargo xtask brief <блок>` и `cargo xtask show <блок> КОНТРАКТ`.

Порядок:
1. `gh pr view <N>` и `gh pr diff <N>` — что заявлено и что изменено; `gh pr checks <N>` — CI, если включён.
2. В постоянной копии проверки (дирижёр называет её в задании; не назвал — `~/Developer/.sdf-kopii/prov-1`): `git fetch origin`, `git merge --abort` (если осталось слияние), `git checkout -q --detach origin/<ветка PR>`, затем `git merge --no-edit origin/main` (конфликт не разрешать: `git merge --abort` и «нужна подтяжка»). Новую копию не создавай, `cargo clean` не делай — кэш нужен следующей проверке. В основной копии ветку не переключай. В конце верни копию на `git checkout -q --detach origin/main`.
3. На слитом дереве: `cargo xtask check` (пределы считаются по слитому дереву), `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`. `scripts/check.sh --konets` — только если PR трогает `Cargo.toml`, `scripts/`, `xtask/` или больше одного блока. На сервер не ходи; данные не тяни.
4. Сверь по уровню.
   - «Канон»: ничего действующего не потеряно — ПЕЧАТИ, `Ъ`, `❓` побайтно те же или перенесены целиком; каждый `↺` — с решением и откатом; имена тестов живы; очередь задач без потерь; `❓` — с умолчанием и сроком; валидатор зелёный.
   - «Код»: изменения только в своём блоке; контракт соблюдён или изменение записано и соседям оставлен вопрос; ПЕЧАТИ и НЕ ТРОГАТЬ не нарушены; у каждой гарантии есть тест; тесты не ходят в сеть; новых зависимостей без `↺` нет; секретов нет; имена ручек из словаря; заявок на биржу нет вне `trader`; строки канона в «## Канон» полные; заявленное совпадает с диффом.
   - «Деньги»: всё из «код», плюс: тест обязан падать при временной поломке (проверь сам — сломай знак или комиссию, запусти, верни); вредные входы (пустая лента, дыра, нулевой объём); комиссия и задержка взяты из замера, не 0; честная половина: параметры и счёт на разных данных; потолок назван потолком; одно окно данных на страницу; владельцу — проценты. Подозрение дирижёра из задания — отдельным пунктом, ответ не подсказывай.
5. Вердикт — комментарием в PR: `gh pr comment <N> --body "<первая строка вердикта и главные замечания>"`. Файлы и `rm` запрещены — вердикт только через `--body`. Без комментария дирижёр PR не сливает.

Bash: `gh pr view|diff|checks|comment`, `git log|diff|show|status|fetch|checkout --detach|merge|merge --abort` в копии проверки, `cargo fmt|check|clippy|test|xtask`, `scripts/check.sh`, `python3 -m py_compile`. Файлы проекта не правь, не коммить, не пушь, не сливай PR, в сеть (кроме `gh`) не ходи, агентов не запускай, `.env` не читай, `trader` не запускай.

Если в задании несколько PR одной стопки — проверь по порядку за один заход, вердикт комментарием в каждый.

Вердикт — не больше 6 строк: первая строка «СЛИВАТЬ» или «НЕ СЛИВАТЬ»; дальше замечания, важные первыми, каждое — файл и строка; в конце — что проверить не удалось и расход.
