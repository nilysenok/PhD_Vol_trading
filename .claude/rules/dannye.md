## Дополнение Ж-020 (v23, §3 документа владельца, дословно)

Источник: `docs/kanon/Kanon_universalnye_dopolneniya.md`, §3. Пункты выше (1–8) — действующие правила проекта; пункты ниже — новые, нумерация владельца Д1–Д7.

Д1. **Проверка сдвига обязательна для каждого входного ряда** до первого использования и после каждой регенерации: корреляция с целевой величиной при сдвигах −2…+1, максимум должен быть на последнем известном дне; для оконных рядов — по приращениям; для рядов с плоским профилем — вторая проверка через связанную величину. Результат — первая строка журнала шага. Ряд без проверки в расчёт не входит (хук на загрузку данных проверяет наличие отметки).
Д2. **Лаг исполнения по умолчанию.** Решение на закрытии дня d исполняется не раньше d+1 (или по закрытию d, если это явно объявлено и обосновано). Тест «исполнение в том же баре, что и сигнал» обязан падать.
Д3. **Point-in-time.** Любой ряд хранится с датой, когда значение стало известно (решение ЦБ ≠ вступление в силу; отчётность ≠ дата периода; пересмотры данных — отдельными версиями). Календарь торгов, остановки, корпоративные события — отдельные файлы с хэшами.
Д4. **Константа в данных — ошибка, пока не доказано обратное.** Любая подстановка (ffill, bfill, среднее, ноль) на отрезке длиннее одного наблюдения требует отметки в журнале и теста, что она не влияет на результат.
Д5. **Ключ кэша = хэш всех входов и кода.** Ряды, параметры, версия кода, конфиг. Проверка: подмена любого входа при том же ключе обязана давать промах кэша (тест с мутацией).
Д6. **Эталонные таблицы** (golden) для каждого этапа пайплайна; после исправления ошибки старые — в архив с хэшами и причиной, новые генерируются с исправленного кода; сверка побайтно или с допуском, объявленным заранее.
Д7. **Одно определение на метрику** на весь проект (например, ddof, годовая шкала, база избыточной доходности). Два определения в одной таблице запрещены; смена определения — PR с пересчётом всех таблиц и строкой «что изменилось».

Для этого проекта: Д1 уже выполняется проверкой сдвига (`otchety.md` п. 2, `testy.md` п. 4); Д4 — случай ставки ЦБ `bfill` (`mutations.md` № 16); Д5 — FA2b (`mutations.md` № 7); Д6 — эталоны `final3` после аудита Н1–Н5; Д7 — ddof=1 и «Δ = разность табличных Шарпов» (#279, `mutations.md` № 12–13). Хука на загрузку данных (Д1) пока нет: его делает ветка `kanon-v23-huki`.
