# Оркестрация (канон v23)

Источник: блок 2 владельца 27.10.2026, дословно — `docs/zadaniya/2026-10-27_kanon_polnota_orkestraciya.md`, строки 46–54.

Контекст агенту передаётся файлами: задание — отдельный файл задания с путями к входам; состояние этапа — файл state/<этап>.md; агент не получает историю диалога и не читает план целиком, только свой раздел. Выход этапа — файл, следующий этап получает путь.

Один агент — одна задача, один результат, одно владение файлами (список путей в задании). Писать вне своего списка запрещено. Параллельно — не более 3–5 агентов; при большом числе элементов — пакеты по 5–10 на агента, не агент на элемент.

Роли разделены: автор реализации не меняет тесты; проверяющий не меняет код (только читает, запускает, пишет отчёт и подложенные ошибки в отдельной копии); главная сессия сливает только после собственного перезапуска проверок.

Ответ агента главной сессии — не длиннее 500 слов: сделано / не сделано / проверено / отступления / решения. Всё остальное — в файл отчёта с путём.

Повторы ограничены: этап с валидатором перезапускается не более 3 раз, затем останавливается с отчётом об ошибке.

Расследование отделено от починки: пока причина не названа и не воспроизведена тестом, правки и коммиты запрещены; гипотезы перечисляются все, проверяются по очереди, отбрасываются явно.

Агент, исчерпавший контекст, заменяется новым через файл передачи; главная сессия не доделывает его работу сама.

## Дополнения Ж-020 (v23, §2 документа владельца, дословно)

Источник: `docs/kanon/Kanon_universalnye_dopolneniya.md`, §2, «Дополнения».

- Бюджет агента: при ~300k токенов агент обязан написать передачу; главная сессия не продлевает агента выше этого порога.
- Файл задания агенту содержит: цель, владение (пути), входы (пути + хэши), гейты, что запрещено читать, формат отчёта, лимит процессов. Ничего сверх этого — план и чужие результаты агент не видит.
- Модели по ролям: оркестратор и архитектура — сильная модель; реализация — средняя; ревью и валидаторы — быстрая, с большим входом и коротким выходом.

Для этого проекта: порог 300k — действующий (решение владельца, Ж-020); бюджет в строке задачи (`~20м · ≤ 50т`) — отдельный, более мягкий порог внутри него: выход за него — стоп и «как разрезать», выход за 300k — обязательная передача (`izmeneniya_v22_v23.md`, пересечение 3). Шаблон задания — `templates/zadanie_agentu.md` (поля из списка выше), шаблон отчёта — `templates/otchet_agenta.md`, гейты — `templates/GATES.md`, передача — `templates/handoff.md`. Соответствие ролей: сильная — дирижёр и `arhitektor`; средняя — `kodir`, `issledovatel`; быстрая — `pisar`, `proveryayushchiy` (канон/мелкие проверки; деньги и критерий — sonnet, как в v22). Связанные файлы: `polnota.md`, `pravki.md`, `proverka.md`, `svyaz.md`, `struktura_kanona.md`.
