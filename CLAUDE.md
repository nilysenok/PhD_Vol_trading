## Роли
Главная сессия — дирижёр. Код и диффы не читает и не пишет. Раздаёт работу и сливает только после собственного перезапуска CHECK-команд (`polnota.md` п. 14).
- `kodir` (sonnet): одна задача — один результат, один PR на 15–20 минут, больше — резать; свой список файлов; тесты не меняет.
- `pisar` (haiku): ответы владельца → канон; блоки владельца — в журнал с номером.
- `proveryayushchiy` (деньги и критерий — sonnet, канон — haiku): вердикт в PR; код не меняет; подложенные ошибки — в отдельной копии.
- `issledovatel` (sonnet): факт из сети → запись со ссылкой в `docs/`.
- `arhitektor`: контракты, симулятор, модель угроз — по поручению.
Других агентов не запускать. Простая задача — простой модели; основная — дирижёр и архитектор.

## Порядок работ
1. Приём блока владельца: записать в журнал (append), подтвердить номером Ж-NNN. Без подтверждения блок не дошёл.
2. Нетривиальная задача: план с гейтами `GATES.md` до первой правки (`polnota.md` А; `pravki.md` п. 8).
3. Задание — файл задания с путями к входам и списком файлов во владении; состояние этапа — `state/<этап>.md` (`orkestratsiya.md`); состав задания — `templates/zadanie_agentu.md`.
4. Большая задача — листы с гейтами и интеграционные гейты ветки, разбиение до распараллеливания.
5. Исполнение целиком, без заглушек; четыре прохода по результату; отступления — отдельной строкой до выводов.
6. Отчёт: сделано / не сделано / проверено / отступления / требует решения; реестр «закрыто N из M»; незакрытое — «передача», не «готово».
7. Перед слиянием дирижёр сам перезапускает CHECK; расхождение — назад агенту.
8. Параллельно — не более 3–5 агентов (ждёт решения владельца (вопрос дирижёра 27.10), `izmeneniya_v22_v23.md`, пересечение 2; до решения потолок — решение владельца 12:30); пакеты по 5–10, не агент на элемент.
9. Повторы: этап с валидатором — не более 3 перезапусков, затем стоп с отчётом об ошибке.
10. Расследование отдельно от починки: пока причина не названа и не воспроизведена тестом, правки и коммиты запрещены.
11. Исчерпан контекст — файл передачи и замена; главная сессия работу не доделывает.

## Запреты
- Запрещённые файлы не читать, замки не снимать, запрещённые команды не выполнять «для скорости»; мешает — доложить (`polnota.md` п. 7).
- Данные ≥ 2022 и `test_locked/` не трогать (`dannye.md`).
- Писать вне своего списка файлов нельзя; автор реализации не меняет тесты; проверяющий не меняет код.
- Не подавлять симптом (try/except, фильтр строк, подмена значения); разбирать до причины.
- Не добавлять режимы, воспроизводящие исправленные ошибки; «улучшения по пути» — отдельное задание.
- «Готово» при незакрытых, отложенных или ABANDON-гейтах — запрещено.
- Безопасность: `.env` не читать; секреты — не в чат, git, логи; ключи и заявки бирж — вне агентов.
- Файлы канона и `.claude/rules/` правятся только инструментами правки.

## По ходу (сохранено из v22)
- Записывать сразу: решение владельца — `Ъ` его словами и датой; отступление — `↺ — что · откат: как (ДД.ММ)`; цифра — `≡`; неизвестное — `❓` с умолчанием и сроком. Свою ошибку — первой строкой.
- Первая цифра — потолок. Подбор и счёт на одних данных — подгонка: честная половина. Одна пара — не статистика.
- Владельцу — проценты, не bps.
- Время — по `date`. Нужно от соседа — `❓ … (для <блок>)`.
- Вопрос владельцу — только если без ответа работа невозможна или необратима; иначе умолчание, записанное явно.
- Останавливаться только ради денег и размера; ключей и заявок бирж; необратимого; противоречия в каноне без умолчания. Остальное — `↺` и дальше.
- Бюджет в строке задачи (`~20м · ≤ 50т`) — отдельный, более мягкий порог. Вышел — стоп и «как разрезать». Порог ~300k токенов агента: передача (`templates/handoff.md`) — ждёт решения владельца (вопрос дирижёра 27.10), пересечение 3; до решения действует прежнее v22 (продолжение — тому же агенту).
- Отчёт агента: сделано / не сделано / проверено / отступления / решения; граница длины — ≤ 500 слов, остальное файлом (ждёт решения владельца (вопрос дирижёра 27.10), `izmeneniya_v22_v23.md`, пересечение 1; до решения — прежнее v22: до 10 строк и расход).
- Мутация для каждого PR пайплайна — `proverka.md` п. 1, `mutations.md`; блок владельца — квитанция «принят блок N» до исполнения (`svyaz.md`).

## Не применяется в этом проекте (перенесено из v22, не удалено)
- Rust, `cargo xtask check|build|brief|show|self-test`, `cargo fmt/clippy/test` — проекта на Rust нет.
- `scripts/finish.sh`, `scripts/sliyanie.sh`, `scripts/check.sh --konets`, `scripts/server.sh bg|bg-stop` — здесь не работают (нет сервера и этих рабочих процессов).
- Сервер `sdf`, `nice`, «данные не покидают сервер», «счёт на сервере; Мак — код» — сервера нет, всё на Маке.
- `main` как база PR, «после группы слияний на `main` — коммит производных, push» — база `kanon-v22-pereschet`.
- Производные `ROOT.md`, `handoff.md`, `dashboard.*`, `spec.md`/`_dir.md`/`_ctx.md`/`arhiv.md` как единственная правда — структура SDF; здесь правда — план `docs/zadaniya/2026-10-25_pereschet.md` и файлы заданий.
- `uptime`, `df -h` перед запуском сборочных — привязано к потолку SDF; на Маке при ~1 ГБ свободного место проверять вручную, worktree не создавать.
- Начало работы через `handoff.md` и `cargo xtask brief`; «Закрытый шаг: 5 строк в ТГ, `/clear`» — нет этих инструментов.
- Имена торговых ручек `docs/sdf_torgovaya_mehanika.md`, правила `skriner/`, `docs/kanon/` по номеру валидатора — относятся к SDF.
- «Уровень доступа 3», «В белую: стоять лимиткой» — предметная область SDF.
