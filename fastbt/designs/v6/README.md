# Сетка v6 (Ж-132): состав, группы, формат

Сетка v6 строится из трёх частей:
- сетка v5 (`fastbt/designs/v5/kub_S{1..6}.yaml`);
- все заготовки кода, которых нет в v5;
- три новые оси владельца: относительный сигнал, длительность, асимметрия сторон (Ж-132 п. 3).

Инвентаризация (ось → модуль → значения → что нужно → группа → смысл → «выкл.»), объём, план Морриса и листы кода — в `docs/otchety/2026-10-29_setka_v6_inventarizaciya.md`.

## Правила расширения (Ж-132 п. 2)

1. Ось входит в v6, только если у неё в кубе записан экономический смысл одной фразой (поле `smysl`). Нет смысла — нет оси.
2. У каждой новой оси обязательно есть значение «выкл.» (поле `vykl`, оно идёт первым в `setka`). Точка v6, у которой все новые оси выключены, совпадает с точкой v5: тот же `canon`, тот же `klyuch_n`. Так v5 вложена в v6, и вклад каждой оси измерим.
3. Группы:
   - `kontekst` — оси, меняющие сигнал: итерации 13, 14, 16–25, фильтры по типу, ТФ, три новые оси;
   - `ispolnenie` — вход и выход, слой v4, паузы, частичный выход;
   - портфельные оси (итерации 3, 5–9, 15, 25, размер, плечо, таргет) — только в слое МСП, не в кубе стратегии.
   Оси v5 тоже несут группу (фильтры v5 → `kontekst`, `vhod`/`vyhod`/`faza3` → `ispolnenie`, сигнал → `signal`), чтобы Моррис раскладывался по группам.
4. Моррис на 5 000 точек на стратегию считается раньше Соболя. Новые оси с «нулевым μ\*» по объявленному порогу замораживаются на «выкл.» (файл `zamorozka.yaml`). Оси v5 не замораживаются.
5. Сетка коммитится до счёта (`otbor_statistika.md` п. 1). Расширение после просмотра записывается строкой с датой и причиной, N обновляется.

## Формат `kub_S{k}.yaml` (`v: 4`; кубы появятся отдельным PR после ответа владельца)

```yaml
v: 4
format: progon-kub
setka: v6
data: 2026-10-30               # дата версии сетки (v5 и v6 — отдельные версии, Ж-132 п. 4)
baza: {setka: v5, kub_sha: <sha256 fastbt/designs/v5/kub_S1.yaml>}
sid: S1
tip: kontr
periody: [train4, v2]
komissiya: 0.0004
fdr: t0d
sobol: {seed: <объявить>, scramble: true, N: 200000}           # Ж-132 п. 2: тот же объём, что v5 на сервере
morris: {seed: 20261101, r: 75, p: 4, delta: 0.6667, kandidaty: 750,
         okna: ["<=2016", "<=2017", "<=2018"], porog_U: 0.05, min_akt: 20}
signal:  {<ось v5>: {setka: [...], gruppa: signal}}
filtr:   {<ось v5>: {setka: [...], yakor: 0, gruppa: kontekst}}
vhod:    {...}
vyhod:   {...}                  # оси v5; расширенные значения (tejk += pol_puti и т. п.) — в конце списка, с полем `v6_dobavleno`
kontekst:                       # новые оси группы «контекст сигнала»
  rel_signal: {setka: [syroy, sektor, rynok], vykl: syroy, p_vykl: 0.5,
               smysl: "сигнал по движению тикера сверх сектора/рынка — без беты", otkuda: "новая, Ж-132 п. 3"}
  sob_tip:    {setka: [net, cbr, div, cbr_div], vykl: net, p_vykl: 0.9, filtr: true,
               smysl: "не входить перед заседанием ЦБ или отсечкой", otkuda: "fastbt/sobytiya_e1.py:30"}
  sob_do:     {setka: [1, 2, 3, 5], vykl: 1, roditel: sob_tip, ...}
ispolnenie:                     # новые оси группы «исполнение»
  time_decay: {setka: [net, da], vykl: net, p_vykl: 0.5, smysl: "...", otkuda: "fastbt/engine.py:113"}
faza3: {...}                    # как v5
msp:   {...}                    # как v5, плюс список «в слой МСП» из отчёта §1.4 — не оси куба
```

Поля новой оси:

| Поле | Обязательно | Смысл |
|---|---|---|
| `setka` | да | значения; первое — «выкл.»; порядок — соседство для плато |
| `vykl` | да | значение, при котором точка = v5 (`canon_v6` выкидывает ось из ключа) |
| `smysl` | да | экономический смысл одной фразой (правило 1) |
| `otkuda` | да | модуль `файл:строка` или «новая, Ж-…» |
| `p_vykl` | да | доля u Соболя, отображаемая в «выкл.»: 0,9 у фильтров (`filtr: true`), 0,5 у прочих; у дочерних осей поля нет |
| `roditel` | для дочерних | ось действует, только если родитель ≠ «выкл.»; иначе схлопывается в канон |
| `tip_s` | если не все S | `kontr` / `trend` / список sid |
| `filtr` | для фильтров | `true` — ось только запрещает вход |

Соболь: u < p_vykl → «выкл.»; иначе индекс 1 + ⌊(u − p_vykl) / (1 − p_vykl) · (L − 1)⌋. Моррис: уровни равномерны, индекс = round(u·(L − 1)), «выкл.» = 0.

## Ledger: ключ версии сетки (предложение контракта, `"v": "2.2"`)

- Каталог `<root>/<setka>/<sid>/`: v5 и v6 не смешиваются.
- `manifest.json`: `kub_sha` (есть), `setka`, `setka_data`, `zamorozka_sha`.
- Строка ledger:
  - `setka` — `"v5"` | `"v6"`;
  - `rol` — `sobol` | `morris` | `faza2` | `faza3` | `kontrol`;
  - `klyuch_n` — sha256 канонической точки + период + комиссия + fdr, **без** `kod` и `vhody`;
  - `klyuch_sha` (ключ кэша, Д5) не меняется.
- N для DSR и общая матрица PBO: уникальные `klyuch_n` по ledger v5 ∪ v6, все роли, кроме `kontrol` (Ж-051 п. 2, Ж-080, Ж-132 п. 4).
- Читатели 2.0 и 2.1 не меняются.

## Выход Морриса (`docs/tables/setka_v6/morris_S{k}.csv`, `"v": "1"`)

Шапка: статус «разработка train4, до аудита», `kod`, `kub_sha`, seed, r, p, Δ, окна, порог, дата.

Колонки: `os`, `gruppa`, `novaya` (bool), `okno`, `n_akt`, `mu_star`, `sigma`, `U95`, `zamorozit` (bool), `prichina`.

Правило заморозки, объявленное до счёта: новая ось замораживается, если `U95 < 0.05` во всех трёх окнах и `n_akt ≥ 20`. Итог — `fastbt/designs/v6/zamorozka.yaml` (`v: 1`, дата, sha входов, список осей).
