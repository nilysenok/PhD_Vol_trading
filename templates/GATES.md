# GATES.md — шаблон (канон v23)

Основа: `polnota.md`, п. 1–4, 10, 12–13. Файл кладётся в рабочий каталог агента до начала работы. Один гейт — один наблюдаемый результат. До запуска `EVIDENCE: pending`. Гейт закрыт, только если CHECK выполнен, код возврата 0 и вывод совпал с EXPECT.

## Шаблон

```
# GATES — <задача>, <агент>, <дата>

## G1 — <результат одной строкой>
CHECK: <команда>
EXPECT: <ожидаемый вывод или значение>
EVIDENCE: pending

## Gn — ...

## ABANDON (только с причиной; гейт не удалять и не переписывать)
ABANDON: <id> <причина>

## Реестр
закрыто N из M; ABANDON: k; pending: p
```

Ручной гейт (без команды) — только если проверку нельзя выразить командой; пишется явно: `CHECK: РУЧНОЙ — <почему нельзя командой>`.

## Пример: «тест ловит мутацию X»

```
# GATES — тест test_gate_shift ловит мутацию сдвига, kodir, 27.10

## G1 — на исправленном коде тест проходит
CHECK: python -m pytest tests/test_gate_shift.py -q
EXPECT: passed, 0 failed
EVIDENCE: 3 passed in 0.4s (код возврата 0)

## G2 — на мутанте (shift(1) заменён на shift(0), в отдельной копии) тест падает
CHECK: python -m pytest tests/test_gate_shift.py -q; test $? -eq 1   # запуск в копии с мутацией
EXPECT: 1 failed (pytest вернул 1, обёртка test — 0)
EVIDENCE: 1 failed, 2 passed in 0.4s; код возврата обёртки 0

## G3 — рабочая копия без мутации не изменена
CHECK: git status --short
EXPECT: пусто (кроме GATES.md)
EVIDENCE: ?? GATES.md

## Реестр
закрыто 3 из 3; ABANDON: 0; pending: 0  → можно писать «готово» (при любом незакрытом — «передача», polnota.md п. 12)
```

Ожидаемый ненулевой код возврата проверяемой команды оборачивается в CHECK (`test $? -eq 1`), чтобы п. 10 («код возврата 0») сохранялся.
